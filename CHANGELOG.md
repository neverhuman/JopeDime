## [0.4.1] - 2026-10-23

Generated with git-cliff 2.14.1 and `cliff.toml` over the commits after `v0.4.0` (#403, #407 and
#412 through #415), then curated, absorbing the Unreleased entries. This tag packages the CPU CLI
from `main` at f9543b85 for the cloud appliance. The research branches are not part of this
release, and this binary release does not claim a qualified end-to-end learning flywheel.

### Pipeline

- pipeline: the `jope pipeline invent --events` journal gains `candidate` records (one evaluation's generation, cut, held-out R^2 and RMSE, or null when it failed, with a fixed `measured`/`failed` status; at most five a second, under 512 bytes each) and `progress` gains `population_r2` and `generations`. Records stay numbers-only labels and values, at most 2048 bytes, through the bounded worker of #400. The shared fold now runs before the progress snapshot, so `population_r2` counts draws another island already measured; the search's decisions and published bytes are unchanged (#403)

### Model objects

- models: saved model objects share one standard layout with session versions and rollback (#413)

### Model export

- C17: native C17 bindings with complete Rust recipe coverage, qualified by six required native contracts (#414)
- TypeScript: explicit `typescript` / `ts` output with a strict typed API and a WebAssembly build source reusing the complete Rust recipe implementation. Includes bound fitted-model export, CLI/pipeline/v3 source binding, token counting, and an executable CommonJS/ESM qualification lane. Build requirements, arithmetic tolerance and current qualification limits are in `docs/typescript.md`.

### Regression objectives

- runtime: `jopedime fit --fitness` selects native methods by a portable regression objective: 38 built-ins (quantile, newsvendor, LinEx, relative errors, Poisson/Gamma/Tweedie deviances, MASE, Sharpe, Sortino, drawdown, Calmar, Omega, expected shortfall, hit rate, normalized Gini, KGE, top-fraction capture and more), `name:key=value` overrides, and custom JSON row expressions over `y`, `pred` and numeric training columns that are never features, with weighted and composite forms. Every specification has a sha256 identity in the selection record, model file and receipt
- runtime: objective-aware output calibration (`--calibration auto|none|shift|affine`, default affine with an objective): a monotone `max(a + b*pred, floor)` map learned on out-of-fold predictions, cross-fitted for selection, stored in `model.jope` and applied at prediction. A model whose map or objective columns disagree with its selection record does not load
- runtime: chronological `--validation forward --gap N` for order-dependent objectives; JSON-RPC (`jopedime api`) and MCP (`jopedime mcp`; revisions 2025-11-25 back to 2024-11-05) tools `fitness_list`, `fitness_validate`, `fitness_evaluate` and `regression_fit_predict`
- pipeline: `jope pipeline run --fitness` and `jope pipeline invent --fitness` rank candidate programs by the objective on held-out rows; observations carry `objective_loss`, receipts record `search.objective` and `validation_objective`, evidence re-derivation and sealed test scoring use the same objective. Order-dependent objectives and objectives that read columns are refused by the search
- examples: 41 objective recipes and a real-world benchmark (`examples/objectives/real-world`) that fetches public datasets outside the checkout and compares RMSE selection, objective selection and calibrated selection on held-out rows

### Benchmarks and AutoML

- automl: the owner-supplied `Gemini4_argon_high` Rust regressor joins the native registry byte-for-byte (`jope-bench run --native Gemini4_argon_high`), replacing the earlier `gemini-argon-4` candidate. The adapter now refuses a non-finite prediction instead of passing it on; the frozen source returns `inf` for some extreme finite inputs
- automl-elo: `assets/automl-elo/v1` adds the four-entrant AutoML Elo over 64 families × 3 folds × 3 seeds. Gemini4_argon_high was fitted on all 576 cells (one CPU and 8 GiB each, no failures); the three earlier entrants' 1,728 fits are reused and the historical fit is reproduced exactly. Ratings: Opus5p5_Extra 1641, Gemini4_argon_high 1561, GPT6p1_Sol_Max 1456, GPT6_Astra_Max 1342 (95% family-bootstrap intervals in `RESULTS.json`; Gemini's RMSE differences are not significant after Holm adjustment), with Elo, pairwise and source-size figures

### CI

- appliance: PR package builds use fat LTO and one codegen unit to retain the existing executable size limits with the new objective/API adapters; numerical optimization, panic recovery and the 5% size tolerance remain unchanged

- runners: four isolated Linux/Docker PR lanes on the xbabe4 VM and three guard-only main lanes join the seven heavy roles, bound to the reviewed deployment inventory
- runner: the daily build-cache trim keeps the newest 3 builds per crate and kind instead of 6. xbabe3's full-lane target regrew to 211 GB within a day under keep-6, its root disk fell below the 50 GB runner reserve, and both its lanes refused to start (main full-main-cpu 39770894207 cpu-1). Rolled out with the usual runner re-provisioning freeze
- ci(browser-deps): `observatory-ui` retries a dropped or refused download of a pinned Ubuntu package up to 4 times with backoff (transport errors and HTTP 5xx only). A size or hash mismatch or an HTTP 4xx still fails at once, and nothing is published before verification. Two jobs failed on 2026-10-22 from single mirror drops
- ci(full-main): the trusted-main source audit is report-only until its score reaches 85 (owner decision, 2026-10-22; 54 at `bdf9441aa`). A verified audit that fails below 85 passes the `audit` job with a warning and a `report-only.json` marker, and its reports keep the failed decision. A failed audit at or above 85 still fails the job, as do missing, inconsistent or tampered evidence and version or tool errors. The floor and policy are unchanged
- ci(full-main): the audit no longer breaks the self-hosted runner after it. Its captured source was left read-only in the persistent workspace, so every later job on that runner failed in `actions/checkout` (`Permission denied`, then `not a git repository`). An always-run step after the evidence upload now restores write permission. The retained evidence keeps its read-only modes, so the verifier still replays on it

## [0.4.0] - 2026-10-22

Generated with git-cliff 2.14.1 and `cliff.toml` over the commits after `v0.3.0` (#386 and
#388 through #400), then curated. This tag packages the CPU CLI from `main` after #398. The
47-task major research qualification and the research branches are not part of this release.
Model and checkpoint publication and training admission remain governed by their own evidence,
and this binary release does not claim a qualified end-to-end learning flywheel.

### Pipeline

- pipeline: `jope pipeline invent --events PATH` writes opt-in progress records without changing the single final `--json` stdout contract. Delivery is bounded and best-effort: records may be dropped and sequences may have gaps. Each evaluated attempt counts the lexical code and documentation tokens of its complete Rust, Python, C++17 and JavaScript sources. On Linux, event-file admission refuses input and work-directory aliases and unsafe targets before truncating (#400)
- gp: every complete program materialized at the documented GP construction and evaluation boundaries is captured and streamed (`gp-source-stream`) as full Rust, Python, C++17 and JavaScript training-recipe source with compilation-qualified token metrics. Legacy operator bodies are observed without being changed (#388)

### Benchmarks and AutoML

- bench: the `GPT6_Astra_Max` Rust regressor joins the same-cut AutoML comparison and Elo path (`jope-bench run --automl gpt6-astra-max`) (#391)
- automl: a dependency-free `jope-automl` native registry with the `GPT6p1_Sol_Max` Rust regressor (`jope-bench run --native GPT6p1_Sol_Max`) (#392)
- bench: the frozen `Opus5p5_Extra` regressor through the explicit `--entrant` path, with wrapper validation of CSV shape, seeds, budgets and process failures (#393)

### Performance

- feat-math: kernel-smoother prediction selects the nearest k rows and sorts only that prefix. Stage-cache hits clone fitted operations after releasing the shard lock, and admission counts serialized bytes through a bounded sink (#396)
- feat-math, engine: feature-major histogram bins, fit-local scratch, capped output allocations, blocked Cholesky, ordered parallel token estimation and streamed CSV hashes. Runtime workers respect the allowed CPUs (#397)
- feat-math: `jacobi_eigen` (every ridge_gcv fit) accumulates eigenvectors transposed, elastic-net coordinate descent reads column-major features, and histgbm builds feature-major bins directly. Each is checked bit-identical to its predecessor (#398)
- engine, campaigns: the queue keeper owns one pool sized to the usable CPUs and hashes its runner and evaluator once per cycle. `serde_json` file reads are buffered, each JSONL record is written in one call, and the teaching store hashes its vocabulary once per publish (#398)

### Engine, security and runtime

- datasets, models: blob verification hashes binary content in one streaming pass with bounded header storage. Dedicated read threads avoid a circular wait between a destination-lock waiter and Tokio's blocking pool (#395)
- audit: bounds on adapter parsing and allocation, corpus copies, and native and GPU inputs; canonical blocking security entry points; an all-feature cargo-deny gate (#395)
- engine: the remaining raw `libc::flock` calls become std `File` locks. A safe `host_os` module provides monotonic and boot-time clocks and process identity. A second SIGINT/SIGTERM exits 143, and timed-out host probes are reaped within a bound (#398)
- vendor: the vendored `ratatui 0.29.0` requires `lru =0.18.4` (RUSTSEC-2026-0002, RUSTSEC-2026-0253), and the vendor-custody verifier enforces that floor (#398)

### CI, build and release

- release: bump the workspace and product crate versions from `0.3.0` to `0.4.0`, syncing the standalone Lambda workspace locks (`deploy/lambda/SNAPSHOT.json`); `jope` prints `jope 0.4.0`
- release: the signed release's build, check and receipt containers are capped at 4 CPUs, 20 GiB RAM, no extra swap and 4 Cargo jobs. The 0.3.0 notes were corrected (#386)
- ci: GP source contract tests run serially in the emitters lane (#390). The workspace `cargo clippy --all-targets -D warnings` gate passes (#398)
- ci: the `full-main-cpu` `full-emitters` family deadline goes from 300 s to 1200 s, and the CPU job's timeout from 130 to 145 min, so every family's declared deadline still fits one job. The family had timed out on every completed main run since #388: its GP-source contracts compile inside the deadline, and the same work takes 343-638 s in the PR-lane emitters job

### Deployment

- appliance: the signed single-file `jopedime` executable (`deploy/appliance/`): specification (#390) with amendments; `jope-assets` (128-byte footer, manifest-signed package, per-asset authentication before decompression, bounded zstd/byte-plane decoding, release key `docs/release/signing.pub`); `jope-runtime` (native roster, raw-cell encoding and bound prediction moved from the panel and pipeline with re-exports; CSV ingress; `jope.runtime-select/v1` bounded selection; `model.jope`; run receipts; exit statuses 2-7); `jope-appliance` (`version`, `doctor`, `methods`, `fit`, `predict`, `fit-predict`, `verify-self`, `licenses`); `jope-dist` (model lock with rights blockers, deterministic pack, release stage and seal, verify, audit, notices, size, SBOM, provenance); `fixture`, `native-only` and blocked `full` profiles; the `e2e-smoke` lane builds, packs and runs the fixture appliance alone (#394)
- feat-math: the fitted C++ runtime is behind the default-on `fitted-cpp` feature so the appliance graph carries no C++ (#394)
- policy: `PolicyModel::load_bound_from_bytes` loads a verified checkpoint from bytes with the same identity checks as `load_bound` (#394)

### Documentation

- docs: the Rust frontier regression challenge specification is versioned under `docs/challenges/` (#389)
- docs: a CSV terminal quickstart, a reproducible synthetic preview and an implementation workplan (#399)
- governance: the same agent may implement, review and merge its pull request; both main protection layers require zero approving reviews (#393)
