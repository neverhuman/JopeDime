# Private research round records

The [proposed qualified provider contract](../../../../docs/contracts/research-provider.md)
records the remaining input/evaluator/reveal/seed and activation requirements,
with decision owners. It is a review draft; it does not activate the CLI.

This is the QLT-03 CPU record and durable discovery capture component for spec 13.2, behind the optional `research` feature. `Discovery::open_research` requires an opaque reviewed input/provider capability. No production resolver or arbitrary JSON importer is registered. The internal native `research record` command still authenticates its package and returns producer-unavailable until the separately approved corpus, conditioning, evaluator, gate and seed contract exists. These hooks and synthetic controls do not qualify a live capture, learned guidance, binary-task evaluation or Q1.

`RoundCapture` controls CPU evaluation of an already observed pre-admission slate. Construct it with an empty dispatch/outcome inventory and an attempt budget. `evaluate_next` invokes the caller's rung-0 evaluator in behavior-policy admission order, or original proposal order when `evaluate_all_proposals` is true. It preserves the input policy, admitted indices, costs, features and source indices. Each attempt is reserved before evaluation, including explicit worker failures; wall milliseconds are measured around the callback. It returns false at the attempt/population limit. `finish` validates the resulting record and marks early stops incomplete. An evaluator error, panic or nonfinite success leaves an unresolved attempt, refuses further calls and prevents publication; inspect `attempted_indices` and `outcomes` rather than fabricating a failed label or retrying within that capture. These in-memory attempt counts do not replace the engine's durable evaluation/wall budget accounting. The standalone controller still requires its caller to provide trusted inputs and commit its result; it alone establishes neither discovery integration nor crash recovery. The discovery hooks below supply separate durable orchestration.

`ResearchRound` carries train-only input identities, task, 10 x 32 conditioning tokens and ten boolean masks, complete program features/projections and operator families, four revealed surrogate/gate pairs, actual behavior-policy costs and admitted eligible-slate indices, the original pre-dedup source indices, actual dispatch indices, capture completeness, and every dispatched rung-0 outcome. Identity pins attest the producer inputs; they do not establish corpus eligibility or that a model actually computed the supplied values. Trusted corpus preparation and a qualified engine producer must establish those facts. No row data or model parameters belong in these records.

`round.schema.json` specifies the closed JSON shape. Rust `ResearchRound::validate` and Python `validate_record` also enforce the cross-field rules: unique programs/indices, outcomes exactly matching actual dispatch, admission distinct from dispatch, full ordinary/evaluate-all coverage required for a complete capture, failures retained as observations, finite numeric values, and full 12/20-entry cost slates for learned policies. Heuristic policies carry `slate_costs: null`. Seed round zero has no revealed entries and admits every seed; the current bounded format accepts 1..16 seed candidates. Later heuristic rounds may have deduplicated partial slates; learned rounds require 8 or16 proposals. Surrogate and user-objective measurements stay separate. A recorded admission is an observation, not proof that the policy selected correctly.

`RecordWriter::create(path)` creates a new 0600 file on Unix and syncs its parent directory. It refuses an existing path; it never resumes or truncates. `append` validates before writing and syncs each line before returning success. Rounds start at zero and are contiguous. Run/input pins, seed, conditioning tokens/mask and evaluate-all mode are constant for a stream. Validation refusals leave the stream usable; write/sync failures poison it, retaining the partial file for inspection. Non-Unix private-file creation is explicitly unavailable until qualified. Parent directory symlinks are followed; create_new protects the final component only. There is no advisory lock: the caller must enforce one writer, since another process under the same UID can open a 0600 file. A parent-directory sync error can leave an empty file; retain it and choose a fresh path for retry. The caller supplies an appropriate private output directory and appends only actual committed rounds. The durable outbox materializer below enforces that boundary for discovery captures.

The Python module uses only the standard library when run directly:

```sh
python3 python/src/jope/north_star/record_reader.py /path/to/records.jsonl
```

It validates the full stream and prints round/proposal/outcome/failure counts. It rejects missing/unknown fields, duplicate JSON keys, nonfinite or oversized values, partial/oversized/empty streams, input changes and out-of-order rounds. `read_records(path)` exposes the same streaming validation. Budget-truncated captures retain all actual outcomes and a false completeness flag. They are refused by default; `--allow-incomplete` / `allow_incomplete=True` permits inspection and reports incomplete rounds. This is never proof of unbiased training labels. Consume and validate the complete stream before using any records for training. Synthetic controls require explicit `--allow-synthetic` / `allow_synthetic=True`; they must never be used as training observations. Import through the existing `jope.north_star` package also executes that package's pre-existing imports; direct-file use avoids those optional dependencies.

For consumers that require every eligible proposal's outcome, use `--require-evaluate-all` / `require_evaluate_all=True`. It rejects ordinary captures and incomplete all-proposal captures, including with `--allow-incomplete`. It does not establish corpus or engine provenance, qualification, or eligibility of a synthetic control for training.

QA is in inline Rust tests, including actual Rust JSONL -> standalone Python readback of both capture modes, complete failure inventories and malformed-stream controls. These fixtures are synthetic software controls, not a corpus run, optimizer evidence, guidance parity or a release qualification.


With `research` enabled, ordinary discovery retains version2 checkpoints and omits all capture fields. A research capture uses version3; normal open refuses it, and research reopen requires the same complete binding and explicit attempt/round/byte bounds. The provider preflights the actual input/evaluator closure before any reservation; program features, original f64 projections, four reveals from measured admitted elites, gates and extra-request seeds are supplied through that sealed boundary. Heuristic admission delegates once to its existing policy with null costs. Other admissions must implement the same-call observed trace or refuse. Empty eligible slates and populations above16 refuse before execution.

Each planned slate retains pre-dedup source indices, eligible order, admission and dispatch mapping. Immutable CAS blobs hold the binding, slates, exact requests and results. All references, including intermediate fit results, are explicit run GC roots in every open/control/round transaction. The controller persists all reservations before any worker call, then serializes result journals while workers run. Reservations, failed and uncertain attempts consume the explicit rung0 cap without refunds; all work and interrupted active spans consume the existing wall budget. Optional label-only work uses disjoint slots32..47, a private counter and provider-supplied seed protocol. It does not enter normal memo/programs/elites/parents, public GP events or promotion; admitted request allocation and exploration RNG remain unchanged.

The validated round outbox reference is installed in the existing `EventLog::commit` transaction together with the actual checkpoint, evaluations, champion and events. A precommit failure leaves only the earlier private journal and possibly unreferenced immutable bytes. An uncertain commit requires reopen/readback. Reopen consumes retained known results without replaying proposal/admission or workers. Any reserved result that remains unknown, stale or aborted taints the capture permanently; this version refuses retries and complete training export. A budget-truncated record remains incomplete. Closed record v1 has no invented unknown/multiple-attempt representation.

`materialize_committed` loads the actual committed completed run, validates CAS content, accounting, binding/round continuity and journal agreement, and requires every round to be known and complete. Synthetic controls are refused by the public entry point. It creates a fresh0600 sibling staging stream in a canonical real output directory, syncs/validates all lines against the outbox, then hard-links without replacing an existing destination and syncs the directory. Store commit and filesystem publication remain separate transactions. Staging files remain as evidence on success or uncertain I/O; retry to a new path and never append to a partial prior output. No export acknowledgement removes roots.

The feature tests use explicitly tagged synthetic programs/measurements and a synthetic matrix. They exercise normal/capture behavior and serialization,1/8 live workers at fixed Plan/R, both label modes, source dedup/exploring16, seed bounds, caps, per-outcome recovery, atomic round rollback, own-child SIGKILL before/after reservations/outcomes/round commit/file publication, CAS loss/corruption, GC roots, public projection privacy and actual Rust-to-Python controls. The ignored child entry point is launched only by its owning SIGKILL test. These are software proofs, not real engine/corpus qualification or optimizer evidence.


If convergence or a wall deadline discards a pending wave suffix, complete export
is refused even when every suffix outcome was already measured and a committed
prefix is known. The private journal retains that prefix, the aborted suffix,
all reservations/outcomes and their GC roots across reopen. It does not refund
charges, rerun those workers or silently publish/renumber the prefix as a full
training stream. Prefix export would require separately reviewed semantics.
The CPU controls exercise both completion reasons at1/8 workers. Their scoped
clock freezes controller wall anchors and dispatch spans without sleeping; real
worker-call durations still use `Instant`, and production has no clock override.
