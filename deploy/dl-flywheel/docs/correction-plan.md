## What was wrong

The augmentation service is currently backpressured at128 published but unadmitted variants. An end-to-end evergreen loop is not complete until actual qualified admission releases capacity. The initial eight-program GP panel is fixed supervision/opponents, not neural output.

## Normalization, loss and overfitting

Always preserve raw fold RMSE/units. Initial quality uses the versioned mean negative log ratio against an opposite-fit-fold mean predictor, with frozen epsilon/clipping. Do not mix raw errors across unrelated scales or silently change denominators.

CatBoost is a stronger difficulty reference but costs more and can produce unstable near-zero denominators. Cache a fixed baseline per exact task/target/split/protocol:500 trees,depth6,learning rate0.05,L2=3,fixed seed,no best-iteration selection,no file writing,bounded CPU. Fit only the opposite inner fold. Preserve out-of-fold predictions, RMSE and source/config. CatBoost-relative quality is a separate immutable objective identity.

The native successor-v1 objective is implemented in the reviewed dependency source: teacher token cross-entropy +0.25 pairwise Bradley–Terry ranking +0.10 listwise ranking +0.25 quality Huber +0.10 feasibility cross-entropy +0.05 runtime Huber. Each term logs its own support; unsupported terms are zero, not evidence of learning. Frozen native eligibility rules decide whether a task has enough distinct teachers for the generator terms. The first bounded run uses these measured fixed labels; new generated measurements enter a later explicitly admitted snapshot, not an unlogged online reward update.

Context preprocessing in the proposed runner fits per-coordinate mean/std on training contexts only, maps near-constant scale to1, and clips standardized inputs to[-10,10]. The raw Kumo vectors stay immutable. Validation never contributes to these fitted statistics. Save both original/transformed content identities and the preprocessing arrays.

Within-task ranking can focus on useful relative GP quality. Keep supervised token and measured ranking/reward terms separate, normalize within task, bound reward/gradients and require enough distinct teachers. Do not claim a ranking/RL term is implemented until source/tests/actual logs show it. Use fixed development lineages for early stopping and retain best/last checkpoints. More noisy descendants are not more independent real data; report parent diversity and group-level uncertainty.
