# Closed contracts and future integration gates

The authoritative field sets are `closed(...)` calls in the four production modules. Unknown keys refuse; no optional version aliases or opaque callback success is supported. All JSON used as an authority/manifest/acceptance is canonical ASCII-escaped UTF-8, sorted keys, compact separators, finite values, no duplicate keys. Existing config/result/snapshot bodies may retain their exact original noncanonical layout; hashes bind those actual bytes and parsers still reject duplicate/nonfinite values.

`ExternalAnchor` supplies independently committed seal physical pin, generation index, old graph SHA, old acceptance head and policy SHA. Its source is **outside this pure library**. `VerifiedAuthority` and `VerifiedHistory` are derived immutable values whose constructor/copy/consumption guards bind all values; they are not persistent certificates and do not survive as trusted arbitrary deserialized objects.

`codex.monitor-accepted-custody-graph/v1`: generation_index, ordered namespaces, acceptance_head. Namespace: id, root, source_manifest_sha256, config_sha256, clock, window_state, status, ordered members, member_manifest_sha256, acceptance. Config and clock are null only for an authenticated `not_created` failed/held-source-only window. Every original reference stays the original six-field physical pin; each retained custody pin adds uid/mode/nlink/file_type and is independently read-only, single-link, regular. Original and custody SHA/bytes must match; all custody paths are disjoint from every old/new original root. Equal content in separate namespaces is not identity deduplication. Namespace IDs, physical aliases and order stay unique.

`codex.monitor-custody-acceptance/v1`: namespace/member/source/config/clock/status/window joins, previous_acceptance_sha256, capture ref, verifier_source ref. Receipt SHA links the next receipt; the final head and complete graph are committed externally. Capture/verifier refs preserve original acceptance provenance; this pure layer hashes each acceptance receipt and captured body, but it does not rerun that original verifier or physically reacquire original capture files. A future actual schema adapter must prove completeness against original full inventories and acceptance custody, not mint this graph from a request roster.

`codex.monitor-pending-custody-extension/v1`: exact generation, authority SHA, old graph/head, all old namespaces byte-equivalent plus one pending new namespace. No acceptance is created. A fresh normal successor requires normal immediate predecessor; historical failed/unknown/source-only-held predecessors elsewhere remain explicit. Actual publication/process closure and current guards must still be independently qualified. No new status turns a failure into normal completion.

`PhaseBinding` carries exact original config/source/clock/snapshot-path, accepted/observed prefix lengths+hashes and null-or-exact legacy-history descriptor. The pure phase proof is only a replay/snapshot result; it does not implement `prior_closed`, command/dispatch equality, full stage closure, current kernel observations, or a fresh root-owned authority producer. All of these remain required in a future composed acceptance. An unknown/partial phase never gets a clean proof. No numeric score or training/GP data is touched.

Remaining work is deliberately bounded: independently review this source/fixture receipt; separately qualify an actual legacy-schema normalizer and external immutable seal read path; settle the accepted-certificate freshness policy; implement same-FD bounded IO and durable partial custody; compare a new pure verifier on exactly retained accepted bytes once under a fresh qualification packet; measure actual memory/transport/counters; review a new cold operator before a root-owned single live transition. None is inferred from this packet.
