## Checks

Run the stdlib custody verifier and refusal fixtures from the repository root:

```sh
python3 deploy/dl-trainonly/verify_lane.py
python3 deploy/dl-trainonly/test_verify_lane.py
python3 deploy/dl-trainonly/test_offline_guard.py
```

The verifier uses committed expected manifest pins for the handoff and its ordered predecessor chain, checks every `supersedes_sha256` link, checks every payload and filename, rejects extra files and symlinks, reconstructs every predecessor's current files and historical versions, and parses Python syntax without importing the staged code. These are source custody checks, not executed-family coverage or producer authentication for operational consumers.

The Python CI lane additionally runs exactly 16 preserved unittest modules (454 collected identities): 436 synthetic cases execute, and 18 genuine private-host cases remain explicitly deferred for host qualification through `run_lane_offline.py`. It uses the existing locked Python environment, hides GPUs, removes ambient credential configuration, refuses Python credential-file reads, every Python socket audit event (including socket creation and UDP sends), and direct Python subprocess/spawn/fork/exec launches. It permits only an exact read-only `/sbin/ldconfig -p` library-cache probe through Popen or posix_spawn if the CPU dependency loader needs it. Independent guard fixtures exercise these boundaries before any network traffic or child launch. The offline fixture process disables urllib3's import-time IPv6 capability probe; socket creation remains refused, including IPv6. These Python audit controls are not OS sandboxing or native-extension isolation. During collection and execution, private-lane path existence checks report unavailable without statting those paths, including optional L7b ancestor pointers. Twelve guard fixtures cover refusals, authorized probes and restoration of the existence function after execution.
