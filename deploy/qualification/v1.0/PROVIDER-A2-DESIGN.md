# REL-07 A2 API contract provider

Spec §14 A2 requires generated OpenAPI/JSON Schemas to equal their committed contracts, catalogued problem+json errors and string-encoded 64-bit values. The provider authenticates the full non-development candidate and embedded source with the existing common helper, independently requires that exact clean checkout, then runs fourteen exact product assertions. They cover byte-for-byte OpenAPI generation, registered operations, the top-level schema snapshot, Appendix D and Problem serialization/schema/refusals, decimal boundaries/numeric refusal/schema, durable cursors, every HTTP-mapped error responder and router errors.

Two small product tests supply missing direct assertions: the OpenAPI generator bytes equal the committed file, and each HTTP-mapped ErrorCode is passed through the actual problem responder and decoded as Problem with the catalog status/code/media type. Non-HTTP catalog entries remain covered by the complete Appendix D test. No wire types, schemas, error catalog, handlers or other production behavior change.

Each selector must execute exactly one named passing Rust case. Zero, wrong, duplicate, failed, ignored or measured cases refuse PASS; source/artifact drift and symlink/non-file paths also refuse. The result is exclusively created outside the checkout and reports only fourteen actually executed Rust cases, bound to the candidate SHA and source SHA. Test lists filtered by exact selectors are outside this gate's claimed coverage. Inspect/verify/build output remains with the release controller; no prior status summary is accepted as execution.

Invoke `python3 -B deploy/qualification/v1.0/providers/a2.py` with the five JOPE_REL07 bindings documented in GATE-RUNNER.md. Provider controls run with `python3 -B -m unittest discover -s deploy/qualification/v1.0/test_provider_a2 -v`; their fake candidate/child output is orchestration coverage, not release qualification. Actual selected Rust cases are separately executed locally. A2 remains NOT RUN for release bytes until a full candidate is supplied.

A generic zero-exit wrapper was rejected because a wrong selector can collect zero tests. Reimplementing schemas/serializers in Python was rejected because it would not test the product contract. No new dependency, GPU, dataset, signing, candidate builder or shared-provider refactor is needed. Risk: a renamed assertion fails closed until the selector is deliberately updated; product compilation failures are real gate failures. Own-family coverage/inventory rows and README census are mechanical registrations only.
