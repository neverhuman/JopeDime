# REL-07 A4 MCP conformance provider

The A4 row in `gate-status.md` points to MCP-01/02/03 evidence, but no candidate-bound command existed. `providers/a4.py` uses the T1 binding protocol: the five `JOPE_REL07_*` variables, full non-development envelope verification, clean exact source before/between/after cases, and unchanged full candidate bytes. It runs 23 explicit existing `jope-appliance` MCP unit selectors, each exactly once. The lifecycle case covers all four shipped protocol versions; the remaining cases cover tool/schema parity, aliases, metadata, discovery, invalid requests, cancellation, bounded resources, stdout purity and safe prediction replay.

The command is `python3 -B deploy/qualification/v1.0/providers/a4.py`, with timeout 3600 seconds in the gate manifest. Every case must report exactly one successful matching test and one result summary. Zero/wrong/duplicated cases, failure, skip, measured cases, source or artifact drift, symlink/non-file candidates, and existing or in-checkout results refuse PASS. The result uses `jope.rel07.gate-execution/v1`, contains the candidate SHA-256 and precise 23/23/23 counts, and is created exclusively outside the checkout. Filtered tests outside these selectors do not count as executed coverage.

The owner's no-speed policy applies: the fitting-p95 test is deliberately not selected, and the result explicitly says timing is not measured. This provider establishes protocol conformance, not the original specification's latency clause or a D2 verdict. It never emits a speed pass/fail value. Dataset-free provider controls use mocked child results; the product protocol tests use their existing committed transport fixtures. Neither is a three-client campaign, signed release qualification, or a reason to relabel unavailable runtime evidence.

Controls: `nice -n 10 python3 -B deploy/qualification/v1.0/test_provider_a4 -v` or targeted pytest with `--import-mode=importlib` on its `__main__.py`. The test directory is directly executable like the existing manual T1 controls; it adds no CI lane or implicit CI-coverage claim. The exact Rust selectors are separately executed locally/offhost from the source under review. Cargo receives incremental=0, dev debug=line-tables-only and four jobs. Candidate execution still requires the real reviewed full release bytes; implementation controls do not create a release PASS.

A generic successful-command wrapper was rejected because it can pass zero or wrong cases. Copying a protocol implementation was rejected because the gate must test product code. Common helpers, runner wiring, signing, data, API schemas and other providers remain unchanged; gov04 owns coordinator integration. Main may advance: the eventual gate runs and rechecks the source named by its candidate, never an ancestor's old test receipt.

The candidate path must also be canonical and have no symlink components. Checking only the final file allowed a parent directory to be replaced by a symlink to identical bytes, so hashing alone did not detect that invalid path. The existing binding checks now reject parent symlinks and `..` aliases before verification, between cases, and before publication. Two controller tests cover initial aliases and a same-byte parent swap after the first case; the existing positive control still executes all 23 selectors for a regular canonical path. Resolving the path silently was rejected because it would accept the alias. These periodic path checks do not establish immunity to every concurrent filesystem race or qualify real release bytes.
