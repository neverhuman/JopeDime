# REL-07 E2 export parity provider

E2 needs the actual native-reference/exporter harness, rather than a successful generic command or a few emitter unit tests. The provider verifies the supplied non-development full candidate and its embedded source pin with the existing common helper, requires the exact clean source before and after each stage, and invokes `deploy/ci/export-parity.sh --require-calibration` with real pinned Rust, Python and Node toolchains. The existing harness enforces spec §10.5 numeric tolerances, exact shapes/column order, tree routing flip limits, populated self-checks, deterministic emission, raw numeric inputs and strict affine/floor and Platt goldens. No engine/emitter/registry/workflow change is needed.

The report must be new and external to the checkout. E2 checks source, harness/lock/registry/fixture identities, retained file sizes and hashes, complete supported-cell and emitted-module inventories, all three primary languages, routing probes, raw contracts and strict calibration counts. Zero, missing, duplicate, failed, stale, dirty, mutated or symlink/non-file evidence refuses PASS. Counts describe actual emitted-module comparisons plus three raw-language comparisons; self-checks are required within each module, not counted twice. Unsupported registry cells stay explicitly unqualified and are recorded separately, never counted as passing or as executed cases. Existing result files are never overwritten. Logs and complete harness reports are retained on failure as well as success.

Coordinator argv: `python3 -B deploy/qualification/v1.0/providers/e2.py`, timeout 3600 seconds, with the five standard `JOPE_REL07_*` bindings in `GATE-RUNNER.md`. The child result includes the exact candidate SHA-256, full source SHA, positive execution counts and the retained parity report path/hash. CPU only, nice 10, 1–8 build jobs, math threads one, one existing target; no sealed data, release signing or speed verdict. Source compilation, missing pinned toolchains and parity defects fail closed. The runtime harness uses deterministic numerical fixtures, not a dataset or model-quality qualification campaign.

Provider controls: `nice -n 10 python3 -m pytest -q deploy/qualification/v1.0/test_provider_e2/`. Synthetic child reports exercise acceptance and refusal handling only; they are not E2 release evidence. Actual E2 execution requires the supplied verified release candidate and complete real-toolchain harness execution. This adapter does not establish hosted CI execution, CUDA/platform qualification, other release gates or an all-28 PASS. The latest owner ruling accepts local process gates; no hosted CI is dispatched by this implementation task. Relevant gate evidence remains DSC-11, EXP-02/03/04/05/06/07/08 and OBJ-04 in `gate-status.md`; those status files are context, not substituted execution receipts.
