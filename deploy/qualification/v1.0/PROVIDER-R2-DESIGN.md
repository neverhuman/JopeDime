# REL-07 R2 worker isolation provider

R2 executes a new, dedicated Linux `jope-service` native integration test for spec §14: infinite-loop and memory-bomb candidates must be killed within their limit plus two seconds, the search must complete, and engine RSS must stay within 10% of baseline. The test uses the actual `Discovery`, process executor, native evaluator, store and model refit. Only the faulty worker closure is synthetic. Healthy evaluations use the existing checksum-pinned S3-derived TRAIN regression fixture (`d9a0b97e…045931`), its fixed FIT rows and ordinary ridge programs; no outer TEST, sealed data, model weights or GPU are read.

The test warms an ordinary successful native search before sampling engine RSS. For each fault it primes a healthy worker, then samples the engine every 5 ms throughout discovery and refitting. The first candidate either spins forever or touches a 128 MiB allocation against a 96 MiB worker RSS limit; its wall limit is 1,000 ms. Both must report the expected worker failure within 3,000 ms, replace that worker, complete discovery with a finite healthy champion and verified model blob, and leave no owned workers after pool shutdown. Peak engine RSS must be at most 110% of the measured baseline, with positive sensor samples. These are fault-containment bounds, not a comparative throughput or latency benchmark. This test proves native discovery completion; the frontend/export lifecycle remains S1's separate responsibility.

The provider verifies the supplied full non-development candidate with `jope-dist`, requires its embedded source and native Linux compiler target, and checks a clean matching Git HEAD. It builds the current service library and snapshots the Cargo-reported dependency artifacts outside source before compiling the libtest. This prevents the unversioned `jope-telemetry.rlib` from being replaced by test feature unification and accidentally linking a different closure. An optional dependency-directory input in the existing test helper selects this immutable snapshot; existing callers retain their default behavior. Hashes, commands, stdout and stderr remain alongside the result. The provider runs the one exact ignored selector explicitly and requires one passed, zero failed/ignored/measured cases plus exactly one valid measurement for each fault. Source, candidate type/bytes and snapshot hashes are rechecked before publishing an exclusive new result. Unsupported targets, missing cases, malformed or duplicate summaries, drift, missing sensors and unsuccessful recovery refuse PASS.

Invoke `python3 -B deploy/qualification/v1.0/providers/r2.py` with the five standard `JOPE_REL07_*` bindings from `GATE-RUNNER.md`. The result records one collected/executed/passed Rust test and two measured fault scenarios. Evidence/runtime paths stay outside source and `/tmp`; Cargo jobs are four, math threads one, and child commands run at nice 10. The build host must satisfy the coordinator's resource admission rules.

Controller controls: `python3 -B deploy/qualification/v1.0/test_provider_r2/test_r2.py -v` (set `JOPE_QUALIFICATION_TEST_TMP` outside source). Their candidate, compiler artifacts and subprocess responses are data-free fixtures, not release qualification. A real candidate-bound R2 PASS requires actually running the provider against supplied signed release bytes; local native test success alone does not qualify a release. No public API, production worker protocol, release schema, weights or signing behavior changes.
