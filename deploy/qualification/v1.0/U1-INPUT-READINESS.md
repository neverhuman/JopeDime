# U1 pending terminal input after resize

The default crossterm 0.28.1 Unix/Mio source returns from inside a readiness batch when it sees SIGWINCH or the first parsed key. A later token in that same edge-triggered batch is then discarded when the next poll overwrites the batch. The unread terminal fd remains readable, but no new edge is required until additional input arrives. This strands an Enter typed alongside resize; waiting for the restored-mode marker in the test avoids the race without repairing input delivery.

Preserve unprocessed readiness tokens across returns. An already-serviced TTY token is consumed, rather than reread without fresh readiness: the controlling terminal fd can be blocking. Signal, parsed-key and waker returns preserve the remaining tokens from that batch. Existing parsing, ordering, timeouts, keyboard APIs and default feature selection remain unchanged. The exact registry crate is vendored from the existing Cargo.lock checksum; only its Mio source changes in behavior. Repository LF line endings and Markdown trailing whitespace are normalized; the upstream license is retained. Switching to the optional tty backend was rejected: its zero-duration poll semantics differ from this application's existing poll calls.

The Linux regression runs a supervised child in a real PTY, registers the input source, primes either SIGWINCH or keyboard readiness first, and stops that same child before polling. The parent queues the other readiness and resumes only that owned child. Both orderings are covered. Both already-ready events must be delivered without another byte. This fails on the original backend and passes with readiness retention. Operational wait limits are safety bounds, not a speed verdict.

Original REL-07 RC source0f1cd933/artifactd9472b53 retains U1 FAIL. A later source fix does not qualify those bytes. Existing test synchronization is preserved. No model/reference/tolerance, signing, GPU, network credential or protected-data change is involved.
