### Working Hypothesis 1 — Static-Catalog `v1` Continuation Plateaued After Epoch 10; Syntactic Support Expansion Occurs in Offline GP Search (`ESTABLISHED` lookup `C25–C27` + `NON_QUALIFYING` `C166–C168`)

### Working Hypothesis 5 — `EXP-004` (`41 / 1,554`) Established the One-ULP Tie-Plateau `quantile_edges` + `slice::partition_point` vs. `(lo, hi)` Mechanism, Which Is Consistent With the Three `EXP-008` Context `14` & `18` Parity Failures (`C41–C45, C47, C49, C149, C167`)
- **Recorded Observations**:
  - In `EXP-004` (`ESTABLISHED` `C41–C45, C47, C49`, [`TECHNICAL_WRITEUP.md` §5.5](../paper/TECHNICAL_WRITEUP.md#55-case-study-a-one-ulp-disagreement-between-two-binary-searches)), `41 / 1,554` (`2.6%`) evaluated pairs failed parity deterministically (`41 / 342 = 12.0%` with quantile binning; `0 / 1,212` without binning). The documented mechanism is a one-ulp non-monotone inversion in interior quantile edges computed as `s_lo*(1-f) + s_hi*f` (`sorted[lo] * (1.0 - frac) + sorted[hi] * frac` in `crates/feat-math/src/ops.rs:219` and `crates/feat-math/src/emit_rs.rs:502`; on a tie plateau `s_lo == s_hi == a`, the two-product form can land one ulp below or above `a`, `C47`) paired with two different binary searches: the standard-library `slice::partition_point` search (`while size > 1 { half = size / 2; mid = base + half; base = if pred(mid) { mid } else { base }; size -= half }`, returning `base + usize::from(pred(base))` in the pinned `rustc 1.97.1` toolchain, `crates/feat-math/src/ops.rs:224-230`), versus the legacy `(lo, hi)` `mid + 1` loop (`C49`).
  - In `EXP-008` (`NON_QUALIFYING` `C167`, [`gp-h1-readout.20261013.json`](../internal/clover/gp-h1-readout.20261013.json)), `48 / 51` selected GP champions matched bitwise on both training probes, while `3 / 51` failed parity with readout deltas:
    1. Context `14` (`dataset 51d5e3d9bca34669`, `retrieval_seeded`, `program_sha256: d2177047decf3e91bfef89f83ebdf82436c13a0e4fd4ac9f1a158dbdb5a785fc`, cut 1 `max_absolute_delta = 0.0021133743`).
    2. Context `18` (`dataset 72c1bdcbd2d62359`, `ordinary`, `program_sha256: 14882a7411547281e530e01e632fb9956c859369d64312e5ebdf7d51d4ac64e9`, cut 0 `max_absolute_delta = 0.0321004556`).
    3. Context `18` (`dataset 72c1bdcbd2d62359`, `policy_seeded`, `program_sha256: 6165e86c1c51dc7a7fc9c514dc90f325517a6507d8751d9302be5fc71de98c93`, cut 0 `max_absolute_delta = 0.1367213160`).
  - **Emitter Fix & Synthetic Parity Verification (`EXP-NEXT-04`)**: Versioned opt-in recipe emission (`EmitOptions::partition_point_quantile_bounds: true`, `"feat-math-quantile-partition-point-v1"`) across all four recipe emitters (`emit_rs.rs`, `emit_py.rs`, `emit_cpp.rs`, `emit_js.rs`) and unconditional `lower_bound` in bound Python (`advanced_v3/emit/mod.rs`) transcribe the exact `(base, size)` `slice::partition_point` loop while preserving shipped `EmitOptions::default()` v1/v2 artifact bytes and native `v1` training scores (`C149`; note that the ADR-0004 evaluator identity moves because `emit_py.rs` and `emit_rs.rs` are hashed identity inputs). Representative pipelines exercising the `quantile_bins`, `bin_onehot`, and `target_bin_encode` operator families on synthetic 1-ULP tie-plateau fixtures (`bins=27`, `bins=16`, `bins=13`) in `crates/feat-math/tests/clover_quantile.rs` verify that the legacy `(lo, hi)` helper diverges while the `partition_point` helper matches native Rust bit-for-bit across Rust, Python, C++17, JavaScript, and `advanced_v3::emit_bound`. Whether those three `EXP-008` `program_sha256` champions are completely explained by this mechanism on their original context datasets remains a working hypothesis consistent with `EXP-004` (`original EXP-008 context replay outstanding`).
