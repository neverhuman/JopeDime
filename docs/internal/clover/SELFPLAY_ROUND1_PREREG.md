# Self-play Round 1 confirmatory pre-registration (`SELFPLAY_ROUND1_PREREG`)

> **Status:** Pre-registration packet (`SPQ-1` PR-3) for one bounded confirmatory multi-round self-play evaluation (`H1` / `H4` candidate discovery and selection). **Not an execution grant:** fields requiring an owner ruling or `G-JUDGE` statistical binding remain explicitly marked `UNPINNED` in [`selfplay-round1-prereg.v1.json`](selfplay-round1-prereg.v1.json). No search, training, test-split scoring, or S3 mutation is authorized until all `UNPINNED` fields are bound and an explicit owner admission is recorded.

## 1. Study objective and hypotheses

Following [`CLOVER_VNEXT_FINAL.md`](CLOVER_VNEXT_FINAL.md) (§5.4, §7, §12, §13) and [`GP_EXPANSION_STUDY.md`](GP_EXPANSION_STUDY.md):

- **Primary question (`Endpoint::FinalVsRound0Incumbent`):** Does a multi-round self-play ratchet (`run_selfplay_ratchet` with surrogate-screened seed admission and `measured_tilt_policy` bounded by `decomposed_support_kl`) select a final-round program whose once-only held-out test RMSE (`jope.pipeline-test-score/v1`) improves over the Round-0 incumbent across parent-clustered datasets by more than the pre-registered practical margin?
- **Secondary question (`Endpoint::RatchetVsOrdinaryFinalRound`, `DIAGNOSTIC_VERIFIER_ONLY_PRODUCER_SCRATCH_UNEQUAL_RESOURCES_SINGLE_ENDPOINT_ALPHA_0_025`):** Under equal per-round evaluation budgets and equal resource accounting (`equal_attempts_in_round: true`, `equal_resource_comparison: true`), does the final-round self-play ratchet champion beat an unseeded ordinary search champion (`SelfPlayRoundReceipt.ordinary_champion_genome` in `crates/jope-learning/src/clover/expansion.rs`) on the held-out test split? `qualify-rounds` evaluates `Endpoint::RatchetVsOrdinaryFinalRound` offline against `test_scores` (`QualTestScore`) at conservative single-endpoint `alpha <= 0.025` and fails closed on legacy receipts that omit `ordinary_champion_genome`. However, this endpoint remains **diagnostic/verifier-only** until `J12` equal-resource accounting and multi-endpoint look accounting are closed: `run_selfplay_ratchet` currently emits `"qualification": "scratch_only"` and `"equal_resource_comparison": false`, and under the `B1` single-registry sequential look rule (`earlier_looks`), a single `pinned_test_score_registry` cannot simultaneously record `cand.earlier_looks == [round0.program_sha256]` (for `FinalVsRound0Incumbent`) and `cand.earlier_looks == [ordinary_final.program_sha256]` (for `RatchetVsOrdinaryFinalRound`) whenever the Round-0 ratchet champion and final-round ordinary champion differ.

## 2. Diagnostic evaluation contract (`jope.selfplay-round-qualification/v1`)

Offline diagnostic evaluation is computed by `jope-pools qualify-rounds` ([`SELFPLAY_ROUND_QUALIFICATION.md`](SELFPLAY_ROUND_QUALIFICATION.md)):

1. **Unit of inference:** Parent dataset cluster (`parent_of_context`, at least 2 independent parent clusters required), resampled with replacement via `pools::bootstrap::cluster_bootstrap_ci` (`SplitMix64`, `bootstrap_resamples >= 1000`, conservative single-endpoint `alpha <= 0.025`).
2. **Paired statistic:** Per-context log-RMSE reduction `ln(test_rmse_reference) - ln(test_rmse_candidate)` (`|ln| <= 1e-12` treated as `0.0` per F10 tie tolerance).
3. **Sequential same-registry test-split look rule (`B1`):** Every scored reference and candidate genome must come from a `jope.pipeline-test-score/v1` receipt (`QualTestScore`) in the single `pinned_test_score_registry` with `feeds_selection: false` and explicit `earlier_looks` present. For distinct reference and candidate genomes on a dataset, the reference must be scored first (`earlier_looks: []`) and the candidate second (`earlier_looks: [reference.program_sha256]`). Omitted `earlier_looks`, mismatched registries, registry resets (`candidate.earlier_looks == []` for distinct genomes), or extra looks disqualify the run (`test_split_earlier_looks_sequence_violation`). Note: `TestScore.registry` is a local record, not cryptographic access control.
4. **R5 parity charging and complete context/record accounting (`M5`):** Every expected context in `parent_of_context` must be present in `ratchet_outputs`, and every scored candidate and reference genome must carry a `ParityRecord`. A parity failure is charged as a program failure (`parity_failure`), and unreferenced score or parity records disqualify the run.
5. **Fail-closed KL guard stop rule (`B5`):** Top-level `kl_guard_evaluated` must be `true`, and every round must carry an allowlisted `kl_source` (`"measured_tilt_leaf_policy"` under `--prereg`; legacy no-`--prereg` diagnostics also accept `"caller_evaluated_leaf_log_probs"`), null `kl_malformed_reason`, a valid finite `decomposed_kl`, and `seed_update_frozen_by_kl_guard == !decomposed_kl.admissible`. Unknown, missing, or `*_malformed` KL sources are disqualified (`kl_guard_unmeasured`) even when `allow_kl_frozen_rounds: true`.
6. **Multiplicity (`B3`):** Joint Holm-Bonferroni family adjustment is not implemented in `qualify-rounds` (`multiplicity_adjustment: "unimplemented_single_endpoint_alpha_cap_0_025"`); `RoundQualPlan` enforces `alpha <= 0.025` for single-endpoint evaluation, and any multi-endpoint family adjustment requires manual `G-JUDGE` verification.
7. **Pre-registration contract and admission-gate binding (`B2`):** When `--prereg <PATH>` (`qualify_rounds_with_prereg`) is supplied, `round_qual.rs` parses the JSON strictly (rejecting duplicate keys at any nesting level and trailing tokens), verifies `plan.prereg_sha256 == sha256(prereg_bytes) || plan.prereg_sha256 == canonical_sha256(prereg)`, checks every pinned contract field (`bootstrap_resamples`, `bootstrap_seed`, `max_conditional_base_kl`, `max_new_support_mass`, `allow_kl_frozen_rounds`, `rounds`, `seed_cap_b`, `measured_tilt_policy`, `allowlisted_measured_sources == ["measured_tilt_leaf_policy"]`, `secondary_status`, `memory_floor_free_percent in 1..=100`, plus any pinned `UnpinnedOr<T>` fields with whole-trimmed-value placeholder sentinel rejection), cross-checks each context's emitted `seed_cap_b`, `rounds.len()`, `max_conditional_base_kl`, `max_new_support_mass`, `measured_tilt_policy`, and per-round `kl_source == "measured_tilt_leaf_policy"` against the pre-registration, checks non-empty non-placeholder `ratchet_champion_genome` / `ordinary_champion_genome` and 64-hex syntax on `ordinary_search_sha256`, `ordinary_observations_sha256`, `ratchet_search_sha256`, and `ratchet_observations_sha256` (without re-hashing raw search/observation artifact payloads or externally authenticating the execution grant), and enforces `status` and `provenance_binding_status` consistency (`"prereg_contract_fields_checked_unpinned_no_execution_grant"` when `authorized == false`, or `"prereg_contract_fields_checked_receipts_and_grant_caller_asserted_unverified"` when all fields are pinned and `authorized == true`). `cpu_ceiling_percent` and `memory_floor_free_percent` are validated as `1..=100` serialized contract claims in the pre-registration manifest, not live process/host telemetry. Every report keeps `qualified_claim`, `promotion`, and `l6_claim` unconditionally `false`, and every `--prereg` report (both unpinned and pinned) appends `"prereg_receipts_and_execution_grant_caller_asserted_unverified"` and `"qualified_execution_mode_disabled_offline_verifier_only"`.
