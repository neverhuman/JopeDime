## Merged encoder-receipt spike

PR101 merged an opt-in implementation and seven unit tests plus a compile-fail doctest. The retained exact-head CI and native review bind its source; they do not establish a live admission change. The module's construction and binding API can reject changed membership or data products where explicitly invoked. The teaching entry point currently remains separate. The correct status is implemented and fixture-tested, with live integration pending.

### Falsifiable enforcement experiment

Wire the capability-bound receipt at every teacher ingress, including cache reuse and historical import. Hold fit membership constant, mutate forbidden labels/features and assert unchanged fitting-side digests. Then deliberately swap a same-width Hyperion/target component and require typed rejection. An integration test must exercise both a valid admitted teacher and the invalid cases; rejection-only tests do not prove the authorized path.

## Findings from this study

Two additional defects were found in the attempted measurement, beyond the older Jailgun report: a timing receipt collided with the supervisor's admission file, and the planner parsed outer development labels before projecting fitting rows. The first prevented all CUDA qualification; the second violated the requested strict staging boundary even though no score or held look was consumed. Chapter10 preserves both findings, the original failed source and the locally tested corrections. Neither source repair is reported as an operationally successful rerun.

## Remaining limitations

The study measures the accepted regression path. Binary/multiclass source paths, experimental models, historical Hyperion variants and external adapters are documented without broadening the benchmark. Metadata inventory is not training exposure; a CPU fixture is not live GPU qualification; a successful export does not promote a model. Qualification failure is useful evidence but does not establish a total latency.

## Interpretation of evidence

A configuration file proves intent. A successful build proves that a source/toolchain combination compiled. A fixture proves the exercised case. An operational receipt proves its recorded inputs and boundaries. A native independent review proves that a different process assessed an exact head. None retroactively repairs a missing historical input closure or a corrupted measurement. This distinction is central to technical auditing of the learning loop.
