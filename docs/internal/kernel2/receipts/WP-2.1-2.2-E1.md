# WP-2.1, WP-2.2 and E1: capability declarations and revisioned search profiles

This is kernel2 PR 09 on `kernel2/claude-m2-manifest`, based on main
`0616a93ef13838625d54f43a315e675738932a74` after #133 and #134. The code
adds `feat_math::kernel::capabilities` and `feat_math::kernel::profile` and an
example dump. No shipping search reads a profile or the manifest in revision 1.
The generated document is `docs/internal/kernel2/capabilities.generated.md`.

## Identity and frozen inputs

The workplan proposed a root `src/capabilities.rs`; this PR puts the public
module under `kernel/` so it adds no ADR-0004 hash input. The 38 evaluator
identity inputs, `evaluator_identity.v1.json`, the jope-engine lineage source
list, registry, frozen grammars, compat fixtures, `Cargo.toml`, `Cargo.lock`
and `docs/internal/kernel2/ablation-protocol.md` stay byte-identical to the
base. Jope-engine lineage digests also hash `/proc/self/exe`; those digests can
move when feat-math changes even while their listed sources do not.

The registry remains untouched under the owner decision, “The registry is not
edited this release.” Its eight compatibility rows generated by the grammars
are declared `LegacyDrift`, and the ten grammar-only rows are explicit.

## Legacy generator rows and their sources

| Row | Source and scope |
| --- | --- |
| `legacy-expr-edit-v1` | `MathExpr::mutate_v1` in `crates/feat-math/src/math_expr/evolution.rs`: leaves, all 15 unary functions, five binary ops, min/max/step and clip; no unary negation. |
| `legacy-full-grower` | `random_expression` and `random_expression_expanded` in `crates/feat-math/src/full_rust.rs`, plus its public transform, expansion, head and target-kind lists. The base and expanded expression runs are checked separately. |
| `legacy-slot-insert-v1` | `PipelineSlots::mutate_v1` in `crates/feat-math/src/kernel/pipeline.rs`: seven inserted stages and expression edits through the first row. |
| `legacy-v3-typed-edit-v1` | `initial_population` and `mutate_candidate` in `crates/feat-math/src/advanced_v3/evolution.rs`: twelve baseline or edited stage names; the two inserted names are checked separately. |

The legacy wrappers copy expression strings; their profiles therefore omit
`expr` and `expr_stages`. The full grower and expression editor can introduce
runtime-only elements, as pinned legacy behavior. Target kinds such as
`rank_gauss` and `log1p` are values of the `target` op parameter, not op rows.
`python/src/jope/grammars/sampler.py` draws from each grammar's tables for seed
corpora and property tests. Python work is outside this PR; the Rust grammar
checks cover those tables.

## Emitter refusal labels

The probe strips a reason at its first `(` or `{`, then maps a reduced label
to the declared row. `Gbm`/`gbm` selects `histgbm` and alias `gbm`;
`Blend`/`blend` selects `ensemble` and alias `ensemble_ridge_gbm`;
`MapExpr`/`map_expr` selects `map`; `DeriveExpr`/`derive_expr` selects `derive`;
`GprKernel`/`gpr_kernel` selects `gpr`; `HistGbm2` selects `histgbm2`.
`target transforms` selects `target`, `symbolic formula programs` selects the
`symbolic` form, and the planning refusal `portfolio` selects the
`nested_portfolio` form. Other prefixed labels use the snake case of their
planned variant; bare planning names select the same-named op row.
