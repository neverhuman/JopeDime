# Scalar-v2 training recipes and fitted export

`ScalarExpressionProgram` exposes explicit numeric-input row and elementwise carriers. `plan_training(carrier, width, lambda)` builds one replacing scalar stage followed by the existing ridge head. `emit_recipe` emits a complete Rust, Python, or C++17 training/prediction recipe. `emit_recipes` returns the existing paired Rust/Python and C++17 artifact containers; its sidecar binds program bytes, numerical policy, grammar/profile identity, input/output shape, lambda bits, all source hashes, and actual token/byte counts. The paired assembly timing excludes the separately assembled C++ source.

Training requires nonempty rectangular rows, width 1–512, matching finite labels bounded to 1e12, lambda 1e-5–2, and valid row/elementwise variable scope. Raw IEEE inputs reach the scalar feature stage. Its final values are protected, and `predict_with_faults` retains the per-row union of feature faults. Prediction checks the fitted input width and leaves training state unchanged; empty prediction is valid. Invalid Clip bounds remain hard errors even below another function. Standalone Rust/Python CSV adapters preserve nonfinite IEEE cells and reject ragged widths; inherited blank/malformed-cell parsing remains zero.

Retained instructions lower through the existing expression emitters. Func19–22 and explicit-policy Asinh13/reductions use the existing qualified helper bodies. Scalar-v2 adapters preserve native signed zero for legacy-policy sums, Python floor/round, C++ min/max/Clip and row extrema, and the all-negative-zero ridge intercept. Those adapters do not change the frozen legacy emitter bodies or outputs. Old operations retain PlatformLibm; Portable emission is refused for this slice.

`ScalarModel::emit_fitted_cpp17` emits immutable predictions and faults without a fitter. `emit_fitted_artifact` reuses the established fitted artifact container with strict scalar-model JSON as its numeric codec. Source and codec hashes, and the model identity in the source header, bind the emitted function to the fitted state. The scalar model reader requires format/minimum-reader 2 and validates feature, policy, grammar/profile, emitter, shape, and IEEE state before prediction; an unsupported future identity refuses before payload dispatch.

The additive feature identities are `feat-math.scalar.ridge.recipe.v2` and `feat-math.scalar.ridge.fitted.v2`. Existing default programs, fixtures, seeded streams, and global emitter version remain fixed. Readers precede these writers: the bounded scalar program reader and strict native scalar-model reader are already available; callers must use the explicit scalar-v2 route rather than legacy deserialization.

The parity test executes 106 mixed programs with both policies and carriers, every retained function and row variable below a new call, large/tiny/zero/nonfinite inputs, cancellation and scaled reductions, exact fit state, held-out poison, and structured width/label refusals. Rust and Python plus g++ C++17 and clang C++20 compare every feature, fault, state, and prediction bit with native execution. C++ qualification uses `-O2 -ffp-contract=off -fno-fast-math`; sanitizer qualification is a separate recorded gate.

Generic fit/model routing, producer-profile binding, shipped generation/EEC, and the equal-budget utility cohort remain subsequent B05–B07 follow-ups. This recipe slice does not change Baseline admission or default search behavior.

The retained `ridge_signed_zero_labels.v1.json` covers all-negative-zero labels and both mixed-sign zero orders on nonzero features, including correlated columns and a constant column. Both policies compare every native/emitted fit-state bit with varying and constant Row features and all three Elementwise features; the intercept is negative zero only for the all-negative-zero case, and every slope is positive zero. Native `RidgeModel::fit` uses floating-point `Sum` for the target mean (`heads.rs:453`) and stores it as the intercept (`heads.rs:479`). Scalar-only Rust, Python and C++ adapters restore that intercept because their retained ridge helpers accumulate from positive zero. Feature standardization is label-independent; the positive-zero right-hand-side accumulation and positive-diagonal Cholesky solve leave every zero-label slope positive zero. Mixed-sign labels produce a positive-zero target mean and do not activate the adapter.
