# Execution closure and remaining acceptance evidence

The requested operating system is **not yet qualified**, and no new flywheel breakout has been demonstrated. This implementation closes specific source defects and expands original evidence custody. It does not establish a funded production release, a useful GPU hour, or either required promotion/discovery cycle.

All builds and substantive tests in this tranche run on the remote eight-A100 node. xbabe2 performs source edits, coordination, synchronization and custody metadata work. The original resident pool is preserved. Source changes are transferred into immutable, independently hashed remote checkouts; they are not silently substituted into the running pool or the live remote application checkout.

These passes cover different content and do not establish a controlled speedup. Blocking filesystem and metadata operations can still exceed the bulk window; a strict whole-operation I/O deadline is not claimed. Whole-project remaining bytes/files remain unknown; a page is not a denominator for the project.

Available source objects can now be preserved while missing paths remain explicitly unresolved. Canonical publication requires complete observed source coverage on both hosts. The CLI no longer publishes a canonical pointer before the controller performs these checks.

Only the maintenance mirror controller and its timer are installed in this tranche. Its exact identity, live attempts, transferred versions and remaining coverage appear in the implementation summary and original mirror receipts. Earlier targeted CPU, resident, cache, heartbeat and query results retain their own exact source bindings. The linked verification matrix records source closures, host, execution times, exit codes and original log hashes; each original receipt contains the exact command and deadline outcome. The index checks retained log bytes against the original receipt digest where present and binds each receipt to its tranche manifest. Earlier receipts lack an execution-time log digest; their later two-host custody hashes are retained and the missing original binding stays explicitly unavailable. These integrity checks do not supply an independent execution witness. Relevant distinctions include:

- The first authority run used a two-thread runner against a one-thread contract and failed before numerical work; its interruption and diagnostic are retained.
- The first neural compile failed because Clang's C++ header search lacked `cstddef`. The corrected remote build uses GCC 11.4, LibTorch 2.7.0 and CUDA 12.8, with CUDA hidden for engineering checks.
- An early science test lacked the gap-register fixture in the staged tree; the successor staging includes it.
- Three debug authority fixtures expired deadlines while hashing/verifying large unoptimized runtimes. The public authority tests pass in an optimized build with their existing 30-second execution cap. The separate retained-query fixture now has a bounded original 120-second window and still waits for original expiry before read-only retrieval. This is not a measured production throughput result.
- The corrected authority suite's original 66 passes, one failure and three ignored cases remain recorded. Subsequent targeted results are recorded separately; counts are not added as if they were distinct tests.
- After provisioning rustfmt and Clippy for the pinned remote Rust 1.97.1 toolchain, formatting failed across 63 files and strict Clippy stopped at 33 findings in the numerical dependency; native lint coverage is therefore incomplete. Formatting/lint findings and unsupported or ignored cells remain visible. A build result does not imply every binary is authorized to execute, or that the deployed UI passed Tuiwright/Bullet qualification.

## What still prevents the requested result

The existing [issue register](gap-register.json) keeps implementation, verification, deployment and scientific status separate. The following are acceptance dependencies, not optional polish:

1. Recover original authorization provenance and complete consumption history; independently reconcile a canonical balance and implement original native grant/consumption adapters. Recovered filenames or caller booleans cannot release the execution hold.
2. Complete all-route containment, historical completion adapters, independent witness recovery and the recovery epoch. Ambiguous starts remain unavailable. Direct library and retained-binary routes need explicit OS custody.
3. Complete both-host raw/protected/source/reference coverage, application snapshots and restoration. Preserve all conflicting originals.
4. Qualify the resident replacement as a complete release, including all-rank checkpoints, exact resume, deadline/rank-loss recovery, device lease and peak device/staging memory. Keep the old pool until that gate passes.
5. Produce a real ready queue from verified funded work. Preserve the 312/208 reserves without counting nonexistent searches as runnable work. Complete cut-commit census/atomic reservations and broader eligible family/dataset/cut collection.
6. Complete original scientific selection/access/query/slot producers and independent verifiers. Keep all ten sealed families sealed. Qualify the required learning objective, requested new exposure and original support/replay study; test the order-aware encoder in its own lineage.
7. Measure exact optimization and screen performance with comparable full-task costs and original eligible work. Preserve negative results and unsupported strata. Neither FP32 storage size nor scratch allocation changes prove application speedup.
8. Join reservations, actual device intervals and accepted durable outputs for a full uninterrupted 3,600-second useful hour: 28,800 allocated GPU-seconds, at least 90% verified useful occupancy, p95 handoff below 30 seconds and complete interval coverage.
9. Qualify P1, observe subsequent original discoveries attributable to P1, qualify P2 and observe subsequent original discoveries attributable to P2. Preserve promotion thresholds and negative outcomes. Independent external evidence is still required for a world-class claim.

At the recorded 22:32:34 UTC hardware sample on September 11, all eight A100s report zero utilization while the preserved ranks retain approximately 16 GiB each. Compilation, CPU tests, cached tensors and descriptive historical receipts do not constitute useful GPU learning or a flywheel. The implementation summary therefore leaves the overall scientific objective incomplete.
