# Data, cuts, eligibility and packing: red-team audit and execution plan

This is a read-only research result and a proposed implementation plan. No fit, training, context-vector read, protected-value read, service change or activation was performed for this audit. Earlier partial implementation edits were stopped when the user changed scope; they remain untested and must not be deployed on the strength of this document.

The strongest finding is a selection bottleneck inside an already large retained cohort. The disputed 4,048-cut expansion number is not needed to explain narrow coverage. The active context index has **8,016 training/validation contexts**, while 68 generation manifests repeatedly select **140 dataset–cut pairs**. Job manifests are not physical-start or fresh-discovery evidence.

## Why only cuts 0 and 1, despite five-fold preparation

Local `parallel/src/proposals.rs:70` selects `c.partition != "meta_test" && c.cut >= cut_start && c.cut - cut_start < cuts`. `continuous_learning.py:688` copies the configured `cuts` and `cut_start` into each generation; proposal commands pass them unchanged. The 68 retained generation specifications and original job manifests confirm `(2, 0)` throughout. There is no rotation implied by generation number. This is an explicit selection policy, not evidence that only two folds exist. Local source and deployed release identity still need their final linkage before attributing all runtime behavior to the local line number.

`prepare.rs:324` implements five ordinary folds for non-time-series tasks. It unions identical predictor rows and supplied entity IDs before assigning groups. Binary/multiclass tasks stratify by group label sets and require class coverage. Each ordinary fold holds out one group partition and trains on the other four. Across five folds, training sets overlap heavily. A cut is not an independent dataset or a fresh source-family discovery.

For `task == "timeseries"`, preparation uses five chronological rolling origins and a supplied horizon. Repeated-cut expansion (`prepare.rs:1206`) rejects time series, changes deterministic partition seeds for ordinary tasks, skips duplicate training memberships, and retains the original source family count of one. Its persisted `heldout_role` explicitly identifies an adaptive teaching objective. Repeated five-fold rounds increase available teacher views, not independent evaluation sample size.

A temporal source mislabeled as ordinary regression will bypass the time-series branch. A missing or wrong entity review can likewise leave related people, locations or instruments on opposite sides even when explicit row-index overlap is zero. Frozen hashes faithfully preserve bad semantics as well as good semantics; provenance and split review remain necessary.

## The 4,048 claim does not survive as an eligibility count

The bounded census considered 17 retained index artifacts, expansion prepared directories, current ordinary component roots and `runs/expansion-encode-*/components/*`. It grouped component metadata by **dataset, prepared digest, cut, training digest and preprocessing digest**, rather than directory names. It found 13,862 component identity groups, of which 12,922 had all three component receipt kinds. **1,930 such groups were outside the retained indexes in this scope.** This does not reproduce 4,048 and is not a global inventory result. Component-spec/signature variants within a group are retained in source bindings but were not exhaustively adjudicated; vector bytes were not opened.

The expansion prepared scope contains 539 preparations and 2,695 cuts: 1,425 regression, 505 binary, 350 multiclass and 415 time-series. All 2,695 are outside retained indexes by the exact dataset/prepared-digest/cut key. **Zero have eligible matching family/partition membership in the audited registries**, including the retained expansion registry. Seventy-five cuts have some historical registry disposition, but that does not match and authorize their current prepared membership.

Only ten expansion cuts satisfy the current strict receipt metadata fields across all three components. This is **not** a claim that only ten vector triplets exist. In the producer's `missing_components` field, “missing” includes incompatible/missing receipt fields: 1,920 cuts lack a conforming Hyperion receipt, 760 lack all three conforming receipts and five lack conforming foundation/target receipts. The original Hyperion example in `source-corpus-metadata.json` has `target_access` as free text, but no `family` or `final_test_targets_used` field. Current native composition expects those exact fields. A schema adapter needs retained provenance and byte verification; writing `final_test_targets_used=false` into old receipts is not verification.

The safe conclusion is **an empty verified expansion queue within this bounded scope**, with unresolved retained component outputs. It is neither “4,048 ready cuts” nor “there is no possible expansion anywhere.” Canonical source-component graph and prior-use decisions must be reconciled before any new family assignment. Empty queue is a valid result; using old training references to qualify assembly does not enlarge it.

## Actual geometry changes the cost argument

The previous chat's 765-cut geometry is not the active-index denominator. On the exact 8,894 active metadata rows, training-row counts are median 275, p90 800, p99 819 and maximum 4,751. Only ten contexts exceed 1,000 rows; none exceed 5,000. Consequently an extra 1,000-row cap cannot be justified from the unrelated 33,543-row maximum cited earlier. Source preprocessing/sampling already materially affects the active views.

All 8,894 metadata cuts have zero explicit training/validation row-index intersection. This confirms a necessary combinatorial property only. Six thousand rows have no `entity_columns` key, 95 have an explicit empty list, and the others name grouping columns. Missing legacy fields need their original review lineage, not automatic exclusion or automatic acceptance. Likewise 8,799 prepared records have `family_partition_frozen=false`, but native registry binding intentionally supports older metadata when a frozen registry preserves the assignment. Testing that Boolean alone would misclassify the active cohort.

Cost profiling must join the exact active prepared digest, dimensions, predictor width, task and model head to **original** timing receipts. Report cold and warm view reconstruction, hashing, transform application, kernel fitting, prediction and admission separately. Do not average RMSE across incompatible target units or infer model cost solely from row count.

## Data-layout and early-row-cap recommendation

Keep the recorded fit contract at f64. The immediate source-supported experiment is to reduce repeated conversion and allocation while preserving immutable input bytes and exact indexing. `gp.rs:352` already writes a contiguous f64 training/validation buffer into a sealed memfd; `gp.rs:418` reads that buffer into bytes and reconstructs `Vec<Vec<f64>>` in each evaluator. `prepare.rs:75` and `fit_boundary.rs:59` also expose nested row vectors. A bounds-checked flat f64 matrix/view can remove row allocations and copying at these boundaries. Extend existing binary/shared-memory representation before introducing a second general-purpose file format.

This is a measurable hypothesis, not a free or guaranteed largest speedup. Keeping element traversal and arithmetic order unchanged can preserve results, but flat layout by itself does not guarantee bit equality: changed reductions, compiler vectorization, fused operations, BLAS choices and threading still need exact fixtures. Code changes also change the source/executable identity; the authority contract binds executable and loaded-runtime digests (`eval_registry/authority.rs:112-118,171`). Successful parity needs an explicit compatibility decision, not an assertion that no identity changes.

Do not add a blanket 1,000-row screening cap to the active collection: only 10 of the current 8,894 context cuts exceed it (0.112%). Prioritize recovering parse/serialization/worker-start overhead and widening verified cut coverage, then compare the actual expensive tail by rows, width and head. If a later separately funded screening experiment uses fewer rows or f32, give it a distinct purpose, computation identity, reservation and training-only data-access contract. Numerical fitting still requires authority even when it emits no admitted observation. Screening changes which programs survive and therefore changes the search protocol; keep its cost, failures, ranking errors and false-rejection rate visible, and refreeze comparisons before it can affect a protected panel. A proposed screening acceptance metric is retained full-fidelity winner recall at equal total core-seconds on a frozen training-only panel, alongside total strict admitted improvements; reduced per-candidate latency alone is insufficient.

## Packing, caches and assembly: performance claims need their own identities

The state-selected corpus `snapshot-000421/corpus/index.json` binds the active context digest and reports 8,899,150 packed records, with `qualification=true`. Its 55,634,460-byte manifest reports 24,313,972 observations seen, 1,338,630 with no matching context, 488,028 withheld meta-test records, 79,375 failed programs, and vocabulary rejections. These are retained counters, not independently verified fresh-admission counts. The packing receipt reports 7,863 reused groups and 14 rebuilt groups: 99.82% group reuse for that snapshot. These receipts do not prove per-rank device reuse or end-to-end latency.

Local teaching storage hashes payloads into sealed memfds and exposes read-only mappings. The shared cache is keyed by content digest and length; an unchanged record payload can be shared even if a path changes. The resident teaching cache uses the corpus index digest. A new corpus digest can therefore invalidate higher-level state even when most immutable shards are unchanged. The scheduler lane independently found all 108 historical blocks reset optimizer/sampler state and use distinct corpus indexes; those facts must be included when evaluating apparent warm-cache improvements.

A large manifest can remain expensive to parse, hash and broadcast despite a fast binary record format. Measure bytes read, parse time, durable-write time, host RSS, live memfd bytes, staging peak and all-rank readiness. Do not propose changing record formats merely because a binary format sounds faster. Compare reuse at payload, shard, corpus, device tensor and sampler state levels.

The retained assembly fixes 512 Hyperion + 1,024 projected foundation + 512 target dimensions. The frozen foundation transform consumes 2,048 raw dimensions; scaling, clipping, component specs and registry are part of its identity. The located `run_context_assembly.py` invokes native CUDA composition; a separately retained CPU helper named in the prior plan was not located in the bounded tools/scripts/tmp search. Its existence and source identity remain unresolved. Native original-reference verification formerly scanned the entire cohort; protected references must be selected out using bound index/registry metadata before opening files.

## Proposed plan with measurable release conditions

1. **Freeze the data boundary and finish the census.** Preserve every existing index by reference and every sealed-family membership. Capture both loaded release sources and complete explicit index/component/prepared root lists; compare original objects, aliases, provenance decisions and historical dispositions. Produce mutually exclusive counts for active, retained orphan, missing bytes, incompatible receipt schema, missing assembly, held/unresolved and eligible addition. Acceptance: every candidate has a complete computation identity or an explicit unresolved reason; all source hashes still match; no unknown read is silently counted as empty; the active ten sealed families and all older protected memberships remain unchanged.

2. **Separate coverage from claims of discovery.** Import original task/completion and witness evidence without rerunning known or ambiguous starts. Join each declared job to original execution, result admission and exact corpus contribution. Acceptance: each physical start is original/reused/failed/unknown with no double count; each admitted label identifies its original completion; an observation becomes “fresh” only if its complete identity is new under the frozen history, not because it was copied into a new corpus. Until then, retain the audit's unavailable discovery count.

3. **Use funded collection waves over existing eligible cuts.** First prioritize eligible contexts missing strict admitted evidence, balance across source families, and preserve the frozen protected qualification panel and its 1,000-slot/600-second limits. Training and development-validation roles remain distinct. Production generic/shuffled controls require explicit reservations. Allocate cut rotation explicitly in a durable wave manifest; do not silently repurpose qualification comparisons. Acceptance: deterministic resumable manifests; no duplicate complete computation identities; every chosen cut has a verified membership and funding reservation; 100% of interrupted outcomes reconciled before another wave. Report the number of previously uncovered eligible pairs actually acquiring strict evidence rather than a utilization score.

4. **Admit genuinely new components only after provenance review.** Reconcile canonical aliases, target/units, predictors, entity/time semantics and prior-use evidence. Apply seed-20260907 stable 80% training / 20% distinct development-validation assignment only to new eligible regression components; never add a sealed-test family. Acceptance: native membership verification preserves all ancestors byte-for-byte by reference; alias collisions crossing frozen roles are quarantined; no Boolean receipt summary grants execution. If no component qualifies, publish the empty expansion queue and continue with existing eligible coverage.

5. **Qualify composition without refitting.** Locate and source-bind the retained CPU helper or explicitly review its replacement. Reserve two CPU threads, an absolute deadline and a bounded task manifest. Select four deterministic training cuts from each of two families using index/registry metadata before opening their component/reference files. Verify exact component bytes/specs, prepared digests, registry aliases, transforms and runtime identity; apply the frozen 512/1024/512 contract. Acceptance: eight finite 2,048-dimensional outputs, unchanged dimensions, maximum absolute error at most `3e-4`, unchanged frozen dependencies, and durable immutable publication. No new fit, transform refit, protected reference access, or expansion/discovery credit from these old references. Failure preserves evidence and blocks activation; it never increases tolerance.

6. **Measure cost on the actual queue.** Profile existing receipts by active rows × width × model head, cold/warm state and worker contention. Include input verification, subprocess startup, native math, download, durable admission and handoff latency. Acceptance: original source-bound timing and peak-memory measurements covering the actual queue distribution, with failures/unknowns charged and retained. Any new row caps, search budget ladders, GPU prototypes or allocation experiments require separate reservations and refrozen comparisons. Do not change the scientific budget to manufacture useful occupancy.

7. **Qualify incremental packing and activation.** Reuse compatible immutable shards with explicit references; build a successor corpus preserving the old index by reference and exact objective/vocabulary lineage. Measure per-rank cache hit rates and staging peaks, then require all-rank readiness before activation. Acceptance: records, label membership, grammar IDs and sampling/exposure semantics agree with an independent exact reference; unchanged shards are not rewritten; peak-memory accounting includes old live state plus new staging and all eight ranks; interrupted publication/restart preserves committed outputs and does not change training exposure.

8. **Adversarial verification before release.** Exercise reordered/aliased component names; old prepared digest with new row maps; same predictors with conflicting targets; entity aliases across folds; temporal order/gap/horizon mistakes; final-test reference paths deliberately unreadable; legacy free-text target-access receipts; stale transform/spec/registry; incompatible cache shards; duplicate jobs; unknown acceptance; missing reservation; interrupted publication and rank loss. Acceptance: each invalid case denies before numerical execution or protected read, while compatible retained outputs are reused exactly. Keep implemented, verified, deployed and scientifically qualified status separate.

## Open questions that block stronger conclusions

- The full-project index/component census and canonical alias/prior-use graph were not completed in this bounded audit. A missing item is not implicitly safe or absent.
- The earlier 4,048 and 765 headlines have no matching frozen input scope here; the new numbers are scope-specific, not universal replacements.
- Search receipt presence establishes neither successful fits nor strict admission; the authority/witness join is outstanding.
- The active metadata family counts and row-index checks cannot certify entity/time leakage absence. Source values and protected observations were intentionally unopened.
- CPU composition parity, source/executable binding, byte verification and deadline enforcement remain unqualified. The interrupted local parity and legacy-emitter changes have not been compiled or tested.
- Packed-record counters and reused-group receipts have not independently established useful optimizer exposure or downstream quality improvement.

These uncertainties are required inputs to the release plan. They do not justify rerunning old fits, weakening promotion thresholds, changing protected memberships or declaring the two scientific cycles complete.
