## What actually runs

The actual checkpoint configuration in all inspected blocks uses a 1,536-dimensional dataset vector plus a 512-dimensional target vector. Separate two-layer context encoders map the 2,048 inputs through width 512 with GELU, layer normalization and dropout. The autoregressive decoder has six pre-normalized transformer blocks, width 512, four attention heads, FFN width 2,048 and dropout 0.1. It prepends one context token, uses causal attention, learned positions and a tied token-output embedding. The observed vocabulary has 401 tokens, 657 embedding rows and a 128-token maximum. Minibatches trim the padded sequence to their longest record rounded to a multiple of eight.

These statements are supported by original checkpoint `config.json` receipts for all 108 blocks, the native-v3 [neural.rs:33](evidence/learning-native-v3/neural.rs#L33), [neural.rs:100](evidence/learning-native-v3/neural.rs#L100), [neural.rs:319](evidence/learning-native-v3/neural.rs#L319), and [training.rs:664](evidence/learning-native-v3/training.rs#L664). The source SHA-256 for native-v3 neural.rs is `0ad270f6d4afe77f474c0aadef7a13109024d380b11d7923b1479397152d67ba`; training.rs is `4bd74f36d9d64aa5407a4afb4a3cef7dd408d6bb4907ad75682ddbf1dd6134ab`. Both match the retained build's `source_bindings`. Its target binary is `3382cdcb15c8a04223d03bc15cc95336d9ed9ebcd43f3d31662392425f138d47`, which matches the inspected resident pool manifest. This is retained build/source binding, not an independent reproducible-build proof.

The reward model is materially simpler than the decoder. It averages the separate reward-token embeddings into a program vector `g`, normalizes it, then combines `g` with the target/dataset context `rz` using `[g, g*tanh(gamma(rz)), abs(g-projection(rz))]`. Four MLP reward heads score this feature vector. Runtime uses another MLP on `[rz,g]` followed by softplus. The ablation head sees `g` alone. Source: native-v3 [neural.rs:402](evidence/learning-native-v3/neural.rs#L402).

Consequently the deterministic reward and runtime path is permutation invariant for a fixed token multiset and mask: it cannot distinguish different program orders with identical token counts. This is a structural limitation, not a measured explanation for any tie. The four reward heads are trained through their mean, with no independently bootstrapped targets in the inspected loss; their spread is not established calibrated epistemic uncertainty. The dirty workspace has an isolated two-layer, width-256 order-aware reward encoder in `parallel/src/neural.rs:182`, but production `Policy` does not instantiate it. Do not report that experiment as deployed architecture.

## The five active loss terms

For a sampled program `i`, let `p_i` denote its within-context percentile, `v_i` its scalar value label, and `r_i` the mean of the four predicted rewards. The inspected production objective is exactly

`L = L_sequence + 0.25 L_BT + 0.10 L_listwise + 0.10 L_runtime + 0.05 L_ablation_BT`.

| Term | Actual mathematics and data | Red-team implication |
|---|---|---|
| Sequence | Grammar-masked token cross-entropy with 0.95 target-token weight and 0.05 uniform smoothing over legal tokens; average over non-padding tokens per program, then normalized program weights `0.05 + p_i^4`. | This is reward-weighted imitation of retained teachers, not direct optimization of downstream generalization. A lower training NLL alone cannot establish new discovery. |
| Bradley–Terry | Within each eight-program comparison, finite unequal `v` labels choose winner/loser. Pair weight is `abs(v_w-v_l)`, doubled if either percentile is at least 0.9, then normalized by mean pair weight. Loss averages `weight * softplus(r_l-r_w)`. | Label transforms, tie handling and comparator construction affect the target. Pairwise loss has no calibrated RMSE scale. |
| Listwise | Per comparison of at least three programs, target distribution `softmax(p/0.25)` against predicted `log_softmax(r)`; average cross-entropy over eligible comparisons. | The soft target has a nonzero entropy floor. Saturation near that floor and changing corpus percentiles must not be called failed learning without a fixed comparison. |
| Runtime | Smooth-L1, beta 1, between `log1p(softplus(runtime_head))` and the stored `log1p(observed_seconds)` label, averaged over sampled programs. | The extra log on predicted positive seconds is intentional in this version and matches label units. Runtime is observed wall under a historical execution environment, not an environment-free model cost. |
| Ablation BT | Same pairwise labels and pair weighting, but scores come from the context-free program-vector head. | This auxiliary gradient can reward global program preferences that conflict across contexts. Benefit or harm remains a testable hypothesis. |

The composite weights are in native-v3 [training.rs:720](evidence/learning-native-v3/training.rs#L720); row weights and mean reward are at [training.rs:692](evidence/learning-native-v3/training.rs#L692). Sequence/ranking implementations are in native-v3 neural.rs under `sequence_nll` and `ranking_losses`, retained byte-for-byte in the audit copy. Corpus construction stores `runtime.ln_1p()`; current `parallel/src/teaching_store.rs:130` uses `v=1/(1+RMSE/median_RMSE)` and version-dependent percentile handling, including strict midranks. Historical labels must be interpreted by their original corpus policy, not retroactively as current strict labels.

Stability is computed and multiplied by zero. Seven `loss_log_vars` scalars exist but each is multiplied by zero; they do not provide adaptive uncertainty weighting. Routing is not an active seventh loss. Telemetry exposes the total and four components, omitting the fifth ablation component and all per-term gradient norms. Therefore these logs cannot directly attribute total-loss changes or gradient competition to all five terms. The sequence term normalizes weights within each rank-local microbatch; accumulated gradients are then averaged. That is not generally identical to one globally weight-normalized batch when local weight sums differ. Changing world size or microbatch allocation can therefore change the effective objective even at the same nominal global batch. Any allocation comparison must freeze or explicitly account for this semantic change. Restoring complete loss telemetry is more informative than treating the seven parameter names as seven active objectives.

The complete bounded census of `runs/continuous-learning-v2-20260909/cycle-*/train-2` found **108 readable completed blocks, 62 distinct starting checkpoint identities and 108 distinct corpus identities**, with zero metadata-read errors. Every original initialization receipt says **fresh FP32 AdamW** and **new corpus starts at step zero**. Every block finishes at optimizer step 3,000. Thus the sum is 324,000 block steps and 663,552,000 global program-example presentations at batch 2,048, not an optimizer age of 324,000, unique examples or unique discoveries. Replayed/uncommitted failure exposure and accounting outside this bounded block set are not resolved by this multiplication.

AdamW is initialized with learning rate `1e-4`, decay `0.01`, betas `(0.9,0.999)` and epsilon `1e-8`, with FP32 master parameters/moments and a fused CUDA backend. BF16 autocast and global gradient reduction are separate from optimizer-state continuity. Model initialization from a checkpoint does not load its moments unless an explicit compatible carry policy is used. Native-v3 has a separate replay entry point that can load compatible moments; its resident `Task::Train` does not carry a replay-policy field. The dirty workspace adds that field. ## Recommended bounded experiments and acceptance

1. **First close the evidence path.** Independently verify original selection, pure-proposal scoring, search-access, fixed monitoring and aggregate producers. Keep generic grammar generation, random same-pool ranking, shuffled context and a randomly initialized network as distinct controls. Score common candidate pools before GP, then assess the bounded downstream GP benefit separately. Preserve actual counts, unknown outcomes, shared teacher membership and original-unit baseline-relative skill. Nominate from training evidence; keep protected tests sealed until the one selected challenger qualifies for their existing role.
2. **Freeze lineage before new optimization.** Separate the serving head, experiment head and task. Bind objective, corpus, model, optimizer, committed steps, seed/RNG, sampler and parent completion. Test initialize versus carry as independent conditions with the selected three seeds, batch 2,048, 1,000 new steps and five-minute caps, with at most 12 funded conditions and only when distinguishable; never infer carry from weight loading. A task with missing funding, stale parent, missing witness/acceptance or unknown completion stays unavailable. Qualify exact continuation by comparing uninterrupted and interrupted trajectories under the same identities; changing semantics requires a new lineage.
3. **Measure useful freshness.** Freeze fresh eligibility by complete admitted computation identity. Use the proposed 50/50 fresh/broad comparison sampler, but report actual committed fresh-program exposures, distinct programs/contexts/families, repeat concentration and fallback. No eligible discovery means an empty fresh queue, not reclassified history. Admission's exact active-cohort census, rather than the older raw/prepared denominator, must control coverage experiments. Reserve 312/208 proposal waves and prioritize under-covered eligible contexts before more repeated searches.
4. **Ablate only distinguishable causes.** After the baseline evidence chain works, compare sequence-only against the frozen five-term objective; add a focused remove-ablation-BT test if gradient diagnostics support conflict. Treat order-aware reward encoding as a separately parameter-matched, latency-accounted reranking experiment on common pools. Measure same-token-multiset collisions before funding it. Do not simultaneously change loss weights, corpus semantics, sampler and architecture and attribute success to one. Log all five components and per-term gradient alignment first. A frozen recovery control and unchanged statistical/regression promotion protections remain mandatory.
5. **Qualify scheduling through the full queue.** Start with sequential eight-GPU tasks. Instrument reservation→eligible→lease→all-rank acceptance→corpus activation→first committed step→completion→handoff, with absolute deadlines and original reconciliation. Then assess alternative disjoint device allocations only after lease and communicator isolation are demonstrated. Optimize useful queued completions and latency, not kernel busy time. A 3,600-second useful-hour claim requires the full 28,800 GPU-second denominator, at least 90% classified useful occupancy, bounded handoff latency, no unidentified intervals and original progress receipts.

High-confidence findings are exact configuration/loss structure, optimizer-reset census, missing promotion evidence, deployed/workspace source differences and original receipt arithmetic. Causal explanations for the validation gap, final-GP ties, auxiliary loss harm, larger-model benefit and optimal multi-job GPU allocation remain hypotheses. No protected-reference qualification, scientific promotion or two-cycle discovery claim was established here.
