# Precision, representation and early-search performance

The strongest source-supported direction is to avoid repeated decoding and intermediate allocations, exploit existing compact representations, and reuse compatible immutable computations. Flat f64 storage is a promising experiment; exact parity and useful throughput improvement remain unmeasured. A lower-precision screening tier changes the search experiment and still needs authorized numerical custody.

This addendum examines source and metadata only. No fit, benchmark, protected data read, compile, service change, or implementation edit was performed. The eight key vendor files inspected are byte-identical between the root vendor and embedded parallel copies at capture; hashes are retained in precision-layout-findings.json. This does not certify all vendor files or every historical binary.

## Existing representations and concrete opportunities

| Existing representation | Source evidence | Proposed bounded experiment | Acceptance condition |
|---|---|---|---|
| Nested dense f64 rows | vendor/feat-math/src/lib.rs:82-86 defines Rows=Vec<Vec<f64>> | Flat f64 storage with checked dimensions/stride and borrowed row slices | Same canonical inputs, loop/reduction order, model/prediction bits, exceptional-value behavior and durable completion artifacts |
| Sealed flat input decoded into nested rows per worker | parallel/src/gp.rs:352-432 writes flat little-endian f64, then allocates a byte buffer and per-row numeric buffers | Read-only mapped/borrowed dense view, with alignment/endian/shape validation and scoped lifetimes | Fewer measured bytes allocated/copied; no new mutable access or descriptor lifetime ambiguity; original row/target identities retained |
| New output for every transform | vendor/feat-math/src/ops.rs:893-943; :1282-1303 clones the input again for append, truncates width, sanitizes | Two reusable workspace buffers, explicit output-width planning, copy-on-write append where legal | Preserve append column order, MAX_WIDTH=512, empty-row fallback and each sanitize point; bound peak memory under concurrent workers |
| Already-flat integer tree bins | vendor/feat-math/src/heads.rs:1387-1396 uses Vec<u16>; :1280-1285 accumulates f64 histograms | Reuse bin maps/edges within exact compatible fit contexts; consider u8 only where the established bin range and sentinels fit | Identical bin assignments and split tie-breaking; identical per-bin summation order and final model; account conversion costs |
| Already-flat kernel matrices | vendor/feat-math/src/gpr.rs:74-101, :185 and :252; krr.rs:92-100 | Reuse scratch arrays and independently batch matching shape/kernel operations | No claim that a blanket input-layout rewrite accelerates these dominant solves; measure by head and matrix geometry |
| Dense values with sparse metadata | vendor/feat-math/src/advanced_v3/feature_block.rs:75-84 has dense Rows plus missing masks and sparse_columns | Compressed indicator/one-hot blocks where transforms and heads explicitly support them | No implicit densification explosion; exact missing/category/zero semantics; preserve reduction order when iterating nonzeros |
| Existing flat typed prediction table | advanced_v3/fitted_cpp_runtime.rs:68-137 has Vec<f64> values plus Vec<u8> missing mask and dimensions | Reuse this layout design where appropriate; dictionary/category codes or packed missing bits as separate exact encodings | Frozen sorted category dictionary, unknown code -1, missing sentinel, per-column role and inverse mapping all preserved |
| Existing stage-prefix reuse | vendor/feat-math/src/stage_cache.rs:29-42, :74-88, :99-138; model.rs:125-174 | Authority-owned immutable transform DAG, canonical prefix keys and shared input blocks | Full data/target/fold/preprocessing/implementation identities; no caller-chosen tag treated as proof; real peak-memory and race qualification |

A nested Vec normally incurs a buffer per nonempty row plus row descriptors. It does not prove that numerical computation is memory-bound, that all buffers are far apart, or that SIMD is impossible. A flat layout improves the opportunities for predictable traversal and fewer allocations, but its speedup is a hypothesis. The selected head may already spend most time on flat Cholesky matrices, histogram accumulation, sorting, or kernel gradients.

The stage cache is implemented, but the current parallel authority executor calls ordinary feat_math::fit (parallel/src/fit_boundary.rs:143), not fit_with_stage_cache. The cache's byte counter estimates data cells and serialized fitted-op bytes; it omits some allocator/capacity overhead and enforces the aggregate cap during sweep rather than on every insertion (stage_cache.rs:116-141). It is therefore not a complete concurrent peak-memory guard. Reuse should be integrated through qualified custody, not enabled merely because the API exists.

## Exact f64 semantics and representation changes

Current authority NumericalContract accepts only f64 and binds numerical thread counts (parallel/src/eval_registry/authority.rs:128-168); fit identity also binds executable/runtime. Changing memory representation can preserve mathematical semantics, but that fact is not automatic evidence of exact floating-point behavior, and a new executable does not retain an old executable hash.

A layout experiment must initially preserve traversal/reduction order and compiler floating-point settings. Do not combine it with SIMD reductions, parallel reductions, BLAS replacement, fused multiply-add, reassociation, new clipping or new sparsity rules and then attribute any difference only to layout. Rust documents that mul_add uses one rounding operation and can differ from an unfused multiply-plus-add.[1] GPR explicitly pins kernel/Cholesky/inverse/gradient arithmetic order for emitted parity (vendor/feat-math/src/gpr.rs:18-20).

Skipping zeros in sparse arithmetic also needs care: ordering, signed zero, exceptional values and downstream sanitization can matter. Integer categorical coding and bit-packed masks can preserve information exactly, but sorting/remapping category codes or interpreting unknowns differently changes the model's inputs. Histogram bins are already a compact integer representation; replacing arbitrary continuous features with bins is quantization and a separate semantic contract.

Use existing permitted synthetic inputs and retained original outputs to qualify each conversion. Check intermediate stage bits, fitted parameters, final prediction bits, canonical serialization and original target/row ordering. Preserve the same exact tolerance requirements already assigned to each route. Any approved equivalence across implementation identities needs explicit evidence and continued historical exclusion checks; it cannot authorize re-running an old fit by calling the layout new.

## Typed programs and compilation

Typed ASTs and schema-aware checks already exist in advanced-v3: grammar.rs:64-125 defines compiler modes, emitter targets, stage classes and parameter domains; compile_v3_genome at :1596 validates the task/schema and materializes stages. CompiledV3Genome stores canonical syntax, semantic hash, stage list, feature widths, row-order requirement and target-awareness (interfaces.rs:20-28). This is a useful starting point for a planned execution schedule and buffer-lifetime analysis.

A practical experiment would lower legal stages into an operation schedule with shape annotations, preallocated scratch requirements and explicit dependencies. Reuse parsed/canonicalized programs and immutable prefixes, and choose specialized kernels from already compiled code. Avoid promising a universal JIT breakthrough: the current compiled object still stores Stage records, and total fit costs must show that parsing/dispatch is material before optimizing them.

The fitted C++ route is also distinct from a free compiled interpreter. encode_fitted_cpp17 ultimately calls compile_model_library, spawning g++ for a model-specific shared image (advanced_v3/fitted_cpp_runtime.rs:353-367 and :502-546). That can be useful for retained serving, but compile cost belongs in end-to-end search accounting if used during search. Existing source-name claims about a once-compiled runtime do not imply every model-specific compilation disappeared.

## Early screening and batching

An f32/subsampled/surrogate screen can be scientifically useful without matching final f64 predictions bit for bit. It must instead demonstrate that its decisions preserve useful high-quality candidates at the intended final-budget cost. It is a separate evaluator contract and a changed search-selection policy. Its source, precision, subset/fold identity, target access, RNG, reservation, deadline, physical starts and outcomes must be recorded even when its scores are ineligible for the training corpus.

Screening must not call an existing forbidden fit under a new label or use protected outcomes to tune survival thresholds. Known or ambiguous screens require the same no-rerun/reconciliation discipline within their computation identities. Final f64 qualification remains unchanged. Account both rejected candidates and final survivors, including transfer, conversion, warmup, compilation and synchronization.

The decisive metric is new independently admitted discoveries or protected quality improvement per total reserved compute, with recall of useful candidates and deadline failure rates. Profile this by actual active cohort row count, effective width, head/kernel family, stage chain, cache state and candidate reuse. Old geometry from a different 765-cut cohort cannot set thresholds for today's active contexts. No order-of-magnitude speedup or break-even threshold is established by this source audit.

Persistent authority-owned evaluators and batches may amortize process/descriptor/parse work, but must preserve single-use fit permits, original child/task custody, deadlines, memory isolation and ambiguity reconciliation. Batch only compatible shapes/contracts and retain per-fit identities and original outcomes. The current broad claim that process startup is 93% of useful training time has already been challenged by the scheduler/root's independent timing boundaries; CPU candidate startup requires its own measured profiler rather than borrowing training percentages.

## Deployed parent-selection correction

The remotely retained native-v5 source has no policy_weighted_parent function. Its gp.rs:823 selects left parent as ranked[proposal_attempts % keep]; :824 alternates mutation/crossover by the same counter parity; :829 chooses the next ranked parent for crossover; every eighth attempt draws a grammar-random candidate (:820-821). The later local weighted helper is a separate, unqualified change with the raw-seed quantile defect documented in authority-gp.md.

This deployed rule is deterministic rank cycling, not independent uniform random parent sampling. With keep=10, even left ranks are associated with mutation, odd left ranks with crossover; every-eighth random draws remove even-rank turns. Rejections advance the same counter, so projection failures affect that schedule. Sampling branches and parent choice should use independent, recorded RNG streams in a future experimental protocol if stochastic operator allocation is intended.

Absent policy_logprob fields in sampled retained seeds do not establish that the local weighting function executed inside the old binary. The defensible finding is that the deployed rule has no explicit policy-score weighting of parent choice. Neural seeds still alter the starting population, their survival and their descendants, so they can affect the later trajectory. That causal effect must be measured separately from a direct policy-weighting mechanism.

## Independently confirmed head hot spots and authority costs

The retained native-v5 source for boost2.rs, gpr.rs and heads.rs was independently rehashed against its build manifest and compared with current root vendor bytes. All three agree; the source-bound excerpts are in [head-hotspot-source.json](authority-gp/head-hotspot-source.json). This verifies code-path availability in the retained release, not workload shares or speedups.

**histgbm2:** boost2.rs implements exact, leafwise split search rather than the integer histogram algorithm in heads.rs. It sorts feature-row index vectors once per fit (boost2.rs:207-221), then builds sampled index lists per tree (:339-347) and left/right lists during splitting (:383-398). Index/workspace reuse is a concrete candidate optimization, subject to preserved row ordering, tie-breaking, subsampling draws and gradient accumulation. It must not be described as sorting every feature from scratch every boosting round.

The default is three bags and 500 rounds, but **500 is not the implemented maximum**. MAX_ROUNDS is the historical-default constant; ROUNDS_CAP is 1,000 (:38-48), and parsing accepts up to that cap (:125). Early stopping uses patience 50 (:279-284), so requested rounds are not actual executed rounds. The claimed 97.4% vocabulary occurrence and 13.3x head cost require original corpus/profile evidence; neither is established by these defaults. Replacing exact splits with histogram binning is a new approximate algorithm, not a guaranteed bit-identical storage optimization. The already-implemented histgbm head can be a separately qualified screen, with its own fidelity identity.

**Composite GPR:** gpr.rs:673-679 constructs r2s, s2s and psums vectors inside each kernel term, off-diagonal row pair and gradient step. Allocation reuse is source-supported work to profile. It applies to GprKernelModel, not automatically every gpr candidate: heads.rs:100-104 sends a literal rbf/default kernel to the separate dedicated GprModel path. The source-level vector-construction count is `3 * number_terms * m_opt*(m_opt-1)/2 * steps`; for one term, 256 rows and 40 steps, that is 3,916,800 constructions. This is not an observed malloc/free count, and a 5.9-million universal per-fit claim is unsupported. Scratch reuse must reinitialize every element whose previous value could otherwise leak between terms/pairs and preserve operation order; caching kernel intermediates must bind the current parameter step rather than reuse stale hyperparameters.

**Current unqualified authority:** process_runtime_digest reads process maps and hashes each mapped executable/library file without a content cache (parallel/src/eval_registry/authority.rs:176-194). The worker verifies its runtime before readiness (service.rs:1149), and the service independently validates that original child (service.rs:935). These are separate checks with real potential cost. Mutation holds an authority file lock, appends/fsyncs the journal, waits for independent witness recording on authorization, persists the acknowledgment, updates the witness checkpoint and commits SQLite with synchronous=FULL (authority.rs:1483-1598, :1022). The witness wait is inside the durable mutation sequence. Such serialization can limit dispatch throughput; neither its magnitude nor an fsync-count-per-fit estimate is measured by this inspection.

Add a mandatory, reserved, source-bound throughput qualification before deployment: attribute wall time and actual CPU separately to descriptor decoding, executable/runtime verification, authority-lock waiting, journal writes/sync, remote witness transport/ack, SQLite commit, child launch, numerical work and completion publication. Record distributions at bounded concurrency, warm/cold cache states, denied/reused/new work, witness delays and interrupted replies. Verify the CPU evaluator's exact loaded executable/dependencies; a neural binary --help timer is not a fit-start measurement. Retain fail-closed identity checks and independently durable acknowledgment before every start. Any cache or pipelined/group durability proposal must prove invalidation, ordering and crash recovery rather than skipping those gates.

The unprovided 857k workload shares, 0.97% spawn share and estimated 1.7x speedup are not adopted. Population-level timing claims require original receipts with CPU versus wall boundaries, selection rules, failed/censored attempts and complete head/kernel identities.

## Recommended order

1. Finish the authorized execution boundary and retain original custody.
2. Profile decode/copy/allocate/transform/head/output costs on a bounded permitted fixture panel, including warm/cold conditions and complete charges.
3. Qualify borrowed flat f64 views and buffer reuse independently, then compatible stage/bin/kernel scratch reuse.
4. Qualify exact compact categorical/missing/indicator representations only where measured sparsity/cardinality supports them.
5. Compare authorized persistent/batched execution under original deadlines and individual fit permits.
6. Only then reserve a separate multi-fidelity screening experiment and measure final-candidate recall plus useful quality per total cost.
