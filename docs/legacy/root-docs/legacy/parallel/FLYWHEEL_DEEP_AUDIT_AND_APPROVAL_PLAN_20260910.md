# A regression flywheel that earns its next update

The system needs a stronger learning contract more urgently than it needs more automatic training. Immutable incremental packing, compact resident tensors and persistent GPU processes have substantially improved the operational foundation. The current production corpus still assigns unsupported preferences to exact ties, the reward model discards program order, new collection has narrow cut coverage, and neither the strict replay experiment nor recent automatic candidates has produced a qualified replacement for recovery. Increasing their training frequency cannot establish progress.

The most urgent GP correction is **global at-most-once evaluation dispatch**. The live deduplication only covers individual searches; it does not meet the user's campaign-wide no-repeat requirement. A validated exact-fold result must be reused, while an uncertain started attempt remains blocked. The reviewed registry prototype is not yet integrated into the native evaluator. Its integration and historical exclusions take priority over expanding the collection rate.

The recommended learning direction is **GP-driven expert imitation with explicit measurement of direct neural proposals**, followed by separately qualified ranking, leader-transfer and reusable-component experiments. Keep the recovery model serving. Stop creating automatic training blocks after repeated frozen diagnostic failures and preserve existing durable work. Route continued collection through the qualified global registry and admit only identity-valid observations. Repair the evidence and training distribution before resuming a bounded challenger experiment. MCTS and new vocabulary tokens should follow demonstrated partial-program learning, rather than precede it.

This report distinguishes measured facts, confirmed source defects, plausible explanations and proposed experiments. Operational identities and observations are from September 10, 2026; the data audit fixes snapshot 408 rather than treating a moving corpus as one dataset. The final operational addendum records the last verified deployment and outstanding checks. The ten sealed test families remain unopened.

## 2. Packing and GPU execution

### Improvements already established

Per-search publication and immutable group shards remove the requirement to rebuild and export the entire corpus before every training stage. A versioned manifest references unchanged shards and newly rebuilt affected groups. The reference export remains an oracle: five tested exports reproduce 7,979,769 reference records byte for byte under unchanged label semantics. A warm incremental pack took 45.56 seconds with no rebuilt groups and 7,877 reused groups; a cold qualification took 450.84 seconds. These are specific runs, not universal latency bounds.[^5]

Token and legal-set identifiers now remain 16-bit in resident device arrays. At snapshot 408, these two arrays occupy 4,540,427,264 bytes per GPU, approximately 4.2286 GiB; their old 64-bit representation would require 16.914 GiB. A minibatch is gathered before conversion to the indexing type required by LibTorch. Grammar IDs remain meaningful through explicit shard-local mappings. Binary group metadata replaces enormous JSON lists of record indices.

Persistent workers avoid repeated CUDA process startup and reuse context tensors. Content verification uses sealed shared storage and complete digests; file modification times do not substitute for identity. The verifier now runs independently of the controller's GPU scheduling path. On the deployed combined-verifier release, the first two production verification receipts passed in 10.836 and 10.817 seconds, while training proceeded concurrently.[^6]

Equal-global-batch, equal-step resident qualification provides a useful hardware comparison:

| Configuration | 128-step stage time | Scope |
|---|---:|---|
| Reference, 8 GPUs | 40.92 s | Baseline stage |
| Cold resident, 8 GPUs | 50.32 s | Includes cold work |
| Warm resident, 8 GPUs | 15.93 s | Same immutable corpus cached |
| Warm resident, 4 GPUs | 19.28 s | Global batch remains 2,048 |
| Warm resident, 2 GPUs | 26.46 s | Global batch remains 2,048 |

Parameter parity and the tested two-GPU recovery path passed. Eight GPUs minimized wall time in this fixture; two used fewer aggregate GPU-seconds. This does not authorize repartitioning production resources without checking concurrent proposal/monitor demand and a representative corpus-changing workload. A separate increase from global batch 2,048 to 8,192 changes optimization as well as throughput.[^7]

### Remaining costs and the next useful optimizations

The resident tensor cache is keyed by **whole-corpus identity**. A new snapshot currently walks all records and stages the full token/legal/context-ID arrays again. Incremental disk packing therefore does not yet imply incremental GPU staging. This is a stronger candidate for the next data-path optimization than replacing binary files with another streaming format merely because it is called streaming.

The next design should retain immutable device shards or a program table keyed by verified content, update only affected group indirection/targets, and switch a complete manifest at an optimizer boundary. Account for peak memory while old and new tables coexist. A variable-length program table is promising: the audited mean length is 19.34 tokens, median 20 and 99th percentile 31, versus 128 stored slots. Identifier payload savings could be large, but offset tables, deduplication, alignment and staging overhead must be included. Existing forward passes already round each minibatch's maximum length to a multiple of eight, so removing disk padding does not imply a corresponding attention-compute speedup.[^1][^2]

The source also contains avoidable-looking costs that require profiling before changing arithmetic: per-batch host construction of weights, labels and comparison strings; an entire `microbatch × microbatch` pairwise matrix even though comparisons are confined to groups of eight; scalar device-to-host reads in loss checking; gradient flatten/copy work; per-step synchronization and multiple collective operations. A group-shaped `[groups,8,8]` ranking implementation could reduce irrelevant pairs dramatically. Its gradient reduction order, translation-invariant biases and Adam updates need parity tests because the current dense implementation was introduced to avoid nondeterministic atomic accumulation errors. Do not replace it with the previously problematic repeated-index backward path.[^1]

The policy already calls scaled dot-product attention and uses BF16 autocast. “Enable FlashAttention” is therefore not a substantiated missing feature. Profile actual kernels and backend selection on the installed LibTorch version, including its mask and determinism constraints. Move recurring immutable validation out of the minibatch path only after preserving tamper detection and restart checks. Batch telemetry transfers without weakening nonfinite detection or durable checkpoints. PyTorch's own guidance warns that manually pinning memory on the critical path can erase transfer benefits; use pinned staging only when a measured resident-capacity constraint requires it.[^8]

The controller has a confirmed residual scheduling delay: a receipt-discovery pass took 10.550 seconds, after which the old loop slept another ten seconds and only then reached subsequent polling. The cadence correction launches already-ready GPU work before the CPU scan, subtracts work from the tick sleep, and rechecks pause before a second task-start pass. The parent suite has 90 passing checks; an independent reviewer reproduced and corrected a mid-scan pause race and passed 13 focused cases. This is a source-level correction; its actual deployment status is recorded in the addendum. A long scan can still delay the next poll.

The operational acceptance targets remain at least 90% GPU task occupancy during a full eligible hour, handoff p95 below 30 seconds, and an explicit incident for unexplained idle time above 60 seconds. Occupancy must retain its denominator and uncertainty. Report busy GPU rank-seconds divided by eight times eligible wall-seconds, kernel utilization separately, and all unexplained idle intervals above 60 seconds as incidents. A 10-second observer does not establish exact handoff durations. The independent assessor preserves lower/upper bounds and refuses to call a mostly paused, partly unknown or censored hour a pass. The original assessor used an exact-deployment-start window with initial sampling uncertainty. The current v3 observer instead predeclares the first valid post-release sample as its fixed hour boundary, records the offset and never selects a favorable window afterward. Its separate timestamp defect and retained outcome are documented below. The final release still needs an observed hour with useful work queued; repeated rejected training cannot supply that work.[^9]

## 3. Admission, missing outcomes and checkpoint credibility

Treat an observation as immutable measured evidence, and a training target as a versioned derivation. Admission must bind canonical program, family/partition, prepared input, training/evaluation cuts, evaluator executable and protocol, preprocessing, target scale and metric units, vocabulary, feature view, evaluation seed, resource policy, outcome and source receipt. Compare identities before deduplication; do not let “first program/context row wins” hide a later incompatible measurement. Exact repeated measurements with unresolved disagreement belong in quarantine.

The production GP now emits stronger declared admission identities, and `strict_midrank_v3` exists in the packer. Production training still consumes `reference_v1`. This distinction prevents the existence of corrected code from being mistaken for corrected live labels. Historical data with unresolved identities stays informational. Rebuild a new eligible corpus from bound observations; preserve the legacy shards, recovery checkpoint and rollback manifest.

A confirmed native outcome defect also limits trust: the inspected GP path can clear an unsuccessful worker result when a `result.json` file exists. A file may have been written before a later failure or timeout, and an interrupted attempt may leave one behind. Therefore `failure: null` and a finite metric are insufficient evidence of clean completion. The separate completion proposal requires actual timely successful exit plus bound result evidence and handles recovery through that evidence. Its separately frozen v2 passes 22 actual-helper Rust tests under independent review and corrects the initial proposal’s runtime-binding and exit-attribution gaps. Independent exact-source full native CPU type checking now passes; outcome/admission integration, target build, evaluator/memfd/service execution and real crash qualification remain separate. Existing scores are not retrospectively certified.[^10]

An evaluation registry needs a stronger execution identity than the current declared fields: numerical dependencies, platform and floating-point settings, thread/affinity/quota configuration, all fit RNG, sealed input bytes, normalization and exact deadline protocol. Production explicitly sets OMP/Rayon from `--threads` and BLAS/MKL to one; the concern is an enforcement gap, not observed variation in these settings. Admission eligibility is checked separately and cannot create permission to repeat an identical physical evaluation. The user's no-repeat requirement means historical uncertainty and dispatched work with unknown outcomes must remain blocked. An unknown result is neither a reusable success nor permission to fit again. A genuinely unseen full key requires one durable, fenced start authorization shared by every fit-capable entrypoint.[^11]

The [detailed evaluation registry plan](GP_EVALUATION_REGISTRY_PLAN_20260910.md) specifies canonical keys, durable claims, ambiguous crash behavior, fast indexed lookups, historical tombstones, fold-level reuse and rollout. It specifies at most one authorized start under the declared identity, accepting that a crash can leave permanently unresolved work; this is not a guarantee already enforced by the live GP. Matched experiments need a predeclared shared measurement oracle and equal logical evaluation charges; freezing different per-arm visibility while sharing a global no-repeat authority can otherwise block one arm. Record actual CPU, original measurement cost and logical budget separately. Real cache-off reruns of the same inputs would violate the new requirement; verify registry equivalence with synthetic evaluators. No trustworthy historical full-key hit rate has yet been measured.

The isolated [evaluation-registry prototype](../runs/flywheel-implementation-20260910/evaluation-registry-v1/README.md) implements durable claims, consumed start tokens, result recovery and conservative historical blocking. Its 24 owner tests and 27 independent synthetic tests pass, including 104 competing clients producing one synthetic start. The independent run repeats those 24 cases and adds three crash/token cases; the counts overlap and frozen source is unchanged. It accepts one physical fold and rejects aggregate CV requests; original result references and fold aggregation still need a native adapter. It scans its dispatch journal during transactions and is deliberately unsuitable for production throughput at historical scale. Source allowlists also do not prove family/partition eligibility when partitions share source bytes. Native interception, exact-context access policy, scalable verification and workload benchmarks remain required. No live duplicate-fit prevention or reclaimed compute is claimed.

A new historical census reports 3,897,275 repeated identity strings among 5,053,113 keyable successful rows, with no observed RMSE disagreements. That aggregate count is arithmetically consistent and makes duplicate elimination a high-priority investigation. Independent source review found that the tool trusts the supplied identity string without checking its fields or clean completion; its merge also leaves 1,925,300 cross-worker repetitions out of the per-origin/tier counters. The headline 74.45% “saved wall” is a counterfactual sum of selected evaluator timers, not measured reclaimed CPU or a forecast. The report publishes no usable registry. Keep it as a descriptive census until the evidence and accounting are corrected. [Source and arithmetic review](../runs/flywheel-implementation-20260910/deep-audit-20260910/registry-bootstrap-review-v1/REVIEW.md).

Reporting has a distinct confirmed defect. The old quality report chooses search-wide minima before retaining the winning identity, and the teacher reporter calls a nine-field key “verified.” A regression running the original modules produces an alleged improvement by comparing a teacher at evaluation seed 0 with a neural result at seed 1. The separate v2 reporter partitions complete declared identities before minima, preserves exact tied origins, excludes conflicting/missing evidence and labels its results **declared-identity-only**. All 24 synthetic tests pass. This establishes a code defect, not that a named production improvement was caused by that mismatch. New output schemas and consumers need explicit integration; adding fields to an already compacted winning row cannot repair the discarded comparisons.[^10]

Checkpoint quality requires more than valid model bytes. Preserve model/config/optimizer hashes, bias-correction step, corpus and replay-policy identity, sampler continuation, initialization, runtime/loss versions and consumed-snapshot records. The reviewed training path checks those identities on exact resume. Nevertheless `qualification: true` in a low-level training receipt does not mean the model passed scientific qualification. Likewise, an in-run `validation_best` checkpoint uses adaptive validation for selection; it cannot be presented as training-only nomination or independent evaluation. Candidate and serving state must remain separate, with the full promotion gate as the only serving authority.

## 4. Losses and the training set

The actual objective is:

`L = weighted sequence NLL + 0.25 pairwise + 0.10 listwise + 0.10 runtime + 0.05 context-free pairwise`.

NLL uses legal-token masking, 5% smoothing over legal tokens, a mean over valid tokens within each program, and record weight `0.05 + percentile^4`. This is weighted per-program mean-token likelihood, not ordinary unnormalized sequence likelihood. Pairwise ranking skips equal packed values and weights comparisons by their value separation, doubled when either percentile is at least 0.9. Listwise targets are `softmax(percentile/0.25)` within comparison groups. Runtime loss compares `log1p` of a positive prediction to stored `log1p(seconds)` using smooth L1. Stability and learned loss-weight parameters contribute zero; four reward heads trained through their mean do not demonstrate calibrated uncertainty.[^1]

Three changes should be separated:

1. **Correct derivation.** Exact original-precision RMSE ties share midranks. Preserve original observations, version the policy and rebuild affected targets. Do not freeze arbitrary old percentiles while assigning new percentiles on a different scale.
2. **Correct exposure.** The fresh half of the proposed sampler balances families, includes the champion and at least one actual fresh program, then fills score bands. The broad half preserves historical family balance. Track unique admitted programs, repeated appearances and comparisons separately. If there is no eligible fresh program, record the broad fallback. Bind block identity so new blocks advance RNG while exact resume restores continuation.
3. **Correct representation.** Prototype the separately versioned order-sensitive reward encoder: two attention layers, width 256, four heads, positional information and the existing vocabulary. Initially freeze policy generation and rerank the same frozen pools. Measure predicted selection RMSE, within-pool regret, failures and ranking latency before joint policy/reward training.

The current reward/runtime representation averages token embeddings; the policy transformer itself is order-sensitive. Swapping operator order or parameter attachment can leave the reward representation effectively unchanged. Floating-point summation may introduce tiny numerical differences, but it provides no meaningful learned order representation. The 1,142 observed collision buckets show that this architectural limitation matters to actual teaching labels, without quantifying deployment regret.

Later, compare the moving group-median value normalization against a fixed, training-derived per-cut reference. Current value `1/(1+RMSE/median)` changes when the group median changes. A changed median changes value magnitudes without reversing the order of two fixed RMSE observations; adding programs also changes percentile positions. The concern is uncontrolled target drift, not that derived labels are forbidden to change. A fixed reference may improve stability, but it is a separate target experiment from the first architecture comparison.

Near misses should remain useful without inventing evidence. Keep valid diverse near-best programs for ranking and bounded imitation; exact ties get equal quality-derived targets. Good-but-expensive programs inform a quality/cost frontier. Failed fits inform feasibility. Timeouts provide censored runtime bounds and unknown final quality, not an invented bad RMSE. Interruptions remain distinct from observed evaluator failures. Conflicting repeated measurements require adjudication before teaching.

The failed four-arm replay does not isolate why NLL regressed: its strict-admitted training support is much narrower than recovery's. Before attributing that regression to freshness, add a recovery-wide rehearsal control using only observations that pass strict admission, matched optimizer steps/global batch, sampling policy and repeated predeclared seeds. If the historical evidence cannot support that control, record it as unavailable rather than importing unverified labels. Compare support restoration and fresh exposure separately, keeping the frozen diagnostic panel out of training. Frozen-pool reranking measures selection quality; it cannot diagnose this policy-training support confound. [Measured support mismatch](../runs/flywheel-implementation-20260910/context-support-audit-v2).

The next training set should increase **eligible support**, not just row count. Freeze family membership and contamination status; current prepared identities remain provisional for independent benchmark claims. Keep one anchor training cut per family and rotate another through eligible cuts after that collection protocol qualifies. Respect group/time boundaries and refit every transform inside each search-selection fold. Training-inner CV may drive GP, but repeated optimization over those folds is still adaptive training evidence. Evaluate the whole search/selection procedure on held-out families and preserve sealed tests.[^12]

## 5. What to borrow from AlphaGo Zero

AlphaGo Zero learns from search-produced action probabilities and completed game outcomes. It uses asynchronous self-play, training and evaluation, with a challenger gate before replacing the best player. AlphaZero retains the policy/search/outcome loop but removes that best-player gate and trains separate instances for its games. The 2017 preprint and final 2018 paper also report different training hardware; neither supplies a valid throughput target for this regression pipeline. Retaining our qualification gate is a deliberate response to noisy, adaptively selected cross-dataset evidence.[^13][^14]

Expert Iteration is the closer abstraction: search improves decisions, then supervised learning amortizes that improvement. Neural-guided GP population seeding demonstrates a related loop in symbolic regression, and explicitly notes that GP's sampling distribution is intractable for ordinary off-policy importance correction. Historical GP results therefore must not be treated as standard on-policy policy-gradient samples.[^15][^16]

| Element | Proposed regression counterpart | Required evidence |
|---|---|---|
| State | Training context, partial typed program or complete program under edit, feature view, remaining budget | Immutable context/view/budget identity |
| Action | Legal operator, parameter, macro expansion or edit | Legal set, RNG, action and parent identities |
| Expert | Fixed-budget GP | Evaluated alternatives, ancestry, actual fit/reuse counts |
| Policy target | Recorded distribution over evaluated improved programs; later conditional prefix actions | Frozen weighting rule, duplicate/tie treatment |
| Value | Observed quality under the stated cut and resource protocol | Clean outcomes, original scores, units |
| Cost/feasibility | Separate measured or censored outcomes | Deadlines, failures, execution identity |
| Replay | Family-balanced history plus actual fresh discoveries | Reproducible sampler and exposure receipts |

Define one **episode** as an immutable training-family problem, its permitted inner folds, feature view, grammar and fixed logical search budget. The model proposes programs; GP makes legal edits and requests evaluations through the shared registry. Reused results consume the same logical candidate slots, while physical cost is reported separately. Only that episode's eligible training evidence is revealed to search. Its terminal output is one selected executable program and complete fold/outcome references, including unsuccessful candidates.

A **local win** means that selected program beats the incumbent under the same predeclared complete-fold aggregation and failure rule. Fix tie handling and any tolerance before collection; never treat a timeout, unresolved prior attempt or missing fold as a numeric loss. Quality and execution cost remain separately measured initially. An existing exact-cell result is reused, and a new search seed changes exploration rather than granting a repeated physical fit. Without valid incumbent evidence, label the comparison unavailable. Local wins update the permitted teacher bank and create eligible teaching observations; they do not replace the global serving model. **Generalization wins** require the separate family-balanced direct-proposal and matched-GP qualification panel. That distinction is the game's acceptance rule, not an optional dashboard label.

Start with a bounded deduplicated elite/near-best set per teaching group and a declared distribution `q(program | group)`. Train its supervised likelihood with quality weights fixed before validation. This is selected empirical imitation, not an unbiased policy-gradient estimate. In a later version, aggregate those program weights through a prefix trie to obtain reproducible action targets. Call them empirical evaluated-program targets, not MCTS visits or calibrated posteriors.

For the proposed learned-guided MCTS, trustworthy values for **partial** programs at a fixed continuation budget are missing. MCTS can instead use terminal rollouts, but their evaluator cost must be compared against GP under the same budget. Whole-program reward does not supply it. Collect bounded expert completions from learner-emitted prefixes, including failures, before comparing GP, beam search and prior-guided tree search. Tree search should record actual visits and backups. Do not give ancestors causal credit solely because a successful child contains them. The supporting literature motivates these experiments; it does not establish that this system will become self-accelerating.[^15][^16]

## 6. Leaders, components and a few-generation CV loop

Separate three outcomes for every neural search: the pure predicted-best program, the best evaluated neural-pool member, and final GP performance after retained teachers and evolution. GP rescue can hide a weak generator or selector. Preserve fallback and teacher origins, failed selected proposals, checkpoint identity and the generation RNG manifest. Current generation/enrichment behavior is not a qualified matched-arm protocol merely because a newer implementation exists.

A 16-slot shared bank is a useful first transfer experiment: eight local teachers, four eligible cross-family structures and four random candidates. Freeze exact content, order and fallback mapping identically across comparison arms. Retrieve only from permitted training sources; map feature types/positions explicitly and consult the registry for each exact current-cut physical evaluation. Reuse its validated original result; authorize a fit only for a genuinely unseen eligible cell. Transfer neither another cut's scores nor its fitted parameters. Quality, cost and structural diversity should influence the bank, rather than selecting only near-duplicate winners.

Using the same bank helps isolate neural contribution only when the other proposal, search and budget conditions are also matched. Whether the bank itself helps requires a separate old-bank/new-bank comparison. Current unqualified enrichment replaces some slots in the neural proposal artifacts while assembling a new generation's jobs, which can confound source attribution and matched capacity. It is applied only to the neural comparison arm. Make this an explicit experiment policy, defaulting off for future generations until qualified; preserve old queued generation identities and seed bytes. Correct false `policy_logprob` values and ranked-parent alignment in versioned source, then qualify a new binary/proposal protocol; do not reinterpret existing seed manifests or swap a running GP process.

The [population-policy v2 source correction](../runs/flywheel-implementation-20260910/population-policy-v2/README.md) now implements that default for new generations. It preserves legacy pending/orphan generations and rejects disagreement between a versioned policy in state and its durable generation file before dispatch. Its 44 focused tests and 136 held-controller tests pass; those suites overlap. Only the controller differs from the 145-file held source. This is not deployed and does not qualify the legacy enrichment or an alternative leader bank. Existing command options still drawn from the current controller manifest need their own review before changing mid-generation.

For components, first log parents, mutations, crossover positions, expanded programs and measured outcomes. Mine at most 16 typed macro candidates from training leaders spanning at least three families, deduplicating shared ancestry before counting support. Expand macros into the existing grammar before evaluation and serialization; charge expanded complexity and runtime. This changes search proposals without immediately changing neural vocabulary. DreamCoder supports jointly testing abstractions and neural guidance; Stitch supports efficient abstraction mining. Neither makes fragment frequency or compression a regression-quality result.[^17][^18]

Freeze the library before testing held-out source families and macro-disabled ablations. Measure whether removing a component changes selected quality or cost, not merely whether it appears in winners. Vocabulary expansion is a later experiment with new checkpoint compatibility and initialization.

After a model fully qualifies, try one bounded GP generation from its proposals followed by at most two additional generations seeded from new winners on **training-inner CV only**. Stop when declared teacher improvement or marginal evidence yield stalls. Do not run extra generations conditionally on validation improvements and call their selection training-only. More searches of the same folds can overfit the search criterion; the outer evaluation must include this adaptive procedure.[^12]

A new retrospective common-program diagnostic on 75 dataset labels favors one five-cut log-score selector over selection on the first cut: 40 wins, 16 losses and 19 ties. Independent recomputation reproduces a mean log contrast of .04748 and a 54.58% reduction in regret relative to the same hindsight pool oracle. The geometric reduction relative to the single-cut comparator is 4.64%; the reported 4.86% uses the other denominator. These are descriptive historical contrasts. The tool does not enforce full evaluator identity, requires successful observations on all ten cuts, omits actual selected-program/cut identities and exclusions, and has no fixed candidate ancestry. Different split seeds reuse the same underlying rows. Its mean centered-log-RMSE plus .25 spread penalty also differs from pooled out-of-fold RMSE. This diagnostic motivates a separate CV experiment; it does not qualify the proposed objective or a transfer gain. [Independent source and arithmetic audit](../runs/flywheel-implementation-20260910/deep-audit-20260910/cv-evidence-review-v1/AUDIT.md).

The associated 7.8% statistic describes dispersion across five single-cut winners' measured second-round scores. It establishes neither a lower bound on production selection noise nor the asserted 8–26% range. Request the complete identity-bound candidate-by-fold table, exclusions and ancestry before stronger interpretation. For a prospective CV engine, bind ordered fold identities, original-unit squared-error sums and row weighting, fold-local preprocessing, every fold's outcome and a **total** candidate deadline. Changing a 30-second total limit into 30 seconds per fold silently changes the compute experiment. Compare mean-only aggregation and a spread penalty separately; freeze the outer assessment of the entire adaptive search before dispatch.

## 7. Hyperion and a meaningful smart flag

The existing Hyperion dataset signature in neural context is different from Hyperion-generated GP input features. Keep these interventions separate. The CV7 confirmation contains 40 seed receipts across 20 datasets: five positive seed deltas, six structural raw fallbacks, zero selected activations and zero robust dataset wins. These are not 40 independent datasets.[^19]

The source audit finds that the confirmation loads full-training encoded features before forming CV folds, then refits percentile postprocessing within a fold. This does not establish fold-local encoder/reference-bank construction. A historical full-table encoding remains diagnostic even if a later normalization is fit only on training rows. Local query recipes also require scrutiny for dependence on other query rows; local source hashes differ from some pinned historical implementations, so these findings must not be retroactively attributed to every past binary.

The proposed contract is strict: one future row's prediction cannot depend on which other future rows arrive with it. Implement `--hyperion off|auto|on` as a versioned experiment. `off` remains the production default. `on` explicitly requests the recipe subject to resource limits and structural validity. `auto` compares raw against raw-plus-Hyperion using group/time-aware inner evaluation entirely within training. Negative, structurally invalid or inconclusive gates retain raw with an explicit reason.

Fit normalization and a fixed reference bank inside each selection fold; encode each query against that bank alone. Bind encoder weights, recipe, normalization, bank and feature-view digests into every evaluation and trained model. Refit the chosen transform on permitted full training only after selection. Required tests cover row-order invariance, batch-composition invariance, fold isolation and exact qualification/deployment transform equivalence. Count feature construction in the compute comparison and retain magnitude-sensitive raw outputs as an explicit candidate; percentile ranking discards magnitudes and is not automatically equivalent.
