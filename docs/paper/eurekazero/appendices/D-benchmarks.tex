\section{Benchmarks and verifiers}
\label{app:benchmarks}

\paragraph{Sealing} For each game, confirmation families are drawn from dependency components held
out at the time the corpus is frozen. Their identities are committed as a salted hash list before any
EurekaZero model is trained, and the salt is revealed only at unblinding. The confirmation roster
(\syn[EZ-G20]{\EZnA}, \syn[EZ-G20]{\EZnB} and \syn[EZ-G20]{\EZnC} families) is registered with the
analysis plan; families are split into development and confirmation halves within components, never
across them.

\paragraph{Verifiers} \Cref{tab:verifiers} gives each verifier. Verifiers run in a process the
proposer cannot write to, from inputs it never sees, with fixed resource limits; a timeout or crash
is a failure of the candidate only when the same verifier succeeds on the incumbent.

\paragraph{References $b(s)$} A: the training-mean predictor. B: random search at the same step.
C: the envelope block with its interfaces, which is feasible but heavy. References are fixed before
training and never tuned on confirmation families.

\paragraph{Public replication} For learning procedures we also report the confirmation protocol on
TabArena tasks \citep{erickson2025tabarena}, which are public but whose test folds the proposer never
sees, so that a reader can rerun one game without our corpus.
