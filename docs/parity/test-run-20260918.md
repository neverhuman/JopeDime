### 1b. The 30 s readiness deadline (fit-authority harness) — root cause found

22 integration tests still failed with the pins set, at any load (8 test threads, load ≈ 35–55): `fit_boundary` ×9,
`view_contracts` ×7, `gp_contracts` ×2, `service_continuous` ×2, `sealed_storage`, `queue`, plus 3
`eval_registry::authority` lib tests. The spawned `jope-parallel registry-authority` never published its socket
within `tests/support/fit_authority.rs`'s 30 s deadline and wrote nothing to stderr. Cause: `Service::bind` hashes
the running executable and the worker executable (`verified_executable`, `ProcessIdentity`) — a ~220 MB debug
binary, twice, with **unoptimised sha2** in the dev/test profile, and the test itself hashes it once more before
spawning. Fix (this PR): `[profile.dev.package.sha2] opt-level = 3` (+ `digest`) in the root manifest. Verified in
`port/timing` (`port/rerun-sha2.log`): the same 55-test set goes from 33 passed / 22 failed to **41 passed /
14 failed** — all 9 `fit_boundary` and the 3 authority lib tests pass. Release builds are unaffected.
