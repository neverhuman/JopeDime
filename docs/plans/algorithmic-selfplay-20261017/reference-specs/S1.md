# JopeDime — Algorithmic Self-Play Engineering Specification

**Version** 1.0 · **Date** 2026-10-17 · **Repository** `neverhuman/jopedime` (mirror of `veox-ai/JopeDime`) · **Pinned HEAD** `5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc` (2026-10-17)

**What this document is.** A full engineering specification for turning JopeDime's existing machinery into an evidence-qualified algorithmic self-play system — deep-learning encodings → GP programs → emitted code — that gets measurably better over time, uses S3 as a research lake with value-based retention, and compiles every research wave into compressed, AI-readable memory. It also scores the five specifications submitted for review.

**How it was produced.** The repository was cloned at the pinned HEAD and read directly: the GP language (`crates/feat-math`), every search loop, the policy models and trainers (`crates/jope-policy`, `crates/jope-engine`, `deploy/dl-*`), the learning store, S3 mirror and retention classifier (`crates/jope-learning`), the claim ledger and experiment catalog (`docs/paper`, `docs/experiments`), the ADRs and planning records. Every repository fact below carries a file and, where useful, a line or claim id; the surprising ones were re-checked by hand. Literature from 2025–2026 was checked against primary or near-primary sources. Nothing was built, trained or run against S3; numeric targets in this document are proposals to pre-register, not results.

**Evidence conventions.** `Cnn` = claim id in `docs/paper/claims.json`. `EXP-nnn` = record in `docs/experiments/experiments.jsonl`. `[Key]` = reference in Appendix A. "Verified" = read in code at the pinned HEAD. "write-up §n" = a section of `docs/paper/TECHNICAL_WRITEUP.md`; a bare "§n" is a section of this document.

## 1. Executive summary

### 1.1 The finding that changes the plan

JopeDime has trained policies, run expert-iteration studies and built more scientific-integrity machinery than most research systems. What it has never done is **measure a policy on the game it is supposed to play.**

- Every paired judgment of a fine-tuned policy made under the scratch-run ruling R22 — the anchored sweeps, scratch runs R25–R27 and the expert-iteration studies EI-0 through EI-4 (352–1,408 optimizer updates per run) — used **L6 on held-out contexts** as its endpoint. L6's dominant term is cross-entropy against *frozen historical teachers*. Expert iteration moves probability toward programs that beat those teachers, so on L6 it scores as a regression. The pattern in the results fits exactly: the more a run moved toward new GP winners (archive-CE), the worse its L6 and the larger its KL; the closer it stayed to v1, the closer its L6 delta to zero. The project's own ledger already says so: the CLOVER synthesis "rejects L6 as the success metric" (C152). The endpoint that measures the game — E2, expected best-of-8 verified `q` — is pre-registered and has never run (C102–C103).
- The **apprentice cannot represent the expert**: CLOVER PolicyLM decodes only through a trie of 6,640 catalog programs, while 40 of 51 GP champions were off-catalog (C167).
- The **expert is weak too**: across 26,357 historical search receipts, **98.84% of winners were already in the seed population**, and in lineage B's paired final searches the neural arm tied the generic arm in 3,227 of 3,268 comparisons. The shipped search uses a population of 12, parents drawn uniformly from 4 elites, one held-out fold, and a 64-evaluation default.
- The **learning signal is starved**: only the champion of each search survives into training; every one of the hundreds of measured parent→child transitions per search is discarded. AlphaZero trains on every move.
- **Evaluation is custody-bound**: ~94% of evaluation wall time is custody I/O (C86); each evaluation writes 7 objects and 4.69 MB, 4.45 MB of it a non-reproducibly rebuilt executable (C57).

None of the five reviewed specifications identifies these. All five frame the next milestone as "the first real optimizer update", which the record shows is not the bottleneck.

### 1.2 The plan in eleven decisions

1. **Fix the scoreboard first.** Discovery-AUC and exact best-of-B are the endpoints for every policy claim; L6 becomes a stability diagnostic (§6.4, §10).
2. **Build the simulator AlphaZero had for free.** A *Measured Universe* — exact `q(c,p)` for every program measured on every context, as Parquet in S3 — plus an **exact arena** that computes any policy's best-of-B in closed form, `F_π(x)^B`, on fully measured D-tune contexts. This is the NAS-Bench move: policy and search-strategy comparisons become millisecond table lookups (§6.5).
3. **Re-judge the existing checkpoints before training anything new.** All EI and R22–R27 checkpoints scored on the exact arena — an afternoon of lookups once the D-tune table exists (W-02).
4. **Strengthen the expert before training the apprentice.** Unify ~30 GP loops into one kernel with named search strategies; make the default combine lite-race's successive-halving racing, the Lambda engine's island parent policies (ε-lexicase, novelty-quality, age-layered), ring migration with novelty, stage caching and functional-equivalence dedup; add a contextual operator bandit and **Gumbel root search with measured leaves** — policy improvement guaranteed at 2–16 simulations, no learned value needed (§8).
5. **Change what the apprentice outputs.** An *edit* policy conditioned on a retrieved parent program, over an open, registry-typed grammar with exact log-probabilities — "take the nearest champion and change this" rather than "emit a program from nothing" (§9.2).
6. **Train on every move.** Log every edit transition with its sibling group and propensity; train with advantage-weighted regression using leave-one-out sibling baselines; add search distillation only from roots where search provably beat the prior (§9.4). Target: ≥ 10⁶ transitions from one campaign, against today's 52-program archive.
7. **Give the value model a problem it can learn.** A binary "child beats parent" comparator plus within-context ranking and an HL-Gauss outcome histogram, pre-trained as a prior-fitted network on unlimited **planted-program synthetic tasks** and fine-tuned on real rows. It replaces the ridge surrogate only after beating it on that surrogate's own benchmark (§9.2–9.3).
8. **Self-play without an opponent, precisely.** Win = beat the incumbent `h_c` by `τ` (Ranked Reward); opponent = the previous promoted search stack on the same context (Gumbel "Play to Plan"); league = the benchmark baselines and historical stacks with PFSP; curriculum = an adversary that plants programs and rewards regret under a solvability guard — which is also the only place invention can be *verified* (§6).
9. **Grow the language with discipline.** One `operators.toml` registry that generates every operator table (today at least 13 lists disagree); an effect-typed `ProgramGraph` layer sourced from the typed grammar that already exists but is dead code; fixes for 14 verified defects; motif promotion as DreamCoder-style language growth gated on measured search gain (§7).
10. **Make S3 a research lake that forgets intelligently.** One object per evaluation, a content-addressed executable cache, Parquet tables that keep failures, and a retention brain whose notion of value comes from the learner — influence and surprise for the current value model, plus hard evidence pins — wiring knobs that already exist but are never read (§11).
11. **Make memory compound.** A deterministic capsule compiler with a 60-token finding line per experiment: the project's entire experimental history fits in ~1,000 tokens and is loaded into every planning context; `do_not_repeat` entries are enforced at pre-registration (§12). And replace 642 KB of root narrative with a generated 2,000-token `STATE.md` (§13).

Deep-learning encodings enter at three places: the context encoder that conditions every proposal, the value model that allocates evaluations, and — licence-gated — as out-of-fold foundation-model components *inside* programs (§7.6). GP is the expert's move set. Code is the terminal state: every promoted program is emitted to Rust and Python with bound identities (#48 fixed, PR-03).

### 1.4 The first phase

PR-01…PR-08 (§14; ≈ 8 engineer-weeks in total, ≈ 5 on the critical path PR-04…PR-08 with PR-01…PR-03 in parallel) — docs diet, capsule compiler, emitter binding, transition logging, distiller fixes, lake readers, Measured Universe, exact arena — then two experiments that need no GPU and no new model: **W-02** (were the EI checkpoints actually better at the game?) and **W-04** (does retrieval from *other* lineages beat ordinary GP once own-incumbent seeds are excluded? — the premise three of the five reviewed specs (SP1, SP3, SP5) adopted without checking). Their answers decide whether the rest of the plan is pointed at the right target.

### 3.4 Defects common to all five

These six shared issues account for most of the gap between the self-scores and the scores above.

## 4. Diagnosis: why the flywheel has not turned

The five reviewed specifications converge on "close the loop: get a first real optimizer update from fresh search outcomes." The repository's own record shows that is not the bottleneck. Lineage B ran DL→GP→DL cycles on 8×A100 for a week and produced the accepted step-60000 checkpoint (ADR-0005); v1 PolicyLM trained ~17,800 updates (C25); the EI-0…EI-4 studies ran 24+ paired GPU runs with 1,056–1,408 optimizer updates each (EXP-013…017). Updates happened. What did not happen is *measured improvement at the game*. Four structural causes (Cause 2 has two halves, §4.2 and §4.2b) explain every negative result in the catalog, and each has a specific fix.

### 4.1 Cause 1 — the scoreboard measures imitation, not play

Every paired policy judgment since R22 used **L6** on held-out contexts as its endpoint (EXP-006, -007, -013…-017; write-up §9.7, §10.3). L6 is a weighted sum of six terms whose dominant term (weight 1.00) is sequence cross-entropy against **frozen teachers** — the historical high-water-mark programs (write-up §4.1, §2.5). Expert iteration, by design, moves probability mass *toward* programs the search found that beat the teachers. On an imitation-of-old-teachers metric, that movement is scored as a regression even when it is exactly the desired behaviour.

The evidence fits this reading closely:

- Archive-CE (training on GP winners outside the catalog) produces the *largest* L6 increases (EI-1 +0.0043, EI-3 +0.0040) and the largest KL departures from v1 (KL stop at 0.08) — it moves the policy furthest from the teachers.
- The 885 held-out-lineage contexts — where the old teachers are, by construction, the reference — carry the largest L6 increases (C177: +0.0063, +0.0042, +0.0046), while the 263 validation contexts are inconclusive.
- Lowering `λ_ar` or raising `λ_KL` (keeping the policy closer to v1) monotonically shrinks the L6 penalty toward zero (EI-2 +0.0004, EI-4 +0.0001) — the metric rewards *not moving*.

None of these runs measured whether the fine-tuned policy *proposes programs that score higher `q` when executed*. The write-up defines exactly that endpoint — E2, "expected best-of-8 verified `q`" (write-up §9.3) — and the exact best-of-B formula (write-up §9.4); E2 is pre-registered but has never run (C102–C103 pending), and the exact ceiling audit is pending (C116).

**Fix.** Make discovery-AUC and `J_B` (§6.4–6.5) the endpoints for every policy claim; demote L6 to a stability diagnostic. Re-judge the existing EI-0…EI-4 checkpoints on the exact arena *before* any new training — they are already on disk, and it costs table lookups (wave W-02, §15). It is entirely possible some "regressions" are improvements at the game; it is also possible they are not. Either answer is worth more than another L6 sweep.

### 4.2 Cause 2 — the apprentice cannot express what the expert finds

CLOVER PolicyLM decodes through a prefix tree of a fixed **6,640-program catalog** (write-up §3.3, C05). It is a context-conditional *selector* over 6,640 strings, not a generator. Meanwhile GP champions are 40/51 off-catalog (EXP-008, C167). Expert iteration requires the apprentice to be able to represent the expert's improved policy; with a closed catalog it cannot, so the only route to new support is appending strings to the vocabulary (the "N+1 extended support" of the archive-CE studies), which is why a 52-program archive could destabilise a 894K-parameter model.

The serving policy (`crates/jope-policy`, width 512, vocab 401, `ACCEPTED_STEP` step-60000) has a grammar-automaton decoder (`crates/jope-policy/src/grammar.rs`, `decode/`), but its context producer requires the foundation and target encoders (`crates/jope-policy/src/context_producer.rs:62`, recipe `"…foundation-pcg20260707…;target-pcg17…"`), which the learning lanes refuse at load time (README "Intended pipeline"; `deploy/dl-flywheel/docs/encoder-mask-plan.md:59`). So the policy that *can* generate open programs cannot be retrained under current rules, and the policy that *can* be retrained cannot generate.

**Fix.** One policy family, open grammar-constrained decoding (exact log-probabilities from the automaton, the same property the trie gives today), and — the decisive change — an **edit** action space conditioned on a retrieved parent (§9.2), so the apprentice expresses "take the nearest-neighbour champion and change this" rather than "emit a whole program from nothing."

### 4.2b Cause 2b — the expert is weak too: search mostly re-finds its seeds

Expert iteration needs an expert that reliably beats the apprentice. The record says the current expert rarely moves far from where it starts:

- In lineage B's paired final searches (arms sharing their seed pools) the neural arm **tied the generic arm exactly in 3,227 of 3,268 comparisons**, and across all **26,357 historical search receipts, 98.84% of reported winners were already in their search's seed population** (`docs/internal/asm-manual/sections/status.md`, "Where the current evidence stands").
- In the H1 pilot, ordinary GP under 200 fits / 180 s per cut beat the re-measured incumbent in only **8 of 17** contexts, with a median log loss ratio of **+0.0011** against it (i.e., slightly worse); `gp-h1-readout.20261013.json`, `arms[0]`.
- On the same-cut ladder the searched program ranks 3rd behind `baseline.gpr` and the RF adapter, and did not reach the top-5 screen on 5 of 10 datasets.

So the search is currently a good *re-measurer* and a modest *improver*. That bounds what any policy trained on its output can learn. §8 therefore treats search improvement (operators, credit, diversity, root search) as a first-class workstream, not as plumbing for the policy.

**A provenance ambiguity that must be resolved before it is used as a premise.** The H1 pilot's third arm is described as "training-only retrieval seeds" whose "ancestry must refer to a context in the same frozen train roster" (`docs/internal/clover/GP_EXPANSION_STUDY.md:78,103`), but as "seeded from the context's own HWM" in `deploy/dl-flywheel/docs/model.md:340`; the readout does not record seed ancestry. If the arm was own-HWM seeding, "retrieval beats ordinary 16/1/0" means only that *starting from the best known program beats starting without it*, and "policy vs retrieval 2/0/15" is not evidence that nearest-neighbour retrieval beats the policy. Three of the five reviewed specs (SP1, SP3, SP5; and an earlier draft of this one) treat "retrieval is the hurdle" as established. It is not, until the arm is re-run with own-parent-lineage seeds explicitly excluded and seed ancestry recorded (wave W-04, §15). The gen-0 mixture in §8.2 therefore separates `own_incumbent` and `knn_retrieval` (neighbours from *other* parent lineages) as distinct, separately credited sources.

### 4.3 Cause 3 — the learning signal is starved; the firehose is discarded

- Measured support is sparse: of 263 validation contexts, only **99** carry the multi-program measurements behind the `q`, ranking and runtime terms (write-up §8, C18).
- L6's imitation term uses *only* frozen teachers; "verified programs written by the model never replace a teacher, and in this work they never become imitation targets" (write-up §2.5, §4.2; C127).
- The archive used for archive-CE was **42 contexts / 52 programs** (EXP-017 next-implications).
- The v1 `q`-head never learned (`L_q` 0.1804 → 0.1809 over 40 epochs, C28) and ranks fresh programs at chance (0.506 [0.441, 0.568], C76), while LightGBM on raw features beats a separate DL outcome predictor (R² 0.785 vs 0.690, C178) and a 93-feature ridge surrogate learns to select (EXP-018).

Meanwhile every GP run produces hundreds to thousands of **(parent, edit, child, Δq)** transitions — each mutation and crossover is a labelled, counterfactually clean training example of the exact decision the apprentice should learn ("from this program on this dataset, which edit helps?"). Today only the champion survives into the teaching corpus; the transitions are discarded or buried in per-run `observations.json`. AlphaZero trains on *every move of every game*, not only on game winners. JopeDime trains on winners only.

**Fix.** Log every edit transition (§8.6 sibling design, §11.3 `edit_transitions` table) and train the edit policy and value head on them (§9.3). Back-of-envelope: a 32-population × 8-generation search (the same-cut setting) measures ~256 programs per cut, each with a recorded parent and operator. Run over the 2,611 real regression datasets with 2 cuts each, one campaign yields ~1.3M labelled transitions — four orders of magnitude more policy-relevant labels than the 52-program archive. W-06 pre-registers ≥ 256 evaluations per cut for `modern_gp_v1`, so the same ≥ 1.3M figure holds for the configuration that will actually run. (The existing S3 `GP_RESULTS_INDEX.json` is *not* such a source: its 8,908 scored rows (of 18,380 runs) cover only 13 program hashes — `docs/experiments/README.md`, EXP-018 card.)

### 4.4 Cause 4 — evaluation is bottlenecked by custody, not compute

Each evaluation writes ~4.69 MB in 7 objects, of which 4.45 MB is a compiled executable rebuilt non-reproducibly every time; the score row is ~100 bytes (C57). About **94% of evaluation wall time is custody I/O** (C86). At the write-up's 2,000 evals/h projection, request charges alone ($54/month) exceed the $25/month storage target, and a 1 TB hot tier fills in 4.4 days (C59, C61). The same-cut search takes 2.2 s mean per dataset (README) when run in-process — the evaluator is fast; the protocol around it is not.

Every learning method in this spec is sample-hungry. A 10× custody reduction is worth more than any model change.

**Fix.** One object per evaluation (packed member index), a content-addressed executable cache keyed by `(emitter_version, program_id, toolchain)` with reproducible builds, custody batched per wave rather than per evaluation, and in-process fitting for search evaluations at low fidelity levels with full custody only for keepers (§11.2).

### 4.5 What is *not* the bottleneck

- **Governance and integrity.** Pre-registration (`SelfPlayPrereg`), parent-cluster bootstrap (`pools::bootstrap::cluster_bootstrap_ci`), Holm correction, create-only receipts, manifest-last mirror with ancestor-checked pointers (`crates/jope-learning/src/mirror.rs`, `sync.rs`), Landlock + two-stage seccomp evaluator confinement (#320, #322), a claim ledger with numeric drift checks (`jope-records paper-trace`), a dry-run retention classifier (`jope_retention`), restart-only and offline-replay controls (#327), a KL guard with exact decomposed support KL. This machinery is more mature than most published research systems. The reviewed specs spend most of their P0 budget re-proposing it. This spec reuses it and spends the budget on the game.
- **Model size.** The neural proposer has not beaten seeded search (lineage B ties; H1 pilot), the order-aware CLOVER `q`-head (it reads `h_EOS`, so pooling is not the cause) is at chance, and a ridge model beats it as a selector. Scaling the transformer before fixing causes 1–3 would scale the wrong thing.
- **MCTS.** Deep tree search is only as good as its value function, and the value function is at chance. Gumbel root search with *measured* leaves (§8.5) is the right first planner precisely because it needs no learned value at the root.

## 5. Self-play and search-based learning, decoded for this problem

This section explains the relevant systems at the level of mechanism, then states what transfers to JopeDime and what does not. Citation keys refer to Appendix A. Items published in 2025–2026 were checked against primary or near-primary sources; vendor-reported benchmark numbers are flagged as such.

### 5.1 The AlphaZero family

**AlphaGo Zero [Silver17] / AlphaZero [Silver18].** One network `f_θ(s) → (p, v)` outputs a move prior `p` and a value `v`. At each move MCTS runs 800 (AlphaZero) to 1,600 (AlphaGo Zero) simulations; each descends the tree by PUCT,

```
a* = argmax_a  Q(s,a) + c_puct · P(s,a) · √N(s) / (1 + N(s,a)),
```

expands one leaf, evaluates it with `f_θ` (no rollouts) and backs `v` up. Root visit counts `π ∝ N(s,·)^{1/T}` are a *better* policy than `p` — search is a policy-improvement operator. Training minimises `(z − v)² − πᵀ log p + c‖θ‖²` with `z` the game result. AlphaGo Zero gated new networks at a 55% win rate; AlphaZero always used the latest.

*Why it works*: (i) search with a learned prior and value is strictly stronger than the prior alone, so there is always a better teacher; (ii) every position of every game is a training example; (iii) self-play supplies an opponent of exactly matched strength; (iv) the simulator is free and exact.

**MuZero [Schrittwieser20]** learns dynamics `g(s,a) → (r, s')` and plans in latent space, trained on *value equivalence* — predicting only what planning needs. Its **Reanalyse** variant recomputes targets on stored trajectories with the latest network. JopeDime does not need learned dynamics (`apply_edit` is exact); it does need Reanalyse: every stored edit transition should be re-scored by the current value model each round.

**Gumbel AlphaZero / MuZero [Danihelka22].** Sample `k` root actions without replacement by Gumbel-top-k on `log p + g`, allocate simulations by **sequential halving** using `g + log p + σ(q̂)`, and train toward `softmax(log p + σ(completed Q))`. It **guarantees policy improvement even with very few simulations** (n = 2–16) where PUCT fails. This is JopeDime's regime: each simulation is a real evaluation, so it is the search paper this spec leans on hardest (§8.5).

**EfficientZero / V2 [Ye21, Wang24]**: sample efficiency from self-supervised consistency losses and off-policy target correction for stale data. **Sampled MuZero [Hubert21]**: plan over a sampled action subset and correct the target for the sampling distribution (`β̂/β`) — required when edits have continuous parameters, or the policy collapses toward its own proposals. **Stochastic MuZero [Antonoglou22]**: treat chance (fold assignment, seeds, subsampling) explicitly; never let one lucky fold promote a program.

**Expert Iteration [Anthony17].** The pattern under AlphaZero: an *apprentice* guides an *expert* search; the expert's improved decisions train the apprentice. **Any search that reliably beats the apprentice can be the expert.** In JopeDime today the strongest expert is incumbent/retrieval-seeded GP (EXP-008), and it is itself weak — 98.84% of historical winners were already seeds (§4.2b). ExIt cannot outrun its expert, so strengthening the expert comes first.

**Single-player self-play.** Two results make "self-play" precise for a game with no opponent. **Ranked Reward [Laterre18]** gives +1 when an episode beats the α-percentile of the agent's own recent scores, −1 otherwise — a stationary, scale-free reward for single-player optimisation. **Gumbel AlphaZero "Play to Plan" [Pirnay23]** makes the opponent a greedy rollout of the agent's *historical* policy: the agent wins an episode if it beats its past self on that instance. Both map directly onto Game P: the win condition "beat `h_c` by τ" is a Ranked-Reward threshold, and "beat the previous promoted stack on this context" is Play-to-Plan.

**AlphaD3M [Drori18/21]** — AlphaZero-style MCTS with a sequence-model policy over grammar-constrained ML pipeline edits — is the closest prior art to JopeDime's game. Its lesson: a pipeline grammar shrinks the search space enough for MCTS to be useful; JopeDime's typed registry plays the same role.

### 5.2 Program and algorithm discovery

**AlphaTensor [Fawzi22]**: single-player TensorGame; synthetic demonstrations generated *backwards* by sampling random factorisations — the template for planted-program tasks (§6.7). **AlphaDev [Mankowitz23]**: single-player AssemblyGame with reward = correctness + *measured* latency (proxies and measured latency diverged); found sort3/4/5 routines merged into LLVM libc++. Lessons: single-player discovery works when the reward is exact; make cross-language correctness a gate and measured per-target latency a reward term.

**FunSearch [RomeraParedes24]**: an LLM evolves one function inside a fixed skeleton; prompts show the best two programs; an **island database** clusters programs by score signature and periodically resets weak islands; shorter programs preferred. **AlphaEvolve [Novikov25]**: diff-based edits to whole files by an LLM ensemble; MAP-Elites + islands; an **evaluation cascade** of increasing cost; asynchronous evaluation; auxiliary metrics improve the target metric. Reported: 4×4 complex matrix multiplication in 48 multiplications, ~0.7% fleet compute recovered, 23% kernel speedup. The follow-up **[Georgiev25]** (Tao et al., 67 problems) found *evaluator design dominates outcomes*, continuous scores beat discrete, and **the system exploits leaky verifiers**. Open reimplementations add cheap wins: **ShinkaEvolve [Lange26]** (power-law parent sampling, novelty rejection sampling at cosine > 0.95, a UCB bandit over proposers rewarded by improvement over parent) and **CodeEvolve [Assumpcao25]** (MAP-Elites per island).

**Evolution with a *trained* proposer — JopeDime's exact loop.** **EvoTune [Surina25]** alternates FunSearch-style search with DPO fine-tuning on (better, worse) program pairs and finds RL shrinks diversity; it counters with forward-KL DPO at high β (0.4), training on elites from all phases, **restarting fine-tuning from the base model each round**, and monitoring the number of unique scores as an overfitting signal. **ThetaEvolve [Wang26]** trains inside a 10k-program evolving database with GRPO (asymmetric clipping), fixed "lazy penalties" for failed and duplicate proposals, and scores mapped to [0,1] and sharpened near the best known value; RL *within* the evolving database beat RL from a static start. **TTT-Discover [Yuksekgonul26]** scores parents by their *best* child (not the mean) and uses an entropic objective that up-weights the highest-reward attempts; best-of-N at equal budget is a strong baseline that must be reported. **Neural-guided GP seeding [Mundhenk21]** — an RNN seeds the GP population each iteration, GP refines, the best samples train the RNN — is JopeDime's flywheel in miniature and beat either component alone. **DSR [Petersen21]** uses risk-seeking policy gradient (optimise the top-ε quantile).

**Guided Evolution with binary discriminators [CoReyes24]**: a GNN over program DAGs predicts "is the child better than its parent?" and filters mutations before evaluation, for a 3.7–4× speedup — and **binary comparators beat regression predictors**. This is direct evidence for the design choice in §9.2: JopeDime's regression `q`-head is at chance, while pairwise/within-context methods (EXP-018) learn.

**DreamCoder [Ellis21]**: wake (solve with neural-guided search), abstraction sleep (compress recurring sub-programs into typed primitives by MDL), dream sleep (train the recognition model on replays and fantasies). The blueprint for `jope-motifs` promotion (§7.7). **AutoML-Zero [Real20]**: aging evolution over Setup/Predict/Learn programs; **functional-equivalence checking** by hashing outputs on fixed probe data, and cheap hurdles — "the cheapest and most effective dedupe and cache you can build." **Lion [Chen23]**: optimizer discovery by program search with funnel selection and post-hoc simplification. **Darwin Gödel Machine [Zhang25]** keeps an *archive* of self-modifying agents, not a single champion.

**Symbolic regression** [LaCava21, Cranmer23]: no single method dominates; the best methods fit continuous constants with gradient/BFGS inside the search rather than by mutation, and report accuracy on a complexity Pareto front.

### 5.3 Populations, leagues and open-endedness

**PSRO [Lanctot17]** keeps a policy population, solves a meta-game over it and adds best responses. **AlphaStar's league [Vinyals19]** adds main agents, main exploiters and league exploiters with **prioritised fictitious self-play** (PFSP) that samples opponents one loses to. **PBT [Jaderberg17]** co-optimises weights and hyperparameters by exploit/explore — directly usable for search-stack hyperparameters against the exact arena.

**MAP-Elites [Mouret15]** keeps the best solution per behaviour-descriptor cell; **novelty search [Lehman11]** selects on behavioural novelty (behaviour = predictions on probe rows); **ε-lexicase [LaCava16]** filters parents on randomly ordered cases with an ε tolerance (MAD), preserving specialists — treat folds, row slices or residual clusters as cases; **ALPS [Hornby06]** protects young lineages in age layers.

**POET [Wang19]** co-evolves environments and agents with a minimal-criterion filter; **PAIRED [Dennis20]** trains an environment adversary to maximise regret; **ACCEL [ParkerHolder22]** edits high-regret levels; **asymmetric self-play [Sukhbaatar18]** has one agent set tasks for another. **OMNI [Zhang24]** prioritises *interesting* learnable tasks. **[Hughes24]** defines open-endedness as continual novelty *and* learnability to an observer — a usable acceptance test for "invention" (§10.5).

### 5.4 RL training methods for a generative policy whose samples are expensive

| Method | Mechanism | Fit for JopeDime |
|---|---|---|
| REINFORCE | `∇log π(a)·(R − b)` | Too high-variance alone |
| **RLOO** [Ahmadian24, Kool19] | baseline = mean reward of the other `k−1` samples; unbiased, no critic | Natural for "k children of one parent"; verified offline in `deploy/dl-flywheel/pipelines/rlfw/onpolicy/objective.py` |
| **GRPO** [Shao24] + **DAPO** [Yu25] + **Dr. GRPO** [Liu25] | group-normalised advantage + KL; DAPO adds asymmetric "clip-higher", drops zero-variance groups; Dr. GRPO removes std normalisation (it inflates fold noise on nearly-solved contexts) | Use group baselines *without* std normalisation; drop groups whose children all tie (a §9.4 challenger) |
| PPO [Schulman17] | clipped ratio + critic | Overkill; a program critic is the hard part |
| **AWR** [Peng19] | regression weighted by `exp(A/β)` on logged data | Default trainer: stable, off-policy, uses every logged transition |
| DPO / IPO [Rafailov23] | closed-form preference objective | Measured sibling pairs are free preference data; forward-KL, high-β variant per EvoTune |
| ReST / ReST-EM / STaR [Gulcehre23, Singh24, Zelikman22] | sample → filter by rising threshold → fine-tune (ReST-EM restarts from base) | The simplest expert-iteration baseline; reported as a control arm in W-11 |
| **PKPO** [Walder25] | unbiased pass@k gradients for continuous rewards | The flywheel's objective is max-of-K (search keeps the best child); mean-reward training collapses the proposer toward safe programs |
| V-trace [Espeholt18] | truncated importance weights for actor lag | Needed once proposals come from stale checkpoints at scale |

**The coverage warning.** [Yue25] shows RL fine-tuning mainly sharpens pass@1 while base models overtake RL-trained models at large k — RL *narrows coverage*. For a proposer whose output is consumed best-of-B by a search, narrowing coverage is exactly the wrong outcome. Hence: max-of-K objectives (PKPO), entropy floors, KL anchors, replay of all-time elites, and EvoTune's restart-from-base.

### 5.5 Optimisers, losses and schedules

**AdamW [Loshchilov19]** stays the default for embeddings, norms, biases and heads. **Muon [Jordan24, Liu25b]** (Newton–Schulz-orthogonalised momentum on 2-D hidden matrices) needed ~52% of AdamW's FLOPs in LLM pre-training and was used to pre-train TabICLv2; here it is a later ablation for the policy trunk (§9.5), not a default. **Schedule-Free AdamW [Defazio24]** won the AlgoPerf self-tuning track [Kasimbeg25]; **WSD [Hägele24, Hu24]** matches cosine while allowing a deployable cooldown branch at any time. A never-finishing flywheel fits these; it fits a plateau controller with a floor badly — v1 sat at 1e-6 for 12,096 of 17,773 updates (C25).

**Distributional value losses**: C51 [Bellemare17], QR-DQN quantile Huber [Dabney18], and **HL-Gauss** (cross-entropy against a Gaussian-smoothed histogram) [Farebrother24], which scales better than MSE — mirroring TabPFN's bar distribution and TabICLv2's 999-quantile pinball head. **Ranking losses**: Bradley–Terry/RankNet [Burges05], ListNet [Cao07], ListMLE [Xia08] — scores are comparable only *within* a context, so rank within groups. **Censored losses** for timeouts [Hutter11, Eggensperger18]: a timeout is a right-censored observation, not a value.

### 5.6 Tabular foundation models — opponents and components

TabPFN v2 [Hollmann25] (Nature 2025) learns in-context prediction from synthetic structural-causal-model priors; TabPFN-2.5/3/3.5 [PriorLabs25/26] scale to 50k–1M rows; **TabICLv2 [Qu26]** (column-wise set transformer with induced points → row attention → dataset-level in-context transformer, permissive licence) and **Mitra-v2 [Tao26]** (Apache-2.0) are the strongest *openly licensed* options; TabArena [Erickson25] has only **13 regression datasets**, and all September 2026 vendor Elo claims (TabPFN-3.5, LimiX-2, TabFM, EXAONE) are unreproduced and from different snapshots. On this repository's Golden45 ladder, TabFM Ensemble (1934.9) and TabPFN v3 (1909.5) lead, with TabICL fifth (1887.6); the reproducible JopeDime regressor is 1687.0 (rank 31, 42/45 coverage).

Three lessons: (1) **prior-fitted networks trained on synthetic tasks are how to learn a strong predictor when real labelled tasks are scarce** — §9.3 applies this to *program-outcome* prediction; (2) open-licence FMs are both league opponents and candidate program components (an out-of-fold FM prediction as a feature or residual base, §7.6), while TabPFN-2.5's distillation into an MLP/tree head is the template for keeping emitted code small; (3) the AutoGluon lesson [Erickson20] — diverse stacked ensembles beat single tuned models — still holds, so the language must express OOF stacking well.

## 6. The JopeDime game, defined precisely

### 6.1 Why "AlphaZero for programs" needs a different board

AlphaGo Zero's loop works because four things are true: (1) a perfect, free simulator (the rules of Go); (2) a terminal reward that is exact and unambiguous (win/loss); (3) an opponent that improves exactly as fast as you do (yourself), giving an automatic curriculum; (4) a search (MCTS) that, given the current network, reliably produces a *better* move distribution than the network alone, so the network always has a stronger teacher to imitate.

JopeDime has none of the four for free:

| AlphaZero property | JopeDime today | What replaces it in this spec |
|---|---|---|
| Free perfect simulator | Each evaluation costs seconds to minutes, 94% of it custody I/O (C86) | **The Measured Universe** (§6.5): a growing, content-addressed table of exact `q(c,p)` that *is* a perfect simulator on its support, plus a calibrated surrogate off it |
| Exact terminal reward | `q` is noisy (2 inner folds), heavy-tailed, censored at 90 s | `q` from eq. 3 of the write-up (already scale-free and robust), with fold variance carried as uncertainty; ties on `q_grid` |
| Self-opponent curriculum | No opponent; datasets are fixed | **Three opponents**: the incumbent high-water mark `h_c`, the previous promoted search stack (Play-to-Plan), and a frozen baseline league (GPR, stack, ensemble, XGBoost, LightGBM, CatBoost, RF — already run by `jope-bench`); plus an adversarial *task* generator (§6.7) |
| Search reliably improves on the prior | It mostly does not: 98.84% of historical winners were already seeds; ordinary GP beat the incumbent in 8/17 H1 contexts (§4.2b). Incumbent/retrieval-seeded GP beats policy-seeded GP 15/2 (EXP-008), with the seed-provenance caveat of §4.2b | A stronger expert first (§8: operators, credit, diversity, Gumbel root with measured leaves), then Expert Iteration with an **edit policy** as apprentice (§9) |

The closest published analogues are therefore not board games but single-player discovery games: **AlphaDev** (assembly programs; reward = correctness + latency; single player; huge action space) and **AlphaTensor** (TensorGame; single player; reward = −rank), both trained with AlphaZero-style search + policy/value networks, and **FunSearch / AlphaEvolve** (an evolutionary program database with islands, where a learned proposer mutates the best programs and an automatic evaluator scores them). JopeDime's game sits between them: AlphaDev's exact-evaluator discipline, FunSearch's evolutionary database, and a learned proposer that must eventually be cheap enough to run thousands of times per dataset.

### 6.2 The four games

The system plays four nested games. Each has its own state, actions, reward and learner. Conflating them is the root cause of the measurement confusion in §4.

**Game P — Program construction (inner, per dataset).** The agent edits a typed program until it stops.

- *State* `s = (c, p, H_c, b)`: context `c` (dataset version, cut, inner folds, frozen embedding `z_c`), current program `p` (canonical typed IR), the observation history `H_c` of every program measured on `c` so far (program id, `q`, fold residuals, runtime, failure class), remaining budget vector `b`.
- *Actions*: typed edits from the edit ABI (§7.5): `Insert, Delete, Replace, Wrap, MutateParam, Splice(donor), Retrieve(k), Simplify, Stop`. Illegal edits are masked by the operator registry before the policy normalizes.
- *Transition*: deterministic (`apply_edit` is pure). The *observation* of `q` is stochastic and asynchronous.
- *Reward*: terminal, `R_P = max(q_best − h_c, 0)` relative to the incumbent, where `q_best` is the best **verified** `q` in the episode. Intermediate rewards are zero — no shaping that the policy can exploit.
- *Win condition*: `q_best > h_c + τ`, with `τ = 0.01` (the tie threshold already pinned in C71). Draw within `±τ`. Loss otherwise.

**Game A — Evaluation allocation (inner, per dataset).** Given a candidate pool and budget, choose which candidate to evaluate next and at what fidelity.

- *State*: pool of candidates with surrogate posteriors `(μ, σ, p_fail, ĉost)`, history, budget.
- *Actions*: `Evaluate(candidate, fidelity ∈ {static, smoke, fold1, fold2, full_inner})`, `Stop`.
- *Reward*: the same terminal `R_P`, minus nothing — cost enters through the budget constraint, not the reward, so arms are always compared at equal budget.
- This is exactly the game EXP-018's `ContextualSurrogateQHat` already plays on frozen shadow pools of 9–51 candidates per context. It is the cheapest game to win and the one with positive evidence; it ships first, wrapped as the kernel's default `Allocator` in PR-13.

**Game T — Task curriculum (outer).** An adversary chooses *training* contexts (real or synthetic) to maximise the learner's regret, subject to solvability.

- *State*: league table, per-family win rates, coverage of the Measured Universe.
- *Actions*: sample a real training context (by family weight) or generate a synthetic planted-program task (§6.7).
- *Reward to the adversary*: learner's regret on that task, gated by a solvability check (a known program achieves `q*`). This is PAIRED's regret objective with the "antagonist" replaced by the planted solution.

**Game L — League (outermost).** Search *policies* compete. A policy is a full stack (proposer checkpoint + allocator + GP settings). A match is a paired run on the same contexts and budget; the payoff is the paired difference in discovery-AUC (§6.4). Elo is descriptive; promotion uses paired, cluster-bootstrapped intervals (the F10 machinery of ADR-0005 already does this for regression and is reused unchanged).

### 6.3 The reward is already right — use it everywhere

The repository's executed-outcome score (write-up §2.3, eq. 3) is an unusually good reward for this game and should be the single scalar the search optimises and the policy is judged on:

```
q(c,p) = −½ Σ_{j=1,2} log( max(r_j, ε_c) / max(b_j, ε_c) )
```

where `r_j` is the program's RMSE on inner fold `j`, `b_j` the complementary-fold mean predictor's RMSE, and `ε_c` a robust scale floor (eq. 2). It is scale-free (comparable across datasets), symmetric in improvement ratio, bounded after clipping (`q_opt ∈ [−log 1000, log 1000]`), has a defined tie grid (`q_grid = round_half_even(10⁶ q)`), and leaves unknowns masked rather than zero. Two extensions:

1. **Fold-uncertainty.** Carry `σ_q = ½|log(r_1/b_1) − log(r_2/b_2)|` (the standard error of the two-fold mean, n−1 convention) with every `q`. The search's acquisition and the judge's paired tests use it; the policy's value head predicts it.
2. **Cost-aware variant for Game A only.** `q − λ_c · log(1 + cpu_seconds)`, with `λ_c` pre-registered per campaign and `0` in Game P's win condition. Storage always keeps raw `q`, `r_j`, `b_j`, runtime and failure class; scalarisations are views.

### 6.4 The discovery endpoint: what "the policy got better" means

The policy-improvement claim must be stated in the currency of Game P, not in the training loss. Define, for a search stack `S` (policy + allocator + GP) on context `c` at budget `B`:

- `BSF_S(c, t)` = best verified `q` found by stack `S` after spending `t` units of budget (best-so-far curve).
- **Discovery-AUC** `D_S(c, B) = (1/B) ∫₀ᴮ [BSF_S(c,t) − h_c]₊ dt` — rewards finding good programs *early*, which is what a better proposer buys.
- **Final gain** `G_S(c,B) = [BSF_S(c,B) − h_c]₊`.
- **Win rate** `W_S = P(BSF_S(c,B) > h_c + τ)`.

Primary endpoint for every H3/H4 claim: mean over contexts of the paired difference `D_challenger − D_parent`, parent-cluster bootstrap 95% CI, at equal budget. Secondary: `G`, `W`, and `J_B` below. L6 is retained as a *training diagnostic and stability guard only* — consistent with the repository's own ruling that the CLOVER synthesis "rejects L6 as the success metric" (C152), which every paired judge since R22 nevertheless used as its endpoint.

### 6.5 The Measured Universe: building the simulator AlphaZero had for free

The write-up already contains the key equation and lists it as pending (write-up §9.4, C116): on a context where every program in a support set `A` has been measured,

```
P[ max_{b≤B} q_b ≤ x ] = F_π(x)^B,   F_π(x) = Σ_{p∈A: q_p ≤ x} π(p|c)
```

so the expected best-of-B, `J_B(π) = E_c E[max(h_c, q_1..q_B) − h_c]`, is **exact and free** for any policy `π` restricted to `A` — no sampling, no evaluation, no noise beyond the table's own fold noise. This is the NAS-Bench-101 idea [Ying19] applied to program synthesis: exhaustively measure a search space once, and every subsequent algorithm comparison on it becomes a millisecond table lookup.

**Specification.**

- `M[c, p] → (q, σ_q, r_1, r_2, runtime, failure_class, parity_flag, evaluator_id)` stored as partitioned Parquet in S3 (§11.3), keyed by `(context_id, program_id, evaluator_id)`.
- **Seed it** with: (a) the full 6,640-program catalog on the 26 D-tune contexts (~172K evaluations, ≈ 86 h at the 2,000 evals/h design rate, less after the custody fix in §11.2); (b) every program already in `GP_RESULTS_INDEX.json` (8,908 scored rows) and the lineage-B winners (11,903) where their evaluator identity matches; (c) all 1-edit neighbours of the top-20 programs per D-tune context (bounded by the registry's legal-edit fan-out, typically 10²–10³ per program). Staging: (a) is W-01/PR-07; (b) is backfilled by PR-05/PR-06; (c) needs `legal_edits` (PR-19) and runs afterwards as a W-01 top-up.
- **Exact arena.** `jope research arena --exact --contexts dtune` computes `J_1, J_8, J_32`, `W`, and simulated discovery-AUC for any checkpoint whose support lies in `A`, in seconds, deterministically. This replaces L6 as the *fast development endpoint* for every policy change. D-confirm keeps its one-look rule and is never readable from `M`.
- **Simulated search.** Any search strategy (GP variants, Gumbel root search, bandit allocators) can be run against `M` as a black box that returns exact `q` for in-table programs and a surrogate prediction flagged `simulated=true` otherwise. Strategy research (operator rates, island sizes, mixture weights) runs 10³–10⁴× faster than live search; only finalists are re-run live. Results produced against `M` are labelled `ARENA_EXACT` or `ARENA_SIMULATED` in capsules and can never be promotion evidence on their own.
- **Growth rule.** Every live evaluation anywhere in the system appends a row to `lake/v1/outcomes` (it already writes a score row; this makes the row queryable). `M` is the **role-filtered view** of that table, `role ∈ {train, dtune, validation, synthetic}`: `dconfirm` and `sealed` rows are written but are unreadable by the arena, the samplers and the retrieval index (§11.3 readers). Coverage of the policy's support, `Σ_{p∈A} π(p|c)`, is reported for every arena result; a result with coverage < 0.95 is `ARENA_PARTIAL`.

This is the single highest-leverage infrastructure item in the spec. It converts the project's most expensive resource (verified evaluations — 63,108 Golden42 candidate evaluations and 11,903 lineage-B cut champions alone — already paid for) into a reusable simulator, and it makes "did the new checkpoint get better at the game?" a question answerable in seconds instead of a multi-day study.

### 6.6 Opponents and the league

The league has three kinds of members, all frozen and content-addressed:

1. **Baseline engines** — the same-cut ladder's fixed methods (`baseline.gpr`, `.stack`, `.ensemble`, `.krr`, `.ridge`, `.histgbm`, and the XGBoost/LightGBM/CatBoost/RF adapters). These are the "opponents" a program must beat on a context. Today `baseline.gpr` ranks first on the same-cut deep ladder (Elo 1711.6) and the search ranks third (1556.6). A context where a baseline beats every searched program is a *loss*, and losses drive the curriculum (§6.7).
2. **Historical search stacks** — every promoted checkpoint+allocator pair, plus the frozen v1 PolicyLM and the step-60000 serving policy. They prevent forgetting: a challenger must not lose to any historical member on any family by more than the pre-registered non-inferiority margin.
3. **Specialists** — stacks admitted for niche coverage (e.g., best on tiny-n, wide, or periodic families) even when not best overall. They contribute proposals through the gen-0 mixture without becoming the main policy.

Matchmaking uses prioritized fictitious self-play (AlphaStar's PFSP): sample opponents in proportion to `f(P[challenger loses])`, so training time is spent where the challenger is weak. With fewer than five members this degenerates to round-robin, which is fine; PSRO-style meta-strategies are deferred until ≥ 5 members and a demonstrated non-transitive payoff cycle.

### 6.7 The task adversary: planted-program self-play

Real regression datasets are finite (2,611 regression datasets in the real tier; 3,859 total). The policy needs more distinct games than that, and it needs games whose optimum is *known* so that regret is exact. Both are solved by **planted-program tasks**, an asymmetric self-play scheme ([Sukhbaatar18]: Alice sets tasks, Bob solves them):

1. **Alice** (the task generator) samples a program `p*` from the grammar — biased toward motifs the current champion population under-uses — samples a feature distribution (Gaussian copula with random marginals, missingness, categorical columns, correlated blocks), generates `X`, sets `y = p*(X) + noise` with a sampled signal-to-noise ratio.
2. **Bob** (the search stack) plays Game P on `(X, y)` with the standard budget.
3. **Exact regret**: `q(p*) − BSF_Bob(B)`, both measured by the same evaluator. Alice is rewarded for regret, but only on tasks where `p*` itself clears `q(p*) > q(baseline.ridge) + 0.1` (solvable, non-trivial) — the PAIRED/ACCEL guard against unsolvable or degenerate tasks.
4. Bob's trajectories on planted tasks enter the replay buffer exactly like real ones, tagged `role=synthetic`. They never enter any held-out evaluation.

Why this matters beyond data volume: planted tasks are the only place where the system can *verify invention*. If Bob recovers a program equivalent (on probes) to a `p*` whose structure appears nowhere in the catalog or the archive, the system has demonstrably invented — and the capsule can say so with a fact, not an inference. The repository already ships 40 synthetic fixtures (10 per task kind) from one generator module, `jope generate-fixtures` (`crates/jope-cli/src/generator/`); Alice extends that generator with a grammar-sampled target.

**Sim-to-real guard**: synthetic win rates are reported but never qualify anything. Every curriculum change must show, on real D-tune contexts in the exact arena, no loss of `J_8` beyond the non-inferiority margin.

## 7. The GP language: what it is, where it breaks, what to add

### 7.1 What the language is (verified at HEAD)

**Surface syntax.** S-expressions tokenised in `crates/feat-math/src/dsl.rs:212-272`. A pipeline is `(pipe X <stage>+)`; a stage is `(<op> key=value*)` with untyped parameters whose type is guessed (`dsl.rs:355-372`). Program families (`GenomeIr`, `genome.rs:18-35`): **pipeline** (optional leading `(target kind=rank_gauss|log1p|winsor|zscore)`, default head `ridge`), **symbolic** `(sym affine|raw "<expr>")`, **explicit portfolio** of 1–12 member pipelines blended by NNLS, a **compact portfolio head** expanding to the 13-member `core_v1` registry (`members.rs`), and `motif_*` **fragment macros** expanded before canonicalisation (`jope-motifs`). An expression sub-language (19 functions, `+ − × ÷ ^`, column variables, 7 row aggregates; ≤ 64 nodes, depth ≤ 16; `math_expr.rs`) serves `map`/`derive` stages and symbolic programs.

**Operators.** Legacy dialect: **36 distinct transforms** (38 names with aliases) — scalers, rank/Blom, quantile bins, one-hot bins, hinges, splines, winsorising, Chebyshev, polynomial interactions, random Fourier features, random projections, landmark distances, oblique hinges, row statistics, pair products/ratios, target-bin encoding, sigmoid/step, row normalisation, polar, lag/roll, FFT magnitude, row spectra, SVD projection, Nyström, expression `map`/`derive`, symlog, correlation screening, imputation — and **12 distinct heads** (15 names): ridge, ridge_gcv, elasticnet, histgbm, histgbm2, ensemble (ridge+GBM), krr, gpr (ARD-RBF or composite kernels of ≤ 3 primitives), ksmooth, hurdle2, stack (Caruana selection over 5 models), portfolio (`ops.rs:326-798`, `heads.rs:36-183`). The `advanced_v3` dialect adds schema-bound raw tables (categorical modes, imputation, missingness indicators), multiclass/binary heads, `tab_boost`, `extra_trees`, `gam_boost`, `pls`, out-of-fold target encoding and calibration, and row-ordered lag/roll.

**What search actually generates.** `evolve::TRANSFORMS` = 18 transforms (+5 opt-in expansion ops) and 7 heads (`evolve.rs:33-92`). Executable but **never generated**: lag, roll, map, derive, landmark_dist, nystrom, svd_project, fft_mag, row_spectral, row_diff_stats, polar, step, norm_row, and the heads krr, stack, ensemble, hurdle2, portfolio, and every target stage. The generator vocabulary is frozen because "its length is the modulus of every recorded random-generation stream" (`evolve.rs:87-90`).

The language is broad. The problems are that its semantics live in at least 13 disagreeing lists, its identity is lossy, several genes do nothing, and the parts that are typed are not wired in.

### 7.3 `ProgramGraph`: the effect-typed layer, built incrementally

Do not write a fourth language. Build one typed layer *underneath* the existing syntax, sourced from the typed grammar that already exists (G3):

```
legacy S-expr / advanced_v3 / motif macro
      │ parse (existing parsers, unchanged)
      ▼
ProgramGraph  { nodes: [Node{op: OpRef, params: TypedParams, inputs: [Port]}], output }
      │ type/effect check against Registry (types from advanced_v3 descriptors)
      │ canonicalise (fill defaults, shortest-round-trip floats, sorted commutative inputs)
      ▼
program_id_v2 = sha256("jope.program/v2\0" ‖ canonical_bytes)      (+ legacy_program_sha256 kept)
      │ fit plan (effects ⇒ OOF where FitTargetAware; fold-local fits)
      ▼
existing fit / emit / native evaluation
```

Node types: `Table{n_cols, col_kinds}`, `Features{width}`, `Target{scale}`, `Prediction`, `Scalar`. Effects (bit set, propagated): `Pure`, `FitUnsupervised`, `FitTargetAware` (⇒ OOF required in the fit plan), `RowOrdered` (refused on i.i.d. contexts), `Stochastic(seed_stream)`, `WidthChange(Δ)`. The type checker refuses a program before any fit; the edit ABI (§7.5) only offers type-correct edits. Legacy programs that do not type-check are not rejected retroactively — they keep their legacy identity and are marked `untyped` in `programs/`.

Files: `crates/feat-math/src/ir/{graph.rs, types.rs, effects.rs, canon.rs, edit.rs, legacy_bridge.rs}`. Acceptance: every program in the lineage-B winner set, the `gp_distilled/v1` table the vendored champion and the ten same-cut search outputs (`assets/same-cut/v2/reports/`) round-trips `legacy → ProgramGraph → legacy` byte-identically or is reported `untyped` with a reason; `program_id_v2` collapses `(ridge)` and `(ridge lambda_frac=0.02)`.

### 7.5 The edit ABI

The single interface shared by GP mutation, the bandit, Gumbel root search and the neural edit policy (Appendix C):

`Insert(site, op, params) · Delete(site) · Replace(site, op, params) · Wrap(site, op) · MutateParam(site, name, value) · Splice(site, donor, donor_site) · Retrieve(k) · Simplify(rule) · Stop`

`legal_edits(program, registry, context_schema)` returns the type- and effect-correct set at every site; `apply` is pure and deterministic; every applied edit emits a transition row (B.2). Legacy mutation arms map onto it one-to-one (jitter → `MutateParam`, insert → `Insert`, drop → `Delete`, swap → `Splice` within one program, head replace → `Replace` at the head site, crossover → `Splice` from a donor), so legacy profiles can be re-expressed through the ABI and checked against their golden traces.

### 7.7 Learning the language: motif promotion

`jope-motifs` already mines 2–6-stage fragments from qualified programs, quarantines every entry, validates exact expansion, and states "no code path promotes an entry" (`crates/jope-motifs/src/export.rs:59`). ## 8. Evolutionary search: one stronger kernel

### 8.1 Inventory (verified at HEAD) and the unification decision

Two facts make unification urgent rather than cosmetic: the README's same-cut ranking (#3/15, Elo 1556.6) measures **lite-race**, which `jope pipeline run` never executes; and every learning experiment (CLOVER ratchet, H1 pilot) measured with the **legacy** loop, the weakest of the three.

**Decision.** One search kernel in `crates/feat-math/src/kernel/strategy/` (pure library: no I/O, no custody), driven by a `SearchStrategy` value. The name is deliberate: feat-math already has `kernel::profile::SearchProfile` (`kernel/profile.rs:238`), which is a *vocabulary* profile — stages, heads, parameter domains, edit and splice weights — selected by `--search-profile legacy|kernel2-baseline|kernel2-experimental`, and `kernel::search` (`admit_child`, `mutate_program`, `crossover_programs`). A *strategy* is the orthogonal algorithm axis (population, parent selection, racing, migration, allocation). A run is a (vocabulary profile × strategy) pair, both ids are written into every receipt, and the strategy calls the existing `kernel::search` moves rather than re-implementing them. `jope-pipeline` (and its existing `kernel2` profile mechanism, `crates/jope-pipeline/src/kernel2/`, which already gates profile-specific operators behind `--search-profile`) becomes the shipped driver; `jope-bench` calls the same function with the same strategy ids. The three loops above become strategies with golden-trace tests: `legacy_v1`, `lite_race_v1`, `islands_lambda_v1`. The new default is `modern_gp_v1` below. Every other loop is frozen in place (or moves with the lineage-A quarantine, §13 R3) and is not extended.

### 8.3 Learned operator allocation (the first learning in the loop)

A contextual Thompson-sampling bandit chooses the edit kind (and, for `Insert`/`Replace`, the operator family) for each child:

- Context features: dataset metafeatures (n, p, target skew, missingness, categorical share), parent features (head family, depth, transform count), island policy, generation.
- Reward: `[child_q − parent_q]₊ / σ`, plus a censored penalty for failures/timeouts.
- Model: Bayesian linear regression per arm (cheap, exact posterior); warm-started from the `edit_transitions` table across runs; 20% uniform floor for identifiability; exact propensities logged in every transition row (B.2).

This is the cheapest piece of learning in the system, needs no GPU, improves search immediately if it works, and — because every choice is logged with its propensity — produces clean off-policy data for the neural edit policy later.

### 8.4 Residual-guided edits

After a program is measured at `fold2`, compute train-fold residual diagnostics (never held-out): residual vs each feature (monotone trend → add spline/binning on that column), residual periodicity (→ Fourier/lag terms), heteroscedasticity (→ target transform), interaction screen on top residual-correlated pairs (→ interaction op), cluster structure in residuals (→ gating/mixture, §7.6). Each diagnostic proposes a *typed edit* with a prior weight; the bandit decides how much budget these proposals get. This is the GP analogue of a human data scientist looking at a residual plot, and it gives the edit policy a strong, interpretable feature set to learn from.

### 8.5 Gumbel root search with measured leaves

At the start of each generation on each island, for the island's current best program `p`:

1. Enumerate legal edits (registry-masked); sample `k = 16` without replacement by Gumbel-top-k on `log π_prior(e) + g_e`, where `π_prior` is the bandit (or, once gated, the neural edit policy).
2. **Sequential halving with real evaluations**: evaluate all 16 children at `smoke`, keep 8 → `fold1`, keep 4 → `fold2`, keep 2 → `full_inner`. Total ≈ 16+8+4+2 = 30 evaluations at mixed fidelity (≈ 10 full-equivalent).
3. Score `g_e + log π_prior(e) + σ(q̂_e)`, where `q̂_e` is the *measured* `q` at the highest fidelity level reached (completed-Q for unexplored edits = prior-weighted mean of explored siblings).
4. The improved policy `π_search = softmax(log π_prior + σ(completed q̂))` is stored as a teacher target **only if** the selected edit's measured `q` beats the prior's argmax edit's measured `q` (qualified root).
5. The surviving children enter the island population.

This is Gumbel AlphaZero's policy-improvement step [Danihelka22] with each "simulation" being a real evaluation; the sampled-action target correction of Sampled MuZero [Hubert21] applies when parameters are continuous — appropriate because the theory guarantees improvement at n = 2–16 and requires no learned value function at the root. Deeper planning (depth-2 with transpositions, progressive widening) is gated on the value head's calibration (§9.2 N4) and on beating this root search at equal compute twice.

### 8.6 Sibling experiments for clean credit

Every evaluated set of children of one parent at one fidelity forms a `sibling_group` (B.2): same context, same parent, same rows, different edits. Within a group, `Δq` differences are paired comparisons free of context and parent confounding — the exact counterfactual the edit policy needs, and the reason AWR's baseline (§9.4) is the leave-one-out sibling mean. The Gumbel root (§8.5) produces sibling groups by construction; ordinary mutation produces them whenever a parent has ≥ 2 children in a generation (the strategy enforces this for at least 25% of children).

### 8.7 Quality-diversity archive

A MAP-Elites archive per context *family* (not per dataset), cells defined by 3 descriptors:

- head family (linear / kernel / tree-boosting / GP / stack-ensemble / symbolic),
- log program size bucket (transform count × parameter count),
- behaviour cluster: k-means (k=16) over fingerprint vectors (predictions on a fixed train-only probe, standardised).

A cell keeps the best program by `q` (ties by lower runtime) with a minimum-quality floor (`q > q(ridge) + 0.05`). The archive feeds `qd_archive` gen-0 seeds and island resets, and its occupancy and QD-score are round metrics. It is versioned with its descriptor definitions; changing them creates a new archive. Promotion ignores QD — it is a stepping-stone store, not an objective.

### 8.8 Cheap wins from the 2025–2026 evolutionary-discovery literature

Each is a small, separately ablated addition to `modern_gp_v1`:

- **Comparator pre-filter** [CoReyes24]: once V's binary comparator head is gated (W-09), reject proposed children with `P(child beats parent) < 0.2` before any evaluation, except for the 5% audit stratum below.
- **Score parents by their best child, not their mean** [Yuksekgonul26]: an island's parent weight is the max measured child gain over its last 8 children, with exponential decay — a parent that occasionally produces a big win stays a parent.
- **Power-law parent sampling across the archive** [Lange26]: sample archive parents with probability ∝ rank^(−α), α ≈ 1, rather than uniformly from 4 elites (the legacy rule).
- **Functional-equivalence rejection before fitting** [Real20, Lange26]: hash predictions on a 64-row probe after a cheap `smoke` fit; skip `fold1+` for children whose probe hash equals an already-measured program's.
- **Best-of-N at equal budget** is always reported as a baseline arm for any proposer change [Yuksekgonul26].
- **Constants by optimisation, not mutation** [LaCava21, Cranmer23]: continuous parameters of the top-k programs are refined by a short gradient/BFGS or TPE inner loop on train folds (kernel2's refinement move generalised), so mutation budget is spent on structure.

### 8.9 Randomised audit stratum

5% of each round's evaluation budget goes to candidates chosen uniformly from the *rejected* pool (screened out by the allocator or the race at a low fidelity level), evaluated at `full_inner`. This measures the false-negative rate of the allocator and the race, keeps the logged data identifiable for off-policy evaluation, and is the only defence against a value model that has quietly learned to avoid a region where it is wrong.

**The order-aware CLOVER head is also at chance.** Pooling is therefore not the main reason ranking fails; the label signal is. Within-context RMSE differences are tiny relative to between-context differences, and L6's `q` term regresses a *scale-free but context-dominated* target. EXP-018 succeeded by debiasing context effects first (strength-of-schedule offsets, LOPO) and ranking within context — the design below does the same.

### 9.2 Architecture: four networks (shared encoders N1–N2, policy N3, value N4), one family

**ADR-0007 (new): one policy family.** Freeze both existing lineages as league members and comparison identities (step-60000 for the 512×6 open-grammar lineage, v1 for the catalog lineage). New training happens in one family, `jope-policy/v3`, whose context encoder is the **Kumo-Tabular Small** vector the learning lanes already admit (the foundation and target encoders remain refused). Its decoder uses the step-60000 open grammar (401-token vocabulary, extended as §7.4 requires), not the trie.

**N1 — Context encoder `E_c`.** Input: the 2,051-d Kumo vector `z_c` (frozen) plus a **column-set encoder**: per column, a 32-d token of train-only statistics (type, missingness, cardinality, robust moments, skew, train-fold target correlation, monotonicity score, periodicity score), passed through a 2-block Set Transformer [Lee19] (ISAB, 4 heads) and pooled to 8 *context tokens* rather than one prefix. Rationale: the gen31 context gave only a 3.20–3.52 pp conditional ranking advantage over a genome-only control (`docs/internal/asm-manual/sections/training-history.md`, "Gen31 recorded context advantage"); one pooled prefix vector is a known bottleneck, and the column tokens let edit heads point at columns.

**N2 — Program encoder `E_p`.** Typed program graph (§7.3) as a sequence in canonical prefix order, each node token = `[op embedding ‖ type/effect embedding ‖ quantised-param embedding ‖ depth ‖ parent-slot]`, with **tree positional encodings** [Shiv19] (path-from-root encoding) and 4 transformer blocks (width 256); a GraphGPS-style graph encoder [Rampasek22] is the pre-registered alternative once programs become DAGs with shared sub-expressions. Output: per-node embeddings and a `[CLS]` program embedding. Wire in `OrderAwareRewardEncoder` as the initial implementation and replace masked-mean pooling everywhere.

**N3 — Edit policy head `π_edit`** (the apprentice). Given `(E_c tokens, E_p nodes of the parent, history tokens)`, a cross-attention trunk (4 blocks, width 256) and a **factorised action distribution**:

```
π(edit | s) = π(kind | s) · π(site | s, kind) · π(op | s, kind, site) · π(params | s, kind, site, op)
   kind   ∈ {Insert, Delete, Replace, Wrap, MutateParam, Splice, Retrieve, Simplify, Stop}
   site   : pointer over parent nodes (and edges for Insert)
   op     : over registry operators legal at that site (masked by the registry, §7.4)
   params : per typed parameter — categorical bins for discrete, a 2-component
            logistic mixture over the normalised range for continuous (exact density, no fake bins)
```

Every factor is masked by legality before normalisation; the log-probability of an edit is the exact sum of factor log-probs — preserving the property the repo values (exact behaviour likelihoods for off-policy correction and KL). A **whole-program decoder** (the step-60000 decoder, re-headed on N1) is kept as the `Generate` arm for cold contexts with no retrievable parent.

**N4 — Value/outcome model `V`** (the critic). Predicts, for `(c, p)`: the distribution of `q` as an HL-Gauss histogram over 64 bins on `[−log 1000, log 1000]` [Farebrother24] (quantiles read off it), `P(fail)`, `P(timeout)`, `log runtime` quantiles, and — most importantly — a **binary comparator** `P(q(child) > q(parent) + τ | c, parent, edit)`. The comparator is the head the search uses first (pre-filtering mutations before evaluation), because binary child-vs-parent discriminators beat regression predictors for guiding program search [CoReyes24], and because JopeDime's own evidence points the same way (regression `q`-head at chance; within-context ranking learnable). Trained separately from the policy (shared N1/N2 weights frozen or with a stop-gradient) to avoid the multi-head interference the v1 `q`-head suffered. **Gate:** V replaces `ContextualSurrogateQHat` as the allocator only if it beats it on EXP-018's own metrics (B=1 top-1 gain and pairwise accuracy, parent-cluster CI) on the same shadow pool *and* on the exact arena. Until then the ridge surrogate stays in production and V is a candidate.

Sizes are deliberately modest (≈10–15M parameters total). Scaling waits until rung-1/2 gains appear (§10.1).

### 9.3 Training data: use the firehose, then the prior

Three sources, in order of trust:

1. **Edit transitions** (§4.3, `lake/v1/edit_transitions`): every GP child with its parent, operator, site, parameters, measured `Δq` and `σ`, plus the *siblings* evaluated from the same parent (§8.6). These are clean counterfactual comparisons — same context, same parent, different edit — exactly the supervision an edit policy needs. Target: ≥ 10⁶ transitions from one campaign over the real regression tier (§15, W-06).
2. **Measured Universe outcomes** (`lake/v1/outcomes`): `M[c,p]` rows for V's absolute-quality heads, with `role` enforced.
3. **Planted-program synthetic tasks** (§6.7): an unlimited source of `(task, program, q)` with known optimum. Used to **pre-train V and N1/N2 as a prior-fitted network** in the TabPFN sense: sample a synthetic task, sample ~64 programs (half near `p*` by edits, half random), measure them cheaply (n ≤ 2,000 rows, 2 folds), and train V to predict their `q` *in context* — given a set of (program, q) pairs already measured on the task, predict the rest. This is the remedy for the q-head's data starvation: the in-context formulation means V learns "how do programs rank on a dataset like this, given a few observations" from millions of synthetic examples, then is fine-tuned and calibrated on real rows. The historical `test_adaptive` rows (63,108 Golden42 candidate evaluations; lineage-A snapshot maxima) may be used for representation pre-training only, never as a selection label.

**Reanalyse and staleness.** Stored transitions are never discarded because the model that proposed them is old. Each round, the current V re-scores every retained transition's parent and child (the MuZero Reanalyse step; cheap, since it is inference only), and those refreshed values feed the advantage baselines and retention value (§11.5). The *measured* `Δq` is the label and is never replaced; what Reanalyse refreshes is the baseline and the priority. When proposals come from a checkpoint older than the one being trained, the policy loss uses truncated importance weights `min(ρ̄, π_θ(a|s)/μ(a|s))` with ρ̄ = 1 (V-trace [Espeholt18]); this is why every transition row records its proposer checkpoint and propensity `μ(a|s)` (Appendix B.2).

### 9.4 Objectives

**Policy (N1–N3), per batch of contexts:**

```
L_policy = L_AWR + λ_SD · L_SD + λ_KL · KL(π_θ ‖ π_anchor)_sampled − λ_H · H(π_θ(kind|s))
```

- `L_AWR = − Σ_t w_t log π_θ(e_t | s_t)`, `w_t = clip(exp(Â_t / β), 0, w_max)`, `Â_t = (Δq_t − b(s_t)) / σ̂(s_t)`, where `b(s_t)` is the mean `Δq` of the *sibling* edits from the same parent (an RLOO-style leave-one-out baseline computed from logged data, no critic needed), and `σ̂` is the pooled fold-noise scale. Advantage-weighted regression on logged transitions is off-policy-stable and uses every transition, winners and losers.
- `L_SD`: **search distillation** — cross-entropy to the Gumbel root search's improved policy `π_search = softmax(log π + σ(completed Q))` over the sampled edit set (§8.5), only for roots where the search target is *qualified* (it improved measured `q` over the prior's choice on that root; SP3's "no false visit-count teacher" rule). `λ_SD = 0` until ≥ 10⁴ qualified roots exist.
- `KL_sampled`: the anchor is the previous promoted checkpoint. With an open grammar the exact catalog KL is unavailable; use the unbiased estimator `E_{e∼π_θ}[log π_θ(e) − log π_anchor(e)]` on 64 samples per context, plus the existing exact trie KL on the catalog *as an additional diagnostic* (continuity with C120).
- `H`: an entropy floor on the edit-kind head prevents collapse onto one edit type (§17).

**Value model (N4):** HL-Gauss cross-entropy on the `q` histogram, binary cross-entropy for the comparator (on sibling pairs and parent–child pairs, label smoothing 0 — these targets are later distilled), `P(fail)` and `P(timeout)`, a censored survival likelihood for runtime (`log S(T)` for timeouts, `log f(t)` for completed runs), and a **within-context listwise term** (ListMLE over measured programs on the same context, after subtracting the context's mean `q`) — the debiasing that made EXP-018 work, now inside the network. Report calibration (PIT histogram, quantile coverage) per family; the allocator only trusts V where coverage is within ±5 pp of nominal.

**What is dropped:** imitation CE on frozen teachers as the dominant term. Teachers are retained as a small replay share (≤ 10%) to protect coverage, not as the definition of success.

**Pre-registered challengers** (each a pre-registered secondary arm of W-11 or W-13, never the default until it wins at rung 2):
- *Group baselines without std normalisation* (Dr. GRPO's correction [Liu25]): `Â = Δq − mean(siblings)`, dropping groups whose children all tie on `q_grid`. Dividing by the group std inflates fold noise on nearly-solved contexts.
- *Max-of-K objective* (PKPO [Walder25]) with `K` = the search's per-parent child count: the search keeps the best child, so the proposer should be trained for the best of K, not the mean. Mean-reward training narrows coverage [Yue25].
- *Restart-from-anchor each round* (EvoTune [Surina25]): train round `k+1` from the round-0 anchor on all-phase elites rather than continuing from `π_k`; monitor the number of distinct `q_grid` values among proposals as an overfitting signal.
- *Forward-KL DPO on sibling pairs* at high β as an alternative to AWR.
- *Lazy penalties* (ThetaEvolve [Wang26]): a fixed negative reward for proposals that fail to type-check, fail to fit, or duplicate an already-measured canonical program.

### 9.5 Optimisation

- **AdamW**, decoupled weight decay 0.05 on matrices only (no decay on norms, biases, embeddings — fixing lineage B's decay-on-everything), β = (0.9, 0.95), ε = 1e-8, global-norm clip 1.0, BF16 autocast with FP32 master weights (lineage B's proven setup).
- **Schedule:** warmup 1,000 steps, then **WSD** (warmup–stable–decay) with the decay phase (final 10–20% of steps) set *in advance* per round. Never a plateau controller with a floor. The repo already has `warmup_linear_cosine_v1` (`deploy/dl-trainonly/…/objective.py:134-145`) as a reference implementation.
- **Continual rounds:** each round warm-starts from the promoted checkpoint with *reset* learning-rate schedule (re-warm) and kept AdamW moments — the pattern of owner ruling R14 (write-up §4.3), now systematic. Schedule-Free AdamW is the pre-registered challenger for the continual setting (no horizon to choose); Muon on the 2-D trunk matrices is a later ablation.
- **EMA** of weights (decay 0.999) for all evaluation and proposal generation; checkpoint the EMA and the raw weights.
- **Replay mix per batch:** 60% fresh-round transitions, 30% replay coreset (§11.5 influence-weighted), 10% frozen teachers. At most one context per parent lineage per batch (existing rule, C07).
- **Determinism:** the EXP-005 recipe (bitwise CUDA next-update parity, CPU fixtures) qualifies the new step before any campaign, as ADR-0006 P3 requires.

### 9.6 The expert-iteration round

```
ROUND k (inputs: promoted π_k, V_k, archive A_k, Measured Universe M_k)
1. Collect   — on a fresh TRAIN roster (disjoint from D-tune, D-confirm, sealed):
               run the search stack S(π_k, V_k) at fixed budget; log every transition, decision, outcome.
2. Improve   — at a sampled subset of roots, run Gumbel root search with measured leaves → qualified π_search targets.
3. Train     — V_{k+1} on M_k ∪ new outcomes; π_{k+1} on L_policy (warm start, WSD, EMA).
4. Arena     — exact arena on D-tune (rung 1): J_8, simulated discovery-AUC vs π_k, v1, step-60000, retrieval-only.
               Stop here if not better (non-promotion is recorded, capsule emitted).
5. Develop   — live D-tune search at equal budget (rung 2): discovery-AUC paired vs S(π_k).
6. Confirm   — D-confirm one look (rung 3), F10 structure on discovery-AUC; promote via pointer CAS.
7. Memory    — capsule for the round (always), retention brain pass, Measured Universe compaction.
```

Controls for every H3 claim (reusing #327's restart-only and offline-replay controls): `π_k` continued on *old* data only (no fresh feedback), `π_k` with re-warm only, and the search stack with `π_k` frozen. A round shows fresh-feedback value only if `π_{k+1}` beats all three at equal compute.

### 9.7 Trainer authority

Unblock the tch trainer rather than extending Python: replace the always-refusing `require_original_gpu_grant` with a verifier that checks a signed, scoped grant (round id, GPU host, max steps, deadline) — the signed-participant-grant mechanism the native loop already uses (`README.md`, W7 native loop). Port only the four pieces the round needs from Python (§13, R7). Until the port is qualified, run rounds in Python under an explicit, recorded ADR-0006 exception scoped to `jope-policy/v3` training, so the ruling and the practice stop diverging silently.

## 10. Evaluation, qualification and claims

The repository's statistical machinery is sound; what needs changing is *which endpoint it is pointed at* and *how cheap the development loop is*. This section reuses F10 (ADR-0005 §6), SPQ-1 (`crates/jope-learning/src/clover/round_qual.rs`), the R6 D-tune/D-confirm split, the parent-cluster bootstrap and Holm correction unchanged, and adds an endpoint ladder.

### 10.1 Endpoint ladder

Each rung is cheaper and noisier than the one above it. A claim is labelled with the highest rung it reached. Rungs 0–2 are for development; only rungs 3–4 can support promotion.

| Rung | Name | Where | Cost | What it can show | Label |
|---:|---|---|---|---|---|
| 0 | Training diagnostics | train/val split | free | optimisation health: L6 per term, KL to anchor, entropy, gradient norms | `DIAG` |
| 1 | **Exact arena** | D-tune, Measured Universe (§6.5) | seconds | `J_1, J_8, J_32`, `W`, simulated discovery-AUC on in-table support, coverage | `ARENA_EXACT` / `ARENA_PARTIAL` / `ARENA_SIMULATED` |
| 2 | Live development | D-tune, live search, equal budget | hours | discovery-AUC, final gain, win rate with real search (off-table programs measured live) | `DEV` |
| 3 | Confirmatory | D-confirm, one look per pre-registered comparison (R6 rule) | hours | paired discovery-AUC, parent-cluster CI, Holm across arms | `CONFIRMED` |
| 4 | Held-out generalisation | sealed families (one-holdout ruling, C180) with SPQ-1 `QualTestScore` sequential looks | days, owner grant | held-out test RMSE ratio vs incumbent and vs ordinary search (`Endpoint::FinalVsRound0Incumbent`, `Endpoint::RatchetVsOrdinaryFinalRound`) | `QUALIFIED` |

Rules:

- **No rung-0 metric is ever a success claim.** L6 stays as the anchored objective's stability guard (the G32 regression guard — trips after three consecutive closed epochs above 1.02× v1's plateau-best L6, write-up §6.6 — unchanged) and as a diagnostic. This brings practice in line with C152.
- A change that does not improve rung 1 does not get rung-2 budget, unless it targets off-table behaviour (e.g., the open decoder), in which case rung-1 coverage is reported and rung 2 is required.
- Rung 3 uses the existing E2 design (write-up §9.3): `n_prop = 16` proposals per context per checkpoint, U-statistic best-of-8, failures ranked lowest, `parity_unqualified` charged as failure, > 5% unknown ⇒ inconclusive. It is extended with the search-stack variant: same budget, same GP, different proposer/allocator.

### 10.2 Re-judging the existing checkpoints (first, before any new training)

The EI-0…EI-4 and R22…R27 checkpoints and the v1/v2 anchors are recorded in the experiment catalog with host-custody locators (EXP-006, EXP-007, EXP-013…017 `artifacts`); W-02's first step verifies that each one is retrievable and hash-matches. Rung-1 judgment of all of them is pure computation once the D-tune catalog table exists:

1. Measure the full 6,640-program catalog on the 26 D-tune contexts (W-01, §15).
2. For each checkpoint, compute `π(p|c)` over the catalog (exact, via the trie — the existing exact trie log-prob code from #278/#289, `deploy/dl-flywheel/pipelines/rlfw/trie_logprob.py`, which PR-08 ports to Rust) and `J_B` by the closed form.
3. Report paired `J_B(ckpt) − J_B(v1)` with the parent-cluster bootstrap (26 contexts is small; report it as `ARENA_EXACT`, development-only).

Possible outcomes, all useful: (a) fine-tunes that "regressed" on L6 improve `J_B` ⇒ Cause 1 confirmed, the EI direction was right and was mis-scored; (b) they also regress on `J_B` ⇒ the archive-CE recipe genuinely hurts and the edit-policy redesign (§9) is necessary rather than optional; (c) no difference ⇒ catalog-selection quality has saturated and the gain must come from support expansion (open decoding / edits), which the arena cannot score and rung 2 must.

### 10.3 Promotion rule (adapting F10 to discovery)

F10 is kept verbatim for its structure — paired per-cut statistic, cluster bootstrap over cuts, preregistered resamples/seed/alpha, accept iff mean improvement AND wins ≥ losses AND no extra failures, malformed ⇒ inconclusive, `final_tests_opened == false`. Two substitutions:

1. **Statistic**: per-context mean over seeds of `D_challenger − D_serving` (discovery-AUC at equal budget) instead of `ln(best_challenger / best_serving)` on proposals fitted once. The latter remains a secondary endpoint.
2. **Contexts**: D-confirm (one look) for promotion of the policy pointer (`pointers/`, §11.6); D-tune results never promote.

The promotion record is the existing pointer protocol: flock + ancestor compare-and-swap locally, conditional PUT naming the expected previous version in S3, immutable objects (ADR-0005 §6).

### 10.4 Power, honestly

With 27 D-confirm contexts and ~54 validation parent lineages, small effects will be inconclusive. The pre-registration must state the minimum detectable effect from a power calculation on rung-2 variance (measured in W-03), not adopt the "n ≥ 881" rule, which the repository itself found was derived from a misread standard error (C144). If the MDE at 27 contexts is larger than any plausible effect, the honest options are (a) more confirmation contexts from the 5,461-context join backlog (write-up §8) under a sealed role assignment, or (b) accept rung 2 as the highest available rung and say so in the capsule. Do not lower the bar; enlarge the panel.

- **Distillation**: `gp_distilled/v1` (`crates/jope-learning/src/retention/distilled.rs`, 25 columns) built from `GP_RESULTS_INDEX.json` — whose producer is **not in the repository** (copied from a host lane, `NUMBERS_TRACE.md:208`). Three defects: every distilled row is `Outcome::Ok` and unscored runs are skipped (9,383 of 18,380 in C190), so **all negative signal is dropped** despite the module's own promise that "failures and partial results are rows too"; `split_role` defaults to `train` for every row; and the hand-written Parquet writer emits one row group with no statistics or dictionary encoding (347 B/row), so no engine can prune it.

The foundations (immutability, manifest-last, conditional writes, a dry-run classifier, a pack format, a Parquet bridge) are right. What is missing: a cheap per-evaluation write path, the canonical layout actually populated, a queryable lake shaped for learning that keeps failures, and a retention policy whose notion of *value* comes from the learner.

### 11.2 The evaluation write path: one object, cached executables, batched custody

Replace "7 objects per evaluation" with:

1. **Executable CAS cache.** Key `exe/sha256(emitter_version ‖ program_id ‖ toolchain_digest ‖ target)/<digest>`. Requires reproducible builds of the emitted code (pin compiler, flags, `SOURCE_DATE_EPOCH`, strip non-deterministic sections; verify by double-build in CI). Effect: the 4.45 MB executable is written once per *distinct program*, not once per evaluation. The same program evaluated on 1,000 contexts stores one executable.
2. **Evaluation pack.** One object per evaluation: `evals/<yyyy>/<mm>/<dd>/<round_id>/<eval_id>.pack` — a zstd-compressed tar with a fixed member index (`score.json`, `metrics.json`, `predictions.arrow`, `stderr.log`, `emitted/` sources), whose member SHA-256s are recorded in the score row. One PUT, one GET.
3. **Wave batching.** Within a round, score rows are appended to a local outbox and flushed every N evaluations (or T seconds) as one Parquet row group per flush (`ledger/<table>/…/part-<ulid>.parquet`), plus the per-evaluation packs. Custody verification runs per batch (hash-closure of the batch manifest), not per evaluation.
4. **In-process fidelity levels.** Search evaluations at levels `static, smoke, fold1, fold2` run in the worker with `feat_math::fit` (as `jope pipeline run` already does) and write only their score rows. Full custody (emitted executable, parity, sandboxed native run) is reserved for *keepers*: per-context new bests, parity samples, and the pre-registered 1% audit sample (C62).

Target: ≤ 1.2 objects and ≤ 50 KB per non-keeper evaluation; custody share of wall time ≤ 30%. Measure before and after with the existing timing receipts; the change is evaluator-adjacent, so it gets a new ADR-0004 evaluator identity and the Measured Universe partitions by that identity.

### 11.3 The research lake

Add an analytics layer of append-only Parquet tables under a new canonical prefix of the learning bucket (not `staging/`, which "must not be promoted as" canonical):

```
s3://veox-jopedime-learning-use2/lake/v1/
  outcomes/          evaluator_id=…/date=…/part-*.parquet    # one row per verified evaluation: the Measured Universe M[c,p]
  edit_transitions/  date=…/part-*.parquet                   # (context, parent_id, edit, child_id, Δq, σ, fidelity, operator, policy_id, propensity)
  search_decisions/  date=…/part-*.parquet                   # choice-set digest, selected, propensities, budget before/after
  programs/          part-*.parquet                          # program_id → canonical DSL, typed-IR digest, size, ops histogram, motif ids, behaviour fingerprint
  contexts/          part-*.parquet                          # context_id → dataset/cut/fold ids, role, parent lineage, encoder digests, z_c
  checkpoints/       part-*.parquet                          # policy/value checkpoints, ancestry, corpus manifest, arena scores
  capsules/          part-*.parquet                          # L1 capsules flattened (§12)
  retention/         date=…/part-*.parquet                   # per-object value scores and tier decisions (§11.5)
```

Design rules:

- **Rows reference authoritative blobs by digest; the lake is an index, not the authority.** Every table is rebuildable from the immutable packs and receipts. A row whose referenced blob fails hash verification is excluded at read time.
- **Partition by date and evaluator identity**, never by program id (high cardinality → small-file explosion). Compact daily to 128–512 MB row groups.
- **Role is a column, and readers enforce it.** `role ∈ {train, validation, dtune, dconfirm, sealed, synthetic, test_adaptive}`. The training sampler's reader rejects `dconfirm`, `sealed`, `test_adaptive`; the arena reader rejects everything but `dtune`.
- **Query engine**: DuckDB over S3 Parquet for analysis and the exact arena (single host, no service); S3 Tables / Iceberg only if concurrent writers or schema evolution become painful. Start with plain Parquet + a manifest; the design does not depend on a catalog.
- **Backfill**: `GP_RESULTS_INDEX.json` (all 18,380 runs — the 8,908 scored as `completed`, the 9,383 unscored as `failed`/`unknown` with their recorded reason, and the 89 provenance-incomplete rows as `provenance_incomplete` — never dropped) → `outcomes`, after committing the index producer to the repository; lineage-B `parallel.cut_champion.v1` winners (11,903, with the 873 sealed `meta_test` rows tagged `sealed`) → `outcomes`; lineage-A snapshot maxima and the 63,108 Golden42 test-scored candidate evaluations → `outcomes` with `role=test_adaptive` (representation pre-training only, never a selection label — the README already establishes why they are not held-out results).

### 11.4 Conditional writes: extend what exists, then qualify it live

S3 supports `If-None-Match: *` (create-only, GA August 2024) and `If-Match: <etag>` (compare-and-swap on overwrite, November 2024). The mirror already uses both through `object_store`'s `PutMode::Create` / `PutMode::Update`. Three changes:

- **Extend the same protocol to every new table and pointer** in §11.3 (evaluation packs, Parquet parts, Measured Universe manifests, `pointers/accepted-main.json`, round heads). No new mechanism; one more caller of `put_if_absent` / `put_conditional`.
- **Replace ~12k per-cut `current.json` pointers with a per-batch Parquet HWM snapshot** committed under the same `HEAD` CAS (`docs/learning.md:179-180`: with ~12k pointers, each would cost a GET per push). This removes the stale-derived-pointer class and most request cost.
- **Qualify it live**: a restore drill and a two-writer race on the real bucket under scoped roles (§11.6) — the step `docs/learning.md:252-256` records as untested.

### 11.5 Retention brain v2: value that rises and falls with what the system knows

`jope_retention` classifies by *kind* and *age* (tiers, a 90-day noncurrent window, pins from evidence mentions). That is the right safety layer. Add a *value* layer that answers "if this object disappeared, how much worse would the system get?" — and let the learner supply the answer.

**Per-object value score** (computed nightly into `lake/v1/retention/`):

```
value(o) = PIN(o) · ∞
         + w_e · evidence_refs(o)            # claims, capsules, receipts that cite it (any ⇒ PIN)
         + w_i · influence(o)                # leave-one-out influence on the current value head (rows only)
         + w_n · novelty(o)                  # 1 − max behaviour-fingerprint similarity to retained rows
         + w_u · uncertainty(o)              # value head's predictive σ at this (c,p): rare/surprising rows are worth more
         + w_r · reproduction_cost(o)        # CPU-seconds to regenerate × P(regeneration needed)
         − w_s · bytes(o) · tier_price(o)
```

- `PIN` = referenced by any claim locator, capsule `evidence_root`, promotion record, sealed-family receipt, or the pre-registered 1% custody-parity audit sample (C62; distinct from the 5% allocator audit stratum of §8.9). Pinned objects are never candidates. This is the existing T0 behaviour, generalised.
- **Score rows are always kept** (≈100 B each; C91 already proposes permanent retention). Value scoring applies to *heavy* objects: executables, predictions, logs, raw hot objects, intermediate checkpoints.
- **Why it gets smarter.** As the value head improves, `influence` and `uncertainty` of routine rows fall — the hundredth evaluation of a near-duplicate program on a near-duplicate context teaches nothing. Their heavy artifacts become deletion candidates while their 100-byte score rows remain. Surprising rows (large residual vs prediction) and rows from under-covered regions keep high value. Retention therefore tracks the learner's frontier instead of a calendar.
- **Coresets for replay.** The same scores drive replay sampling: a stratified coreset over (family × program cluster × outcome quantile) weighted by `influence + uncertainty`, so replay stays small as the lake grows.

**Implementation, inside the existing classifier (not a new tool):**

1. **Wire the dormant knobs** (`policy.rs:127-136`): keep the top `k_ctx` programs per context and `k_lineage` per parent lineage by measured `q`, plus a `reservoir_rate` (e.g. 5%) hash-selected random reservoir for unbiased negatives; the *heavy artifacts* (executables, predictions, logs) of programs dominated by more than `margin_rel` under a *qualified* champion become eligible after `grace_days`; their score rows are kept.
2. **Replace boolean TV with a per-group marginal value**: the leave-group-out change in the value model's inner-CV pairwise accuracy (cheap for ridge/LightGBM; sampled for the neural V), plus acquisition frequency from flywheel receipts. Stop letting "reservoir" fire on every scored row.
3. **Turn supersession on** once a champion is qualified (`classify.rs:534`).
4. **Build the E-rule provers** the plan already names (`plan.rs:1064-1088`; the labels E1–E5 are the classifier's own and unrelated to the E2 endpoint): E1 GET+sha256 verification job; E2 checkpoint→arena-score table (replacing the `frozen_v1_l6` notion with `J_8`); E3 by writing every distilled table's hash into a T0 manifest; E4 program-subset proof.
5. **Fix the distiller** to keep failures, timeouts and unscored runs as rows with their outcome class, take `split_role` per row, and write row groups with statistics and dictionaries, partitioned by `family/score_name/date`.
6. **Call the pack writer and write-time tags** from the evaluation write path (§11.2) — they exist and are tested, but nothing calls them.
7. **A separate `jope research retention apply --plan <sha>` tool**, outside the statically-guarded classifier sources, which writes `tombstones/` (already a reserved T0 prefix) before any delete.

**Two AWS facts that shape the tiers.** S3 Intelligent-Tiering never tiers objects under 128 KB, so the 180,539-object `archive-use2/staging/node-high-value/` prefix (mean ≈ 60 KB) and every per-evaluation small object (score rows, metrics, logs) only benefit from tiering after packing — and request costs, which dominate (C59), fall only with fewer objects. The pack writer is a prerequisite for cheap storage, not an optimisation. And Object Lock governance mode (bypassable only with `s3:BypassGovernanceRetention` plus an explicit header) is the right guard for sealed-family splits and D-confirm rosters: it makes "the search never touched the held-out set" auditable while leaving a break-glass path, addressing the leaky-verifier failure mode reported for AlphaEvolve-style systems [Georgiev25].

**Mechanics (unchanged safety)**: the brain proposes; a signed deletion plan with a dry-run diff, owner approval (C159), pack-then-verify-then-delete per object, and a receipt per deletion. Lifecycle rules are used only for storage-class transitions of non-pinned objects (Standard → Glacier Instant Retrieval after N days), never for expiry. Object Lock governance retention on promotion records and capsule evidence roots. Versioning stays on, so even an approved deletion is recoverable within the noncurrent window.

**What to clear first (projected, pending the brain's dry run):** the per-evaluation executables in `staging/` that are not keepers (the 4.45 MB-per-evaluation component), mirror-weight second copies whose primaries verify, and raw hot objects already packed. The 430 GB `staging/` estate is second copies by AGENTS.md's own description; the brain's first deliverable is a dry-run report showing how much of it is pinned, how much duplicates a verified primary, and how much is unique.

### 11.6 Roles and credentials (the only P0 storage item that is genuinely open)

Provision six IAM roles and stop using the administrator principal for automated work: `jope-reader` (datasets, models, lake read), `jope-evaluator-writer` (create-only PUT to `evals/`, `exe/`, `lake/*/date=…`; no delete, no pointer writes), `jope-trainer` (read lake, create-only PUT to `checkpoints/`), `jope-promoter` (If-Match PUT to `pointers/` only), `jope-judge` (the only role that reads `dconfirm` and `sealed` rows and sealed-family prefixes; create-only PUT of verdict receipts), and `jope-curator` (create-only PUT to `lake/v1/{programs,contexts,capsules,retention}/` and `tombstones/`; deletes only under an owner-approved retention plan hash, PR-31). The trainer's `checkpoints/` is the top-level `checkpoints/` prefix. `jope research doctor --check-s3` verifies each role can do exactly its allowed operations and is denied the rest.

## 12. Research memory: compressed, evidence-linked, AI-first

### 12.1 What exists, measured at HEAD

JopeDime already has the two raw ingredients most projects lack: an authoritative **claim ledger** (`docs/paper/claims.json`, 186 claims: 121 `established`, 23 `pending`, 22 `non-qualifying`, 20 `preliminary`; ~630 bytes each, every one carrying a `source` locator and a `sha256`) and a curated **experiment digest** (`docs/experiments/experiments.jsonl`, 18 records under `schema.v1.json`, fields `schema_version, id, title, phase_hypothesis, date_utc, source_commit, catalog_snapshot_commit, claim_ids, qualification_status, summary, data, protocol, metrics, outcome, artifacts, next_experiment_implications`). `jope-records paper-trace` already checks printed numbers against the ledger.

What it does **not** have is compression, or enforcement. The digest is 102 KB of JSONL for 18 experiments (median 5.0 KB, max 10.6 KB per record; gzip compresses it 3.3×, a measure of verbosity), plus a 64 KB README and a 30 KB synthesis. It is validated only by an inline Python snippet in its README — CI runs `paper-trace`, which never reads `docs/experiments/` (`crates/jope-records/src/paper_trace.rs:43-46`, `deploy/ci/check.sh:53`) — and 12 of 18 records carry `source_commit: "unknown"`. Meanwhile `jope-records` already defines a richer typed evidence-graph claim schema (subject, metric, units, denominator, comparison, baseline, uncertainty, limitations, stage, evidence nodes, revocation closure; `crates/jope-records/src/claims.rs:23-51`) that holds only two fixture claims, and `FlywheelReceipt` / `RoundQualReport` already emit machine-readable gates and reasons that nothing compiles into a record. `EXP-018`'s `metrics` object alone holds 13 SHA-256 provenance digests and a commit id interleaved with the four numbers that matter. An agent that wants "what have we learned about distilling GP winners into the policy?" must read ~45 KB across `EXP-006`, `-007`, `-013`…`-017` and reconcile Stratum-A/H caveats by hand. And the records are hand-curated: `README.md` says it is "curated, non-exhaustive", and `EXP-NEXT-01` was an entire work item just to catalog six records (EI-0…EI-4 and the PR #339 S3 flywheel) for work that had already run. Memory that depends on a human remembering to write it is memory that lags.

The fix is not a new store. It is a **deterministic compiler** from the authorities that already exist (claims, receipts, prereg packets) into three tiers of strictly decreasing size, with provenance pulled *out* of the reading path and into links.

### 12.2 Three tiers

| Tier | Name | Budget | Generated from | Read by |
|---|---|---|---|---|
| L0 | **Finding line** | ≤ 60 tokens (~300 bytes), one line | L1 fields by template | every agent, every session, always in context |
| L1 | **Capsule** | ≤ 600 tokens (~3 KB) | receipts + claims + prereg | an agent deciding what to run next |
| L2 | **Evidence closure** | unbounded | receipts, Parquet, checkpoints in S3 | auditors, the compiler, `paper-trace` |

The entire experimental history of the project at L0 fits in about 1,000 tokens today (18 lines; ≤ 1,080 at the 60-token cap). At 500 experiments it is ~30K tokens — still loadable whole. That is the property that lets research traction compound: the *whole* history is in every planning context, not a retrieval guess at it.

### 12.3 L0 — the finding-line grammar

One line, fixed field order, no prose qualifiers (qualifiers become the status token):

```
<ID> <STATUS>[@<RUNG>] <ARM>[ vs <CONTROL>][, <POPULATION>] | <ENDPOINT> <Δ> [<CI>] | <VERDICT> | <LESSON> | <C-ids>
```

`STATUS ∈ {EST, PRELIM, SHADOW, NONQ, DIAG, FAIL, PEND}`. Records produced after the endpoint ladder (§10.1) append its label, e.g. `PRELIM@ARENA_EXACT`; older records carry no rung. `VERDICT ∈ {BETTER, WORSE, NULL, INCONC, ALERT, n/a}` — computed by the compiler from the CI and the pre-registered margin, never typed by hand. `LESSON` is the only free-text field, ≤ 15 words, and the compiler rejects any number in it that does not appear in the cited claims.

Rules the compiler enforces:

1. Every numeric field is copied from a claim or receipt by locator; none is typed. A number with no locator fails compilation.
2. `verdict` is computed: `BETTER`/`WORSE` iff the CI excludes zero in that direction *and* the pre-registered practical margin is cleared; `NULL` iff the CI includes zero and the point estimate lies within the practical margin; `INCONC` iff the CI includes zero and the point estimate does not, or no CI exists; `ALERT` is reserved for the judge's regression rule; `n/a` iff the record has no pre-registered comparison.
3. `facts` must each cite ≥ 1 claim; `inferences` may cite none but are rendered in a different style everywhere they appear; `unknowns` are mandatory (an empty list fails compilation — every experiment leaves something unknown).
4. `do_not_repeat` entries are first-class and indexed. Example, from EI-0…EI-4: *"archive-CE λ sweeps on the 52-program r48 archive (42 contexts, disjoint roster) judged on L6-1148."* An agent proposing an experiment whose `(arm, control, endpoint, population)` signature matches a `do_not_repeat` entry gets a hard warning at prereg time.
5. Provenance (receipt hashes, PR bodies, extract hashes) lives only in `evidence_root`'s manifest, never in `metrics`. This alone shrinks `EXP-018` from 10.6 KB to ~1.6 KB.

### 12.6 Compiler design

Build on what exists: capsule fields map onto the `claims.rs` evidence-graph types (reuse its revocation closure for `SUPERSEDED`), and the compiler's first inputs are the receipts that already carry typed gates (`FlywheelReceipt`, `RoundQualReport`, judge verdicts, `SelfPlayRoundReceipt`).

```
crates/jope-records/src/research/
  mod.rs            // public API: compile(), verify(), brief()
  capsule.rs        // jope.research-capsule/v2 types + JSON Schema emit
  compile.rs        // claims.json + receipts + prereg → capsule; numeric-locator resolution
  verdict.rs        // CI + margin → verdict (one function, unit-tested against every existing record)
  render.rs         // L1 → L0 line; L1 → Markdown card; beliefs.jsonl
  index.rs          // Parquet index: (id, hypothesis, status, verdict, endpoint, arm_sig, control_sig, population_sig)
  dedupe.rs         // do_not_repeat signature matching
schemas/jope.research-capsule.v2.schema.json
docs/research/{index.l0.txt, beliefs.jsonl, capsules/EXP-*.json}   // generated, checked in, CI-verified
```

CI lane: `jope-records research verify --check` regenerates every capsule from its sources and fails on any byte difference (the same pattern `readme-benchmarks --check` and `paper-trace` already use). Migration: one PR backfills EXP-001…018 as capsules from the current JSONL (fields map 1:1 except `metrics`, which splits into `effect/secondary` and `evidence_root`), and `experiments.jsonl` becomes a generated view.

**Every wave must emit a capsule, including failures and aborts.** The round state machine (§9.6; states in Appendix B.3) has `CAPSULE_COMMITTED` as its terminal state; a round cannot close without one. That is what makes the memory complete rather than curated.

### 12.7 Using memory to choose the next experiment

Given the belief ledger, rank candidate experiments by `EIG / cost`, where EIG is approximated as the expected reduction in the width of the open hypothesis's CI (from a power calculation on the pre-registered design) and cost is the CPU+GPU-hour estimate from the resource ledger. This is crude and deliberately transparent; the point is that "what next" becomes a computed, logged, reviewable decision rather than whatever the most recent session remembered. Validate the memory itself with the retrospective test the repo already has the data for: give an agent only L0+L1 as of 2026-10-13 and ask it to predict the verdicts of EXP-013…018; compare with an agent given raw JSONL, and with one given nothing.

### 13.2 Principles

1. **Generated state beats narrated state.** Anything an agent needs to *act* on (current direction, open PRs, live gates, capability status, experiment beliefs) is generated from authoritative records and capped in size. Narrative stays, but moves out of the default reading path.
2. **Quarantine, don't delete.** The AGENTS.md custody rules apply: preserve, verify, then remove. Legacy code moves behind a feature gate or into an archive crate with its tests; nothing that a receipt digests is touched.
3. **One authority per concept** — one search kernel, one trainer, one policy family, one operator registry, one research CLI.

## 16. Demonstration: showing algorithmic self-play credibly

### 16.1 What not to show

- A fitness curve rising during one GP run (that is optimisation, not learning).
- A policy checkpoint with lower L6 (that is imitation, not play).
- A test-selected leaderboard row (the README already explains why `jope-dime` at Elo 2259.8 is not a held-out result).

### 16.2 The demo: "Three generations, one dataset family the system has never seen"

A deterministic, replayable web page (published artifact or `jope research demo --replay <capsule-id>`) driven entirely by committed capsules and S3 receipts. Five panels:

1. **The board.** A held-out regression dataset: rows, columns, the frozen encoder's 2-D projection of where it sits among the training families, the baseline league's scores on it (GPR, ensemble, XGBoost, …) and the incumbent `h_c`.
2. **The apprentice's opening.** Generation-k policy: the retrieved parent (nearest-neighbour champion), the top-8 proposed *edits* with their probabilities and the value head's predicted `q` quantiles. Side-by-side with generation 0.
3. **The expert's search.** Gumbel root search over those edits with measured leaves: which edits were evaluated at which fidelity, which were halved away, the improved policy target. Then the GP run seeded from it: a lineage tree coloured by operator, with each node's measured `q`, and the QD archive grid filling in.
4. **The win.** The champion program as a typed graph, its canonical DSL, and the emitted Rust / Python / C++17 / JavaScript with the parity receipt (bitwise or the declared tolerance) — the "deep-learning encoding → GP → code" chain in one view.
5. **The learning.** The edit transitions from this search entering replay; the next checkpoint's probability for the winning edit pattern on *related* families rising; the exact-arena `J_8` and the rung-3 discovery-AUC across generations 0→1→2→3 with their parent-cluster CIs; and the capsule's L0 line for each generation. Failed generations are shown too, with the reason they were not promoted.

A sixth, optional panel shows a **planted-program recovery**: Alice plants a structure absent from the catalog and the archive; Bob's search recovers a behaviourally equivalent program within budget; the recovered program and the planted one are shown side by side with their probe-behaviour agreement. That panel is the cleanest available evidence of invention.

### 16.3 Numbers on screen

Discovery-AUC and win rate per generation with CIs; evaluations and CPU-hours per generation; Measured Universe coverage; number of off-catalog champions and how many recurred as motifs; parity pass rate; the capsule's verdict token. Nothing on screen is typed by hand; every number has a locator.

## 17. Risks, kill criteria and anti-patterns

### 17.1 Risk register

| Risk | Early signal | Mitigation | Kill criterion |
|---|---|---|---|
| Exact arena overfits development (26 D-tune contexts reused endlessly) | arena gains that do not replicate on rung 2/3 | Rung 1 never promotes; refresh D-tune from the join backlog each quarter under a sealed role map; track arena→rung-3 rank correlation | Rank correlation < 0.3 over 5 comparisons ⇒ arena demoted to diagnostic |
| Edit policy collapses onto a few edits | entropy of the edit-kind head < pre-registered floor; QD occupancy falls | Entropy floor; mixture quotas in gen 0 (§8.2); KL to anchor; specialist league members | Two consecutive rounds below the floor ⇒ freeze, revert to parent |
| Value head exploited by search (surrogate over-optimism) | measured `q` of top-ranked candidates regresses below predicted lower quantile more than nominal | Measured leaves at the Gumbel root; randomized audit stratum (§8.9); per-family calibration | Calibration error > 2× nominal for two rounds ⇒ disable value-guided allocation |
| Synthetic tasks don't transfer | synthetic win rate rises, real `J_8` flat | Synthetic share capped; sim-to-real non-inferiority gate (§6.7) | Real non-inferiority fails twice ⇒ synthetic share → 0 |
| Leakage through retrieval or memory | retrieved neighbour or capsule from a sealed family appears in a training context's inputs | Role-filtered retrieval index; capsule `population.role` checked at retrieval; sealed families never in `M` | Any detected leak ⇒ quarantine round, invalidate dependent capsules |
| Custody fix changes evaluator identity | ADR-0004 digest changes | New evaluator identity row; old `M` rows remain valid under their own identity; arena compares within identity only | — (managed by identity, not killed) |
| Retention deletes evidence | a claim's locator 404s | Static guard (exists: no write/delete path in `jope_retention`); T0 pin set from claim locators; deletion only by signed plan with dry-run diff | Any unresolved locator ⇒ deletion halted, restore from versioned bucket |
| Two policy lineages persist | new code paths reference both encoders | One-policy-family ADR (ADR-0007, §9.2, PR-28) | — |
| Process overhead swamps progress | one PR per week, weeks per experiment | Exact arena makes most iteration offline; capsules auto-generated; STATE.md replaces narrative reading | — |

### 17.2 Anti-patterns (each observed in this repository's history or in the reviewed specs)

1. **Judging a policy by its training loss.** L6 on held-out contexts is still a training loss (§4.1).
2. **Sweeping a loss weight on a tiny archive.** EI-0…EI-4 tuned `λ_ar`, `λ_PI`, `λ_KL` against a 52-program archive. Fix the data before the weights.
3. **Imitating only winners.** Every transition is a labelled example (§4.3).
4. **A plateau scheduler with a floor reached in 5,677 of 17,773 steps.** v1 spent 12,096 updates at 1e-6 (C25). Use a schedule whose total length is set in advance (WSD/cosine) (§9.5).
5. **A closed vocabulary for an open-ended search.** The catalog trie (§4.2).
6. **Custody per evaluation.** 7 objects and 4.69 MB for a 100-byte score (§4.4).
7. **Re-proposing merged infrastructure as P0.** The reviewed specs' main failure (§3.4).
8. **Narrative as state.** 642 KB of root Markdown that agents must read to act (§13).
9. **Benchmark-chasing as evidence of self-play.** A Golden45 rank is a separate claim (§10.5).
10. **MCTS before a value function better than chance.** §8.5 uses measured leaves until the value head is calibrated.
