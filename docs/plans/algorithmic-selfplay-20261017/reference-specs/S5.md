# JopeDime: a verified, compounding algorithm-discovery system

**Final engineering specification — 17 October 2026**

**Decision:** evolve the existing Rust implementation into a continuously improving, budget-aware program-search system using Expert Iteration. First close and qualify the existing measured-program → fresh-corpus → native-update → child-policy → next-search path. Then improve structural ranking, evolutionary allocation, language expressivity, and durable research memory through controlled experiments.

**Repository baseline:** [`neverhuman/JopeDime`](https://github.com/neverhuman/JopeDime), commit [`5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc`](https://github.com/neverhuman/JopeDime/commit/5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc), committed 2026-10-17 at 14:05:21 UTC. All claims about current source refer to this commit. Proposed paths, interfaces, experiments, thresholds, and performance targets are explicitly design requirements; they are not claims that those changes have shipped or that they improve accuracy.

**Deliverable status:** engineering design and read-only audit. No repository changes, deployment, GPU campaign, private S3 inventory, bucket mutation, or serving promotion was performed. The specification incorporates complete reviews of all five supplied Markdown documents and primary research. It supersedes their recommendations as one coherent design; it does not replace the repository's currently accepted operating decisions by merely being written.

## 1. The decisions that matter most

### 1.1 What the system should become

JopeDime should learn **how to spend a limited computation budget to discover a good executable learning program for a new regression task**. Its long-term asset is a combination of a learned proposal policy, a learned estimate of which search decisions are worth making, a library of reusable program components, and a compact body of verified experimental knowledge. An archive that accumulates better programs is useful. A policy that proposes better programs on unseen task families is a stronger result. A policy whose improvement is caused by consuming new search evidence is the actual compounding flywheel.

The current implementation already contains a real native trainer, checkpoint/export identity checks, generation-zero neural proposal paths, a substantial bounded research loop, typed kernel capabilities, numerical fault policies, corpus/replay logic, conditional artifact publication, and a compact experiment digest. Starting again with a new orchestrator, new trainer, new storage framework, and new universal IR would squander those investments. The integration and qualification boundaries deserve the first engineering effort. [C04] [C06] [C07] [C08] [C13] [C20]

The strongest immediate scientific hypothesis is unusually concrete: **a structure-aware program critic can use information that the current native reward/runtime scorer cannot represent**. That scorer averages token embeddings without representing token order. Same-multiset programs therefore collide at the representation level even when stage order or nesting changes the algorithm. This is a reason to test a modest structural critic before scaling the decoder or adding a complicated RL optimizer. It is a representational diagnosis, not a promised uplift. [C09]

### 1.2 Ranked engineering priorities

| Priority | Change | Why it comes first | Required evidence before claiming success |
|---|---|---|---|
| P0.1 | Extend the native warm-start lineage with an explicit successor protocol and ancestry-aware challenger binding | Supported fresh optimizer steps 3,000/6,000 do not fit a product challenger rule requiring a step above 60,000; v2 has no successor protocol | Accepted ancestor → warm start → continued child → third bounded research round, with verified objective, corpus, optimizer epoch and inference parity |
| P0.2 | Close one existing learning cycle through one compatible `LearningSnapshot` | The repository has the components; a new parallel loop would create another authority | Fresh exact outcomes are consumed by the real native update and change the next proposal distribution, with crash/restore closure |
| P0.3 | Qualify changes prospectively at matched full cost and by unseen family | Repeated same-cut improvement, lower training loss and archive growth do not prove generalization | Frozen protocol, independent family roster, exact selected-program outcomes, complete attempt accounting, parent and frozen-search controls |
| P0.4 | Fix immutable model publication and replay eligibility gaps | Same-size existing blobs and incomplete historical GP-index rows are insufficient evidence for training or publication | Hash the bytes actually uploaded; reject corrupt same-size objects; account for every terminal attempt with explicit eligibility |
| P0.5 | Compile compact research capsules from the existing census and digest | The 18-record digest is valuable but curated; future agents need exact, queryable evidence and explicit non-claims | Deterministic rebuild, source/role/cost/uncertainty traceability and temporal-cutoff retrieval tests |
| P1.1 | Add a structure-aware, calibrated critic as a challenger | Direct information bottleneck in the current native ranker | Better held-out selection at equal candidate pools and total cost, then improvement when integrated into search |
| P1.2 | Unify search profiles around existing evaluator/variation interfaces | Parallel generic, neural and kernel paths make fair comparisons and capability discovery difficult | Shared admission, numerical policy, budget accounting and provenance; preserved old-profile fixtures |
| P1.3 | Make replay and local outbox storage bounded | Successful long-running publication must not grow local records and startup memory indefinitely | Crash-safe segment compaction, exact deduplication and measured steady-state bounds |
| P1.4 | Introduce provable S3 retention with exact-version retirement | Packing and cold storage alone do not reclaim bytes, and snapshot-only GC is racy | Read-only opportunity report first; later verified replacement, protected roots, monotonic retirement and independent deletion proof |
| P2.1 | Add typed edits, resource-aware allocation and bounded diversity | Better seeding is only one way neural learning can help evolution | Matched-budget gains over gen-zero-only GP; calibrated screening with random override audits |
| P2.2 | Grow reusable typed subgraphs and bounded fit-procedure programs | This enables discovery beyond combinations of existing transforms and learners | Search-space coverage, scope safety, backend parity, resource bounds and transfer beyond the discovery family |

The first useful learning milestone must precede new QD machinery, broad IR migration, MCTS, learned optimizers and an enlarged model. These later ideas remain valuable experiments, with explicit entry and stop criteria.

### 1.3 What would make the technology distinctive

Neural generation-zero seeding is established prior art: NGGP directly studies it; uDSR combines neural and evolutionary techniques; DGSR-MCTS combines neural mutations, tree search and refinement from successful experience. The compelling opportunity is a **verified, cost-normalized learner of algorithm search across tasks**, with transferable abstractions and an inspectable history of why the system learned. NGGP also gives a reason to compare loose and tight neural/evolutionary coupling rather than require neural intervention in every generation. [R23] [R24] [R25]

Three advanced directions are worth preserving as separate tracks:

1. **Learn the value of further computation.** Predict whether another evaluation, a constant-refinement step, a fresh seed, a mutation, a crossover, or a larger fidelity is likely to improve the incumbent enough to justify its cost. This is more directly useful than predicting final RMSE alone.
2. **Learn useful abstractions.** Discover typed reusable subgraphs whose definition cost is repaid by shorter search and better transfer on new families. A macro is accepted because it helps future search, not because it appears often in past winners.
3. **Discover fitting procedures.** Extend the language toward bounded initialization/update/predict programs, with explicit fitted state and effects. This makes algorithm invention a testable property of the representation rather than a description applied to every new parameter setting. AutoML-Zero and DreamCoder motivate this direction; their results do not guarantee tractability in this repository's task distribution. [R21] [R22]

### 2.4 Specific findings that change the recommended implementation

**F01 — The loop exists, but continuation and product identity need joining.** Native v2 loads accepted weights, starts a fresh optimizer and supports windows 0→3,000→6,000. Its predecessor/successor rule rejects v2 continuation. Candle's challenger binding requires a step greater than accepted step 60,000. A later optimizer epoch is not an absolute model age. Introduce explicit ancestry and optimizer epoch identity; do not fabricate a step of 63,000 or relax the accepted release hash. [C07] [C10] [C11]

**F02 — The reward/runtime program encoder discards order.** A masked mean of reward token embeddings feeds the heads. Positions and AST/dataflow structure are absent from this branch, although the decoder has positional information. Construct real valid-program collision fixtures, compare a small structural critic, and evaluate selection regret and uncertainty on unseen families. [C09]

**F03 — Several model lineages must remain separate.** Accepted native inference is width 512, six layers, four heads, FFN 2,048, sequence limit 128, vocabulary 401, context 2,048 values and 27,796,494 parameters across 136 tensors. The CLOVER support experiment uses a separate width-128, two-layer, four-head model, vocabulary 282 and sequence limit 640; its recorded context is 2,051. A retained Python v3 model is another research path. Mixing their vocabulary, loss, timing or checkpoint results would invalidate a design comparison. [C09] [C10] [C12]

**F04 — There is already useful support/likelihood engineering.** The frozen CLOVER trie uses the same legal children for sampling and EOS-inclusive teacher-forced likelihood, with explicit same-support KL checks. Its README explicitly restricts the supported model/form and keeps qualification blocked. Reuse the contract patterns, while implementing a separate native 401-token adapter. A frozen catalog support and an open grammar produce different probability distributions; their NLLs are not interchangeable. [C12]

**F05 — Quantile parity has a known fix with incomplete rollout.** The historical synthesis records 41 parity failures among 1,554 comparisons, concentrated in 41 of 342 quantile cases. A later six-cut replay records opt-in agreement on all six and legacy agreement on three. The reason is the exact binary-search probe behavior on nearly tied quantile boundaries, not an excuse to apply a universal tolerance. Preserve old semantics; qualify a named new emission policy across actual callers and languages. The small replay is diagnostic evidence, not complete production qualification. [C17]

**F06 — Publication can report success too early.** `jope-models/src/publish.rs` accepts a pre-existing blob on size alone, including the create-race path, and reads a local source again after prehashing it. Verify the exact uploaded bytes and existing object's content digest. The learning mirror already demonstrates a stronger pattern. This is a source-level defect, not a claim of a production corruption incident. [C21] [C22]

**F07 — Historical distillation is not a complete attempt dataset.** The GP-index adapter skips unscored runs and incomplete provenance and assigns successful rows a caller-selected default split role. Its shadow token features use a small hash vocabulary. Neither behavior is a suitable implicit source of production policy tokens or trusted role assignment. Preserve unknown/failure outcomes in the census and admit only individually verified training rows. [C23]

**F08 — Current statistical code should be extended.** `qualify/promotion.rs` already computes equal-family effects, practical margins, prespecified looks, bootstrap bounds and safety checks. Its reports do not actually promote, and an adopted sealed-family boundary is missing. `clover/round_qual.rs` also intentionally denies qualified claims. Extend evidence verification and live authority integration; changing a boolean from false to true is not qualification. [C25] [C26]

**F09 — Large source files are an ownership problem, not a mandate to rewrite algorithms.** Examples include the 8,090-line self-play TUI, 7,790-line evolution implementation and multi-thousand-line training/search/authority modules. Split UI, orchestration, pure decisions, receipts and tests along dependency seams. Preserve numerical kernels and existing test fixtures during extraction. File-length thresholds can trigger review; they cannot establish correctness or justify replacing stable code. [C33]

**F10 — Several claims in older audit discussions are stale.** Current finite-value guards exist in retained evaluation/parity paths. The current Python policy file imports `copy`. Explicit AWS profile resolution supports `credential_process`. Current registry metadata, kernel reservations, lexicase, exact serialization and structured experiment memory already exist. The final plan does not spend PRs re-fixing historical absence claims. [C24] [C27] [C28]

## 3. Review and scoring of all five supplied specifications

### 3.1 Method and interpretation

Each document was assessed independently on a common weighted rubric. Scores assess **design quality and implementation readiness**. They do not grade the current product, estimate future accuracy, or measure the authors' effort. The documents' own 96/97 ratings and their scores for earlier drafts were not inherited. Transparency about unverified claims earns credit, but cannot substitute for current source grounding.

Category scores run from 0 to 10: 10 = exact, implementable, falsifiable contract; 8 = strong with small unresolved gaps; 6 = useful with material unresolved work; 4 = conceptual or internally contradictory; 2 = unsupported assertion; 0 = absent. Total = sum of `weight × category_score / 10`. Differences of a point or two should be interpreted as editorial judgment, not precise scientific separation.

## 4. The game, objective, and scientific protocol

### 4.1 A contextual single-player search problem

A task instance is a regression dataset with a declared split policy, feature schema, allowed operators, hardware/resource budget and deployment constraints. An episode runs a program searcher. Its terminal product is the program selected using permitted training/inner-validation information, plus fitted state and verified executable export where applicable. Exact execution supplies feedback; a neural policy and critic help choose what to try next.

The search state is conceptually:

`SearchState = (TaskContext, CandidateState, EvaluationHistory, RemainingBudget, SupportVersion, SearchPolicyVersion)`.

`CandidateState` can be a complete program, a partial typed construction, a parent pair, or an archive view depending on the profile. Each profile declares its state/action schema. `EvaluationHistory` includes what has actually been measured and at what cost; the same program with a different history or remaining budget is generally a different decision state. A surrogate estimate is an observation from a model, not an exact environmental measurement.

Initial actions are whole-program proposal, mutate, crossover, refine constants, restart, select a candidate for exact evaluation, and stop. Later profiles may expose typed edit sites and calibrated fidelity choices. The environment interprets transitions exactly; there is no alternating opponent and no sign inversion during backup. Historical policies are comparators and possible proposal sources, not adversaries defining a zero-sum utility. [R02] [R04] [R07] [R23] [R25]

### 4.2 Family partition, within-task access, purpose and fidelity

| Family partition / evidence role | Who may consume it | Permitted use | Excluded use |
|---|---|---|---|
| `train_search` | Search, trainer and research memory | Inner validation, measured targets, fresh replay, task curriculum | Independent generalization claim |
| `meta_dev` | Experiment designers and frozen development judges | Architecture, loss, schedule, descriptor and protocol selection | Training a checkpoint later evaluated as unseen on the same family |
| `qualification` | Frozen episode actor gets permitted training/inner views; independent judge gets outer labels | Isolated search/fitting on the new task, frozen comparisons and limited signed decisions | Outer-label search feedback, global replay/retrieval updates, checkpoint training on those families |
| `sealed_final` | Frozen episode actor gets permitted training/inner views; final judge gets outer labels | One final confirmation for a frozen claim/lineage protocol | Actor-selected access, global learning or development feedback |

Enforce `DataUseContext = (meta_partition, within_task_view, purpose, fidelity)`. `meta_partition` is the family assignment above. `within_task_view` identifies training features/labels, inner-validation features/labels, prediction-only outer features, or judge-only outer labels. `purpose` identifies isolated episode fitting/search, global policy training, retrieval/index update, independent judging, or audit. A qualification-family actor can solve that task using its permitted training and inner-validation data, while its global weights and retrieval store remain frozen. Those inner observations retain qualification ancestry and cannot be relabeled `train_search` to feed global learning. Prediction-only outer features may be exposed to the frozen fitted model; transductive use during fitting/search requires a separately declared protocol.

Fidelity separately describes row count, folds, repetitions, fitting iterations, precision, resource limit and evaluation procedure. A full-resource inner result on a training family is training evidence; the same computation on a qualification family is restricted episode-local evidence. A cheap independent qualification measurement remains qualification evidence. Verify partition, view and purpose from immutable dataset/roster provenance and authenticated capabilities; a CLI default or file path cannot upgrade them. Preserve current roster semantics through an explicit versioned mapping. [C23] [C25]

Families group related tasks globally: same underlying dataset, transformed variants, row subsamples, synthetic generator ancestry, near duplicates and benchmark aliases must not cross development/qualification boundaries unnoticed. Maintain a family registry with evidence for merges, split revisions and contamination findings. For time/group data, use the declared chronological/group split before any feature fitting. A foundation model's own pretraining provenance is a separate possible contamination source; record what is known and downgrade unknown claims rather than imply a guarantee.

### 4.3 Inner fitting must be honest

Every transform that learns a statistic—imputation, standardization, bins, target encoding, target transform, feature selection, random projection fitting, kernel landmarks, stacking weights and constant refinement—fits only on the training subset available at that call. Ordinary supervised feature selection may transform the training fold on which it was fitted. Target encodings and fitted predictions used as training features require an out-of-fold or independently fitted adapter: the entire fitted dependency closure must exclude the row/group/time ancestry being predicted. No whole-dataset embedding, target summary, cache or support import may expose independent judge labels.

The full fitting request includes task fingerprint, split/fold identity, train-row membership, preprocessing policy, program identity, initial/final fitting seeds, precision/backend, fidelity, numerical policy and resource caps. Fitted-state caching uses this full identity. A transform fitted on one fold cannot be reused merely because the program text is identical. Target-scaling inversion is part of prediction, metric computation and emitted-state parity.

### 4.4 Reward for search and outcome for evaluation

Retain raw RMSE, MAE, R² where defined, failure category, runtime, memory, program complexity and prediction cost. Do not replace those observations with a single scalar. For the initial training/search utility use a declared normalized log RMSE:

$$
\ell_{d}(p)=\log\left(\frac{\operatorname{RMSE}_{d}(p)+\epsilon_d}{\operatorname{RMSE}_{d}(b_d)+\epsilon_d}\right),
\qquad u_d(p)=-\ell_d(p).
$$

`b_d` is a fixed, simple baseline fitted on permitted training data; its evaluation uses the same score fold as the candidate. Choose `epsilon_d = 1e-6 × max(training_target_scale, 1e-12)` with the target-scale definition frozen in the metric version. For a constant target or degenerate split, use a separately declared degenerate-task policy and report absolute error; do not let a nearly zero denominator create an impressive ratio. No epsilon or baseline may be tuned using the independent judge outcomes.

A practical incumbent utility may include declared deployment preferences such as prediction latency or model size, with coefficients and units immutable within an experiment. In the displayed initial recipe, `u` is accuracy-only. Search expenditure is charged once through the transition reward below; do not also subtract it inside `u`. Maintain the vector `(accuracy, fit_cost, predict_cost, memory, expanded_complexity)` for Pareto reporting. User deployment constraints can instead be hard admissibility limits, followed by accuracy optimization among admissible programs. Do not teach the model that a timeout has an ordinary measured RMSE.

For sequential improvement, use undiscounted finite-horizon reward

$$
r_t = u(I_{t+1})-u(I_t)-\lambda_c\,\Delta c_t,
$$

where `I_t` is the best inner-selected admissible incumbent under the frozen scalar selection policy and `Delta c_t` is actual incremental cost. Stop emits zero additional gain and its actual overhead. With gamma=1, reward telescopes and does not reward rediscovering an old incumbent. A discounted or potential-shaped version requires a separately derived terminal convention. Maintain failed-attempt outcomes even when their utility contribution is zero or negative.

### 4.5 Whole-cost accounting

Every arm receives the same declared online budget and hardware class. Record wall time, CPU core-seconds, GPU-seconds/device, peak memory, object requests/read bytes/write bytes, compilation, dataset encoding, policy inference, retrieval, fitting, refitting, exact validation, export verification and retries. Include time spent on proposals later refused. Cache warmness and shared dataset loading must be fixed by protocol; count a cache hit's actual cost and disclose the cache's provenance.

Use a fixed cost unit for the primary budget—for example CPU core-seconds on a homogeneous CPU experiment. For mixed CPU/GPU experiments, define a reference-price conversion vector in the frozen plan, while still reporting raw resource vectors and real wall latency. Do not claim equal compute from equal evaluation counts. Existing nonpreemptive admission budgets may overrun during an admitted fit; record this and either enforce a new bounded fit policy or use a preregistered overrun rule for all arms. [C05] [C19]

Policy-training cost is reported separately and amortized over an explicit number `N` of future tasks:

`amortized_cost(N) = online_search_cost + (training + corpus_preparation + qualification_cost) / N`.

If the claimed benefit is lower online search cost, report the break-even task count and assumptions. A faster searcher can still be uneconomic when retraining and retrieval dominate. Avoid putting external vendor inference or compiler work outside the cost boundary for only one arm.

### 4.6 One exact primary endpoint

The primary endpoint for the first prospective policy study is **equal-family mean improvement in selected-program log-error area over a fixed log-budget grid**. It measures whether the searcher returns better models throughout the budget, not whether its candidate pool contains a retrospectively chosen outer-test winner.

Freeze budgets `0 < b_0 < ... < b_K`, with a mandatory valid baseline available at `b_0` and its setup/fitting cost included. Let `p_d(b_k)` be the incumbent selected using inner evidence at the last completed event no later than `b_k`, together with the exact fitted artifact already completed by that cutoff. Any refit needed to create that artifact must finish and be charged before the cutoff. The independent judge scores those exact artifacts after the episode, without later optimization/refitting and without returning outcomes to the actor. Judge scoring is outside the actor budget clock and inside total reported study cost. For each task/seed:

$$
J_d=\frac{1}{\log b_K-\log b_0}\sum_{k=0}^{K-1}
\ell_d^{\mathrm{judge}}\big(p_d(b_k)\big)\,\big(\log b_{k+1}-\log b_k\big).
$$

This is a left-endpoint step integral, lower is better. Completion exactly at `b_k` is included; an inflight result finishing later is not. The endpoint at `b_K` has zero area weight and is assessed by the separate terminal endpoint. Use the same grid for all contenders. Repeated incumbent artifacts can share an exact judge request when their full evaluation identity matches, without turning repeated grid points into independent observations. Terminal log RMSE, cost-to-target, failure rate, tail regressions, and prediction resources are secondary endpoints. Record terminal predictions for independent reproduction.

For each independent family `f`, average paired control-minus-challenger `J` differences across the family's prespecified contexts and search seeds to obtain `Delta_f`; average families equally. Positive effect favors the challenger. The default pilot uses one fixed terminal look, two predeclared controls and an overall one-sided error budget 0.05, allocating 0.025 to each comparison. It requires the lower family-bootstrap bound for **both** comparisons to exceed a practical margin chosen before results. An initial suggested margin is 0.01 log-error-area units, a design target to calibrate against user value on meta-development data. It is not a known detectable effect size.

Extend the existing `qualify/promotion.rs` calculator rather than adding a competing statistics module. Use its family percentile-bootstrap convention, SplitMix64 generator and type-1 quantile with 20,000 resamples of the paired family effects. At one-sided alpha 0.025 the lower bound is the 500th sorted bootstrap mean. Record seed, algorithm/version, summation order and exact inputs. Coverage is nominal, not a finite-sample guarantee. Its small-family guard is necessary but not proof of adequate coverage. Use at least 30 independent families for an initial prospective study and require development coverage/power simulations using a design alternative strictly larger than the superiority margin—for example a hypothesized true effect 0.03 when the decision margin is 0.01, with a stated target power such as 80%. These values are planning inputs to validate, not known effects. Freeze the family sampling frame; a convenience roster supports a claim about that roster and its justified scope, not automatically every regression task. If available families or compute cannot resolve the margin, report exploratory/inconclusive. Do not change the margin or estimator after results. [C25] [R44] [R45]

For broader claims across stochastic training, repeat independent training lineages, not merely search seeds. Average prespecified repeats within each `(lineage, family)` cell; quantify uncertainty over both lineages and families with a predeclared crossed resampling or hierarchical model. Three descendant rounds are correlated observations. A single fixed checkpoint evaluated across families supports a claim about that checkpoint; it does not estimate variation across retraining.

Multiple looks at a fixed prespecified candidate study require a fixed alpha-spending schedule whose total does not exceed the original budget, and repeated qualification of many candidates requires a study-level exposure/contender ledger. These measures do not validate ordinary bootstrap intervals for future checkpoints adapted using earlier results on the same families. After qualification feedback influences the lineage or candidate selection, use a fresh unexposed qualification block, or freeze all candidates before the panel's first access. A formally reusable-holdout method is a separate qualified research option. Start with one look. The sealed final panel remains unused until selection is frozen. Repeated pass/fail releases also expose information; track that exposure. [R46]

### 4.7 Controls that isolate the cause of improvement

| Arm | Proposer/weights | Historical support and retrieval | Purpose |
|---|---|---|---|
| G | Generic grammar/GP | Frozen common support; no learned ranker | Permanent search baseline |
| R | Generic GP plus retrieval | Frozen archive | Value of memory without updated weights |
| P | Parent policy plus common GP continuation | Frozen archive and support | Main neural parent control |
| C | Child policy plus the same GP continuation | Same frozen archive and support | Pure weight-update effect |
| S | Parent architecture with shuffled task context | Same support, cost and downstream search | Whether context actually matters |
| N | Same update budget, historical-only or no-fresh replay | Same current support in evaluation | Whether fresh evidence caused the child improvement |

Do not launch an unaffordable six-arm campaign before a small development smoke validates the harness. The first decisive checkpoint-quality study compares C with P and with the strongest simple nonupdated control chosen and frozen on meta-development data; use R or a classical-selector-plus-GP control when it is stronger than G. Keep G as a permanent mechanism baseline. A separate matched update-budget comparison with N is required before saying fresh feedback caused the gain. Freeze common data for a pure update experiment; when future evidence diverges because search policies differ, label it a coupled-loop experiment. To separate archive growth from weight learning, evaluate `(parent weights, old archive)`, `(parent weights, new archive)`, `(child weights, old archive)`, `(child weights, new archive)` on a common admissible grammar/support universe. If the new archive introduces previously unavailable programs, availability itself is a distinct factor; report both common-support and expanded-support results.

Use matched task/split/random-seed blocks and randomized or counterbalanced arm execution order, with hardware and cache policy held fixed. Dataset splits, common probe sets and paired fitting/evaluation replicates use common streams keyed by experiment, task and replicate; a checkpoint digest must not change those streams. Proposal/source draws use separate counter-based streams keyed by experiment, task, arm, source and draw index. Record both namespaces and their mapping to each request. This preserves paired experimental noise without forcing different policies to emit identical proposals; scheduler timing must not determine which arm gets a favorable random subsequence. Existing fixed neural-then-generic ordering is a target for this harness correction. [C06]

### 4.8 Failures, censoring and completeness

The planned-unit census is frozen before execution. Every unit ends as completed, algorithm-invalid, timeout, resource refusal, infrastructure failure, policy cancellation or unresolved; all attempts and retry costs remain attached. Invalid/timeout algorithms fall back to the prespecified valid incumbent and count in the algorithm failure rate. Independent judge infrastructure failure is unknown evidence: rerun under the predeclared policy or make the affected decisive comparison inconclusive. Do not silently analyze complete cases that disproportionately remove difficult tasks.

A timeout runtime is a lower bound on completion time. A low-fidelity score is a measured low-fidelity score. A pruned candidate's full-fidelity accuracy is unknown. Keep these labels separate; a survival/censoring head must model the observed stopping mechanism and does not automatically correct informative pruning. [R41]

Qualification requires **100% essential evidence closure** for the adopted cohort and zero unresolved authority/integrity holds. An operational publication SLO such as 99.9% delivery within a time target is a separate service metric. Missing proof is not the remaining 0.1% tolerated by a scientific claim.

### 4.9 Teacher and replay contracts

Define each target's type: `complete_program_imitation`, `matched_program_preference`, `typed_edit_imitation`, `mcts_action_distribution`, `measured_outcome`, `censored_cost`, or `feasibility`. A GP champion does not automatically yield MCTS visit targets. A successful child does not prove which parent deserves all crossover credit. Teacher quality must be evaluated at the same support and budget before its targets become the next policy's main objective.

Log separate quantities: raw proposal probability when actually defined; evaluator-selection probability; retention inclusion probability; replay sampling probability; target/reference policy identity; temperature; legality/support mask; and any clipping. Deterministic heuristic selection has no invented sampling density. The probability of an exact program can require summing several construction paths; a sampled derivation likelihood is not automatically that marginal probability.

Preserve all logical draws and their multiplicity even if several generate the same program. Deduplicate physical evaluation only on the full request identity. A batch of a hundred identical policy draws is evidence of mode collapse, not one draw; it is also not a hundred independent exact outcomes. Different downstream estimators can deliberately weight multiplicity differently, but the raw record must permit those choices.

Behavior cloning and clipped advantage-weighted likelihood are the first learning baselines. PPO requires real behavior-policy trajectories and correct old log probabilities; DPO requires a reference-policy preference formulation. Neither is justified by labeling arbitrary retained GP outcomes as RL data. Selection/retention propensities enable certain estimators where support and assumptions hold; they do not make all historical data unbiased or repair deterministic zero-support deletions. #### LearningSnapshot and the single publication authority

The unit made available to an adopted research actor or serving process is an immutable `LearningSnapshot`: a compatible checkpoint, corpus/replay snapshot, support/registry version, critic, program/motif library and capsule/index references. A component may be absent only when the snapshot's architecture/profile declares that absence. Its identity binds semantic hashes and required physical object-version references. A newer checkpoint paired with an older incompatible vocabulary or critic is not a valid snapshot even if both objects individually verify.

Before a candidate has an assessment, a bounded evaluator uses an immutable `CandidateExecutionManifest` under `jope.candidate-execution/v1`. It binds the completed exported checkpoint, frozen input parent, compatible critic/support, study/roster/data-use context, evaluator, seed/budget policy and required physical versions. The study pins these dependencies through `LearningAuthority`. This manifest permits only the declared evaluation; it grants no research-parent or serving status. Its results feed the later payload and assessment, and the resulting `LearningSnapshot` is a new immutable object. This supplies an executable starting point without requiring a candidate's future assessment to exist first.

Use the final storage contract's single `LearningAuthority` CAS record to map research, serving and rollback roots together with pins and the retired-version generation. Existing per-run `latest.json` and progress heads report local computation; they do not independently authorize global adoption. Research-parent acceptance publishes the new research snapshot through that authority; serving qualification publishes its serving root through the same mechanism, under the appropriate principal and decision record.

A publication revalidates the current authority generation and every required object's availability before its CAS. No live strong physical dependency may reference an S3 VersionId recorded as permanently retired. Provenance, relocation history and tombstones may name a retired version without granting read/replay authority or making its bytes live. If the same semantic bytes are restored as a newly verified physical version, construct a new valid strong reference and snapshot; do not resurrect the retired version. This requirement connects training restore, model adoption and garbage collection without allowing a delayed worker or stale pointer to revive reclaimed storage. Evidence roles are `train_search`, `meta_dev`, `qualification` and `sealed_final`, orthogonal to compute fidelity and enforced independently at every snapshot/receipt boundary.

| `architecture_id`, `vocabulary_id`, `context_abi_id` | Bind shapes, token meanings, encoders and runtime interface |
| `training_intent_id` | Exact frozen replay/input/window/resource plan responsible for these updates |
| `consumption_commit_refs` | Byte-length and hash-bound per-rank journal prefixes covered by this checkpoint |
| `new_updates_since_anchor` | Sum of verified committed descendant updates; excludes undocumented historical work |
| `source_parent_decision_ref` | Already existing decision authorizing the input parent for this intent; the later decision about this child is external and never embedded in its checkpoint-bound lineage |

Identifiers use domain-separated SHA-256 over canonical UTF-8 JSON payload bytes: recursively sorted object keys, preserved array order, canonical integer encoding, fixed escaping and no duplicate keys. Identity records use integers or strings rather than floating-point counters; invalid hashes, unknown enum values, duplicate fields and noncanonical encodings fail closed. A record's own ID and signature envelope are outside the hashed payload, preventing self-referential hashes. Existing historical byte identities remain unchanged. A bridge record relates old and new identities; it does not rename the old checkpoint.

**Four modes must remain distinct.** Exact resume continues the same frozen intent after interruption: identical input closure, objective, optimizer recipe, sampler/RNG convention and qualified partition. Corpus continuation opens a new intent with new eligible replay while carrying a compatible optimizer epoch; it is not exact replay of the preceding intent. A weight warm start copies bound parent model bytes, creates a new optimizer epoch at zero and records every reset. Architecture migration additionally carries an exact parameter-mapping/initialization receipt and its qualified output equivalence or intentional difference. Neither reset mode may synthesize optimizer moments or label a 60,000-step ancestor as a new optimizer at 60,000.

Lineage verification traverses immutable edge metadata to a trusted anchor, checking cycles, counters, duplicate commit credit and unknown roots. Bound traversal and use authenticated ancestry certificates that preserve verified transition/commit metadata, not unverified narrative. Parent lineage and commit metadata remain essential proof. Ancestor weight/optimizer/corpus bodies are strong references only while required by a declared restart, rollback, exact-retraining or claim-reproduction promise; superseded payload links otherwise become provenance-only under the retention protocol. An ancestry certificate does not silently revoke a promised reproduction mode. Record hardware-independent identity separately from the numerical determinism profile used for replay.

### 5.6 Atomic update, checkpoint and recovery semantics

Extend the existing `parallel.checkpoint_commit.v2` mechanism with a new complete commit-format version carrying lineage and intent bindings. Do not rewrite historical `state.json` files. The existing loader dispatches by format and treats old checkpoints according to their original resume eligibility. New sidecars such as `lineage.json` and `training-intent.json` are required objects in the new format, with checksums bound by the state manifest.

The commit order remains: durable rank consumption prefixes; all required checkpoint objects written into a private staging directory; state manifest binding those objects; full loader-equivalent verification; fsync objects/state/directory; rename complete checkpoint; fsync parent; uniquely staged latest-pointer write; atomic rename; fsync run directory; durable journal commit acknowledgments. Checkpoint publication must cover one common applied update boundary across all required ranks. A missing rank cannot be replaced by a smaller world size without a new verified partition/intent.

The three accounting classes remain distinct:

| Class | Meaning | Recovery and budget treatment |
|---|---|---|
| Computed | Forward/backward and attempted optimizer work physically performed | Always charged, including retries and rejected work |
| Applied | Update changed in-memory parameters at the expected step | May be lost after interruption; never presumed durable |
| Committed | Complete published checkpoint covers the update and journal prefix | Counts toward lineage learning exposure exactly once |

A crash after an in-memory update but before complete checkpoint publication restores the last complete checkpoint and re-executes from its sampler/RNG cursor. The repeated physical work is charged again; the final logical update is admitted once. A crash after checkpoint publication but before the journal's commit event is resolved using the verified checkpoint and its bound applied prefix, as `consumption::reconcile` already supports. It may record a missing acknowledgment; it must not rerun an already committed update or invent missing applied work. [Current reconciliation](https://github.com/neverhuman/jopedime/blob/5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc/crates/jope-engine/src/training/consumption.rs#L664-L710).

Use the existing native admission/lease fence as the single-writer execution authority. Preserve current behavior that may save an attempt-local recovery checkpoint after control loss and then stop; saving completed numerical work does not grant adoption. A stale attempt cannot advance an eligible research/serving/global authority root. A shared local latest pointer, if used across attempts, needs an explicit new fencing check; retain separate attempt-local complete checkpoints and expose their unaccepted status. Reject divergent eligible-pointer ancestry and preserve both attempts for diagnosis. No repair path edits historical journals or optimizer files to fit a desired story.

Remote durability is a subsequent explicit state. Reuse `jope-learning` progress outbox/mirror/publish mechanisms: immutable children first, exact checksum/version readback, manifest last, conditional pointer publication. A locally committed checkpoint may support an allowed local resume; if the campaign requires remote closure, it remains `LOCAL_COMMITTED_REMOTE_PENDING` and cannot become a qualified research-parent/serving claim until that requirement passes. S3 listing and derived indexes are not commit authority.

Every `CommittedUpdate` progress event uses an idempotency key derived from checkpoint/intent/parent IDs. Replaying an outbox acknowledgment must not increment learning counters. Checkpoint-bound consumption prefixes end before their own checkpoint-referencing commit acknowledgement, avoiding a hash cycle. Missing capsule publication can be retried from committed evidence without rerunning training. Rollback changes an accepted reference; the rollback operation itself does not delete the rejected child or rewind the ledger. Later retention may reclaim eligible child payloads under their declared obligations.

A clean-host restoration must require only a verified root manifest, the retained required objects and authorized credentials. It reproduces corpus/intent closure, model and optimizer, declared sampler/RNG continuation, child export and machine summary without access to the previous host's mutable indexes. Exact numerical equality is required only within the pinned determinism profile; a changed device/backend requires the documented numerical qualification, not an invented bitwise guarantee.

## 6. GP language, program invention, and evolutionary search

### Preserve the language that already works

The existing `GenomeIr` represents pipelines, symbolic expressions with fitting conventions, and portfolios. The kernel `Program::LegacyV1` carrier preserves exact AST and f64 bits; the intentionally lossy historical printer is not a safe identity function. The registry separates stable wire IDs from semantic keys, includes aliases and parameter metadata, and distinguishes executable/generatable/compatibility/quarantined states. Kernel capabilities further distinguish grammar reachability, numerical faults and emitter support. This is a substantial foundation to extend. [C13] [C14] [C15]

The present 53-entry legacy operator table has 35 generatable entries, 11 compatibility entries and seven quarantined entries. These are registry lifecycle counts, not a promise that every entry is reachable in every neural grammar or supported by every export backend. The appendix lists all 53. V2 reserves wire IDs 53–75 and function IDs beginning at 19; a reservation is not permission to generate or execute it through an arbitrary route. Several explicit scalar and ordered-state implementations exist separately. Capability admission must follow the full route that the search profile actually uses. [C14] [C15]

The immediate language gap is therefore **coverage and compositionality under verified semantics**, not a blank syntax. Examples include runtime-supported column indices above seven that remain outside the baseline symbolic grammar, runtime-only functions, separately implemented scalar/ordered routes, and advanced evolutionary policies that are not active in ordinary selection. A generated capability report should show the exact route rather than flatten all of these into a yes/no operator list.

### The capability contract

Extend `feat-math::kernel::capabilities` as the single source of operator admission facts. An operator/capability row must expose:

| Contract field | Meaning |
|---|---|
| Semantic identity | Stable semantic key, wire/version namespace, aliases, implementation revision |
| Type and shape | Input/output kind; column/row/time axes; symbolic size relation; nullability and dtype |
| Parameter domain | Integer/enumeration/continuous/log-scaled domain, default, explicit search bins or density, constraints and encoding |
| Fit effects | Train-feature read, label read, fitted-state write/read, RNG, row/time dependencies, and whether cross-fitting is required |
| Numeric policy | Domain projection, division threshold, saturation, overflow, NaN/Inf, signed zero, reduction order and backend tolerance |
| Search support | Complete-program sampling, typed insertion/replacement/deletion, mutation/crossover, neural tokens/pointers, refinement |
| Runtime support | Interpreter, accelerated path, fitting route, cancellation points, memory/iteration bounds |
| Export support | Recipe and fitted-state support separately for each backend, with exact fixture/qualification references |
| Lifecycle | Reserved, parse-only, runtime-only, experimental-generatable, qualified-generatable, compatibility or quarantined |
| Provenance | Code/license/weights/input dependencies and accepted numerical/source evidence |

Derive legality masks, parameter validation, documentation and test enumeration from this row. Do not generate executable numerical semantics from metadata. Each backend still needs an implementation and differential evidence. Fail a proposed search profile at construction if a reachable operator has no admitted fit/predict route or required export route. A profile can explicitly allow no export for research, but cannot later relabel those outcomes as deployable.

Add a `capabilities --profile ... --format json` command through the existing CLI ownership, with deterministic output and digests. It must report missing proof and runtime-only functionality, not silently omit it. A profile digest includes this effective capability closure, its grammar, tokenizer, shape limits and numerical policy. Changes create a new profile version and invalidate incompatible caches/likelihood assumptions.

### A staged expressivity ladder

| Stage | Program class | Initial change | Gate to proceed |
|---|---|---|---|
| A: current forms | Pipelines, expressions, portfolios and existing fitted learners | Complete capability mapping, consistent identities and search profiles; neural feature pointers are a later P1 ablation | Existing behavior preserved; no mislabeled reachability or export |
| B: compositional graph | Shared pure feature subgraphs, explicit branches/feature union, typed learner outputs | Add an opt-in `Program::GraphV1` family with one canonical graph contract | Fold/effect checks, bounded expanded cost, cross-backend differential tests |
| C: fitted graph | Reusable fitted transforms, OOF predicted features, sparse/robust heads, nested ensembles | Explicit fit-state slots and cross-fit nodes; conventional solvers first | No fit/validation leakage; faithful refit and emitted state |
| D: learning procedure | Bounded initialization, update and prediction procedures | Small approved tensor/scalar update vocabulary and statically bounded loops | Real isolation, cancellation, memory/fuel bounds and transfer beyond proxy tasks |
| E: learned library | Versioned macros and reusable fitting procedures discovered across tasks | Abstraction mining and transfer-conditioned library admission | Search savings and independent-family benefit after definition/training costs |

The graph name above is a proposed semantic schema `jope.program-graph/v1`; it does not reuse the current V2 reservation bytes or imply it is the existing grammar called V3. Reserve a new carrier discriminator through the current codec only after the compatibility tests exist. Keep reader-first migration: new readers can describe and reject unsupported graph features before any actor generates them.

### Concrete graph representation

Use a typed acyclic graph with an ordered set of entry points. Initial graph nodes are pure feature expressions or explicit fitted operator calls; later fitting procedures introduce bounded control regions. Proposed conceptual types are:

~~~rust
enum ValueType {
    Scalar(DType),
    Column { dtype: DType, rows: RowAxis },
    Table { dtype: DType, rows: RowAxis, width: WidthExpr },
    Mask { rows: RowAxis },
    FeatureIndex { source: SchemaId },
    Parameters { shape: ShapeId, scope: FitScopeId },
    FittedState { operator: SemanticKey, scope: FitScopeId },
    Prediction { rows: RowAxis, target: TargetSchemaId },
}

struct GraphNode {
    op: SemanticKey,
    inputs: Vec<NodeId>,        // order is semantic
    parameters: CanonicalParameters,
    output_type: ValueType,
    effects: EffectSet,
}

struct ProgramGraphV1 {
    registry: RegistryDigest,
    inputs: InputSchema,
    nodes: Vec<GraphNode>,
    fit_entry: EntryId,
    predict_entry: EntryId,
    resource_bounds: StaticBounds,
}
~~~

This sketch fixes ownership and distinctions; production structs must follow the repository's exact serialization conventions. The canonical encoder uses stable operator IDs, deterministic node numbering from ordered roots and input edges, explicit shared references, fixed integer encoding and exact float-bit strings. Preserve operand order even for apparently commutative operators: floating-point behavior, effects and historical identity can depend on it. Do not sort arrays except fields explicitly declared mathematical sets. Reject cycles, unknown features, invalid lengths, non-finite learned constants where forbidden and multiple mutable writers before execution. Bound nesting, node count, expanded macro count, table width, stored training rows, state bytes, loop count and total fuel.

Graph identity means equality of canonical structure under the same registry/numerical version; it is not a complete semantic-equivalence test. A legacy import keeps its legacy identity and adds a graph bridge record; it must not rewrite old hashes. A graph with a shared fitted node and a graph with independently fitted copies may differ statistically even if their text looks similar. Fit randomness and scope determine whether sharing is valid.

### Effects and fold locality

Associate every fit invocation with `FitScopeId = hash(dataset, split, training_row_set, fit_policy, seed)`. A node's fitted-state type carries that scope. Prediction accepts new features under the fitted schema; it cannot access current prediction labels. It can read stored training state where the algorithm legitimately requires it, such as kernel training points, within declared storage/resource limits.

Use a small effect algebra: `ReadFeatures(scope)`, `ReadLabels(scope)`, `FitState(scope)`, `ReadFittedState(scope)`, `Random(stream)`, `OrderedRows(axis,boundary)`, and `Pure`. Infer required effects bottom-up from operator signatures, unify row/column axes, then verify entry-point privileges. A pure branch can be shared; a stateful branch requires an explicit sharing policy. `predict` must have no label-read or fit-state-write effect. A time-series node needs an ordered axis and declared fold-boundary state reset; ordinary exchangeable regression must not accidentally gain access to later rows.

Supervised feature selection fitted on the allowed training fold can transform that fold normally. Target encodings and predictions used as training features require OOF or an explicitly justified independent training partition so each row's label cannot trivially encode itself. An `OOFPredict` node consumes a learner recipe and cross-fit plan, creates training features through fold-local fits, and records the full-data refit used at inference. Ensemble meta-weights fit on those OOF features. Never reuse an in-sample prediction vector as an OOF vector because its dimensions match.

A small example of the intended distinction:

~~~text
train_features = FeatureUnion(
    TransformFitApply(ImputeMedian, X_train),
    OOFPredict(Ridge(alpha), X_train, y_train, crossfit_plan)
)
head_state = Fit(ElasticNet, train_features, y_train)

predict_features = FeatureUnion(
    TransformApply(saved_imputer, X_new),
    Predict(saved_full_train_ridge, X_new)
)
y_hat = Predict(head_state, predict_features)
~~~

No backend may lower `OOFPredict` into an in-sample fit-predict shortcut. The fitted export must contain the full-train model and preprocessing state required for prediction; the OOF evidence remains a fitting receipt dependency. Cross-fitting improves the validity of stacked training features but does not replace the independent outer judge used for model selection claims.

### Numerical behavior is part of the algorithm

Use the existing fault taxonomy and numerical policy. Protected division, projected square root, clamped exponentials and invalid clip bounds are semantic choices, not merely implementation details. Store fault counts/rates and denominators by operator, row and phase, with safe aggregate bounds. Hard faults reject; soft projections may be admissible under a versioned penalty/threshold. Never turn a numerical failure into a finite success score by globally coercing NaN to zero. [C15]

For each operator/backend pair define one of: exact integer/bitwise semantics, a proved implementation equivalence, or a declared absolute/relative/ULP error envelope over a specified domain. Establish task-level prediction tolerances separately because local errors can amplify through a program. Strict byte identity is appropriate for serialized parameters; universal one-ULP equality is not an honest promise for all nonlinear backends/hardware.

The quantile correction deserves a dedicated release. Build a caller census for recipe and fitted emission, add the historical near-tie counterexamples, preserve legacy goldens, and introduce an explicit numerical/emitter profile enabling the partition-point-compatible implementation. Fit and predict on each supported backend; compare intermediate bins and final predictions. Promote the new default only through the release mechanism, with old policy IDs still loadable. [C17]

Equality saturation can be a later extraction optimization. Specify eager/lazy evaluation and observable fault/admission behavior first; include `MayFault` and diagnostic effects in rewrite analysis. Begin with dead-node elimination or common-subgraph reuse only when the removed/shared computation is total and nonfaulting, or when a proof preserves the relevant fault counts, projections and admission observations as well as predictions. Scope must match. Do not assume associativity, `x/x = 1`, `x*0 = 0`, eager/lazy branch equivalence, or identities for protected functions. Prediction equivalence does not authorize reuse of measured runtime or memory. Approximate simplification creates a different candidate requiring exact evaluation. Semantic probe hashes help prioritize duplicates and diversity; they do not authorize exact result reuse. [R33]

### Genetic operators and the neural interface

Keep the existing evaluator and variation interfaces. Add a versioned `VariationDecision` with parent IDs, operator ID, edit site(s), changed parameters, repair steps, random-stream position, proposal origin and known probability fields. Separate generation-zero seeds from later edits and crossover. A conditional neural editor predicts:

`p(operator | context, parent, budget) × p(site | operator, structure) × p(arguments | legal type/shape context)`.

Any sampled parent-selection probability and continuous-parameter density are separately recorded. The legal mask precedes normalization. Continuous parameters use a declared bounded transform and density/Jacobian when the training objective needs a density; discrete search bins remain a strong simpler baseline. Deterministic LM refinement has no invented policy density.

Initial variation supports typed insertion, subtree replacement, deletion that reconnects a valid input, argument mutation, matched-type subtree/DAG crossover, bounded constant perturbation and restart. Pure subgraph crossover cannot copy mutable fit state from another fold. Repair is bounded, logged and charged; reject if repair materially changes the proposed action beyond the allowed contract. Store the original and repaired candidate identities so a policy does not receive credit for a different algorithm manufactured by repair.

Generation zero should mix neural, retrieval and generic sources through a frozen profile. An initial experimental mixture may allocate 50% neural, 25% retrieval and 25% generic proposals; missing sources fall back under a declared rule and remain separately labeled. These are proposed ablation settings, not changes to the current product's slot defaults. Always retain a nonzero generic exploration share during learned allocation. Compare generation-zero-only seeding, periodic neural injection, every-generation injection and learned mutation under matched total compute. [R23]

Constant fitting uses the existing coordinate/LM/guarded machinery. Optimize constants on allowed training partitions, select structures on inner validation, and refit the frozen winner according to the same recipe used by the judge. Bound numerical solve work and include it in search cost. Multiple constant initializations are multiple physical evaluations/solver attempts; retain failures and reject non-finite state. Compare variable projection or exact linear solves for linear-in-parameter substructures before sending those degrees of freedom to an RL policy.

### Selection, diversity and bloat

Treat current epsilon-lexicase and Pareto code as available implementations with specific profiles. The kernel2 Pareto archive currently publishes evidence without controlling parent/survivor selection. Add an explicit selection-policy interface and activate one policy at a time: tournament/elitism, epsilon-lexicase, then an age/diversity-aware archive. Do not credit a stored archive with selection behavior it does not yet exercise. [C16]

A first QD experiment should be small: two frozen behavior descriptors, eight bins each, at most two nondominated representatives per occupied cell, and a hard 128-member archive cap. Example descriptors are normalized feature sensitivity sparsity and nonlinear-response magnitude on fixed training-only probes; choose ranges on meta-development data. Complexity and measured cost remain Pareto dimensions, not arbitrary descriptor labels. This is a concrete starting configuration, not a claim it is optimal.

Descriptors carry version, probe-set identity and validity flags. Change the descriptor definition only between waves; rebuild/reindex the archive and preserve old membership receipts. Approximate behavior collisions can compete for an archive slot, but exact program/evaluation identities remain distinct. Protect a bounded set of rare failure and boundary examples outside the deployable-elite archive.

Charge expanded DAG operations, fitted-state bytes, wall/CPU cost and effective degrees of freedom where measurable. Macro token count alone is not a complexity measure. Use a transparent size cap and Pareto selection before dynamic multi-objective penalties. Preserve useful stepping stones with age and niche diversity, while avoiding indefinite retention of every ancestor.

For measured descendant productivity, spawn prespecified matched-budget continuations from sampled parents, compare gains over each parent's baseline, and report both direct and descendant contribution. For crossover, credit relative to the stronger parent's starting utility and retain both-parent ancestry; that is a declared attribution convention, not a causal proof. Strong causal claims need randomized parent/operator treatments. Do not reward a lineage just because later work had a larger budget.

### Learn allocation before adding a planner

Begin with a fixed source/operator mixture and measured continuation tables. The next allocator can rank candidate actions by a distribution of marginal gain per incremental cost, conditioned on task, program structure, archive state and remaining budget. This label is obtained from actual bounded continuations, not from the program's present score. Compare against equal allocation, simple cost-based heuristics and the existing classical shadow-surrogate style.

A minimal stochastic operator experiment can use an explicitly versioned EXP3-style scheme: weights start at one; over a fixed set of `M` admitted operator families use `p_i=(1-gamma)w_i/sum(w)+gamma/M`; after completion update `log w_a <- log w_a + eta*g/(M*p_a)` for the chosen operator. Define bounded `g=clip(max(0,delta_utility)/(gain_scale*max(cost,cost_floor)),0,1)` before importance weighting, with positive cost floor and frozen gain/cost units. Algorithmic failures receive zero gain and incur their actual cost; unresolved infrastructure failures follow a declared missing-update rule. Store each pending decision until its delayed outcome resolves; do not retrospectively change the probability. Freeze gamma, eta, resets, scaling and available sets, and use log-space normalization. EXP3 addresses adversarial rewards, but unequal durations, endogenous future search states and policy-regret interpretation prevent importing its guarantee unchanged here. Changing legal arm sets requires a separately tested sleeping-arm adaptation. Start with gamma=0.20 in development and reject an allocator that loses to the fixed mixture at equal cost. [R70]

Do not let low-fidelity screening become an invisible source of false negatives. Calibrate rank preservation between rungs on development data, retain the exact screening decision, and promote a randomized minimum sample of rejected candidates to the next/full fidelity. Use their recorded selection probabilities for the specific audit estimator. An uncertainty score that is poorly calibrated on unseen families should reduce screening aggressiveness, not justify more confident pruning. Hyperband/BOHB are useful controls for this allocation problem. [R38] [R39]

### MCTS only after the cheaper controls work

Add exact-transition MCTS if typed partial programs or edits produce reusable, informative continuations and a measured critic can guide them. The first PUCT implementation backs up single-player utility with no alternating sign:

`select a maximizing Q(s,a) + c_puct P(s,a) sqrt(sum_b N(s,b)) / (1 + N(s,a))`.

Define `Q` as expected remaining undiscounted return from the transition reward in the scientific protocol, including search cost exactly once. Do not interchange current terminal utility and remaining-return targets. At a new node, expand first; use first-play urgency equal to the frozen leaf baseline, select the first child by largest prior with a canonical action-ID tie break, and then apply the displayed PUCT score. Do not count simulated evaluator predictions as measured improvements. Distinguish exact terminal outcomes, heuristic leaf values and surrogate outcomes in backup telemetry. A quality head predicting current candidate error is not automatically a continuation-value head.

Progressive widening can initially expose `min(number_of_legal_actions,64,ceil(4 × (1+N(s))^0.5))` children, with reproducible proposal order and explicit probability support. The cap defines a restricted sampled support for that node; teacher targets record it and do not claim to cover every grammar action. Compare with beam/best-first search and independent restarts at equal full cost. Gumbel root planning is a separate low-simulation-budget ablation after this baseline exists. [R02] [R06] [R25]

The transposition identity must include task/evaluator/split, program/partial program, remaining budget, relevant evaluation history, support/library/profile/critic versions and stochastic state where it affects the transition law. If two states share only program identity, share an eligible exact execution cache entry, not search visit counts or future value. Never let an online critic update silently change value semantics inside a frozen wave. Bound tree memory and persist enough lineage to reconstruct teacher targets; prune search caches under their separate reconstructible-data policy.

Stop investing in the planner if two adequately powered development studies show no useful benefit against the best simpler searcher after charging inference and tree overhead. MuZero-style learned syntax dynamics is not a prerequisite: the program language already supplies exact transitions. Learning expensive outcome and continuation distributions is the higher-value modeling target. [R05]

### Bounded fitting code and deployment

Stage D searches `init`, `update` and `predict` regions over approved primitives. Begin with small state vectors and linear/feature-space learners, a maximum update count known before execution, deterministic iteration over permitted training batches and a bounded conventional loss-gradient primitive. The controller can invent combinations, step schedules or state recurrences; it cannot read judge labels, call the network, launch processes, access arbitrary files, load foreign functions or create unbounded recursion.

Prefer a reference interpreter or constrained bytecode/WASM target with explicit host capabilities. Combine fuel/shape/state limits with process isolation, resource enforcement and a kill path; cgroups alone do not confine hostile same-UID code, as the current execution module correctly states. Generated source is emitted only after IR verification and compared with the reference semantics. Do not execute arbitrary LLM-written code in the trusted fitting worker. [C19]

Each deployable artifact contains program and fitted-state identities, necessary preprocessing, dependency/version manifest, input/output schema, numerical policy, supported backend, prediction-resource measurements and exact provenance. Recipe export means the algorithm can be refitted; fitted export means the already trained state predicts faithfully. Both deserve independent capability fields. A model with an external foundation dependency must state that dependency rather than claim portable standalone code.

## 7. Research design: transferable algorithm search with a measurable learning loop

This section translates the most relevant primary research into changes for the audited repository at commit **5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc**. References R01–R70 identify the primary-paper bibliography accompanying the specification. Research establishes the cited mechanisms in the authors' settings; proposed JopeDime adaptations require the experiments below. The method map covers the families that materially affect this design, rather than promising an exhaustive inventory of reinforcement learning.

### 7.1 Research order follows the source diagnosis

The current implementation and evidence are established in section 2; the executable continuation contract is specified in section 5. The research sequence follows those findings: prove useful fresh supervision reaches the existing native trainer; test a critic that represents program order; then evaluate transferable search improvement and richer search decisions. The separate historical PolicyLM, CLOVER fixture and accepted native architecture retain their own identities throughout. A lower training loss or a positive shadow-selector result earns a better prospective experiment, not an independent deployment claim.

### 7.2 The exact AlphaZero and Expert Iteration translation

#### 7.2.1 What the “game” is

For ordinary tabular regression, the natural problem is **single-player, contextual, budgeted program search**. An opponent is unnecessary: predictive quality is estimated against data under an evaluation protocol. A frozen archive can supply competitors and diversity references, but changing their identities must not silently redefine historical reward.

AlphaGo combined expert initialization, reinforcement learning and search [R01]. AlphaGo Zero used self-play outcomes and search-improved action targets [R02]. AlphaZero reused a learning/search framework across several games while retaining each game's rules [R03]. Expert Iteration isolates the transferable mechanism: expensive search improves decisions, supervised learning amortizes those improvements, and the apprentice improves subsequent search [R04]. JopeDime's direct analogue is the measured-program-to-corpus-to-trained-policy path already present in native_loop.

Section 4 defines the exact state, data access, utility, cost and independent judge endpoint. Preserve the single-player maximization convention: no alternating-player sign inversion belongs in regression search backup. Historical-policy comparisons can reveal weaknesses, but direct held-family error/cost measurements remain the primary evidence.

#### 7.2.2 How the self-play improvement mechanism actually works

In AlphaGo Zero, one network predicts an action prior and a value from a board state. Tree search combines that prior, backed-up values and exploration to choose stronger moves than a single network sample. Self-play records state, search action distribution and eventual game result. Training then fits both the search distribution and outcome. A schematic objective is `L=(z-v_theta(s))^2 - sum_a pi_search(a|s) log p_theta(a|s) + c||theta||^2`. This couples a learned value with a policy-improvement target; winning more games is the outcome, and policy/value losses are training signals. The original AlphaGo Zero recipe gated a new best player through match evaluation. AlphaZero later used a continuously updated network for self-play rather than that separate best-player gate. Those are distinct training protocols, not interchangeable definitions of self-play. [R02] [R03]

For JopeDime, exact program execution substitutes for game-rule simulation and supplies statistical performance measurements. GP or typed search can supply the improved teacher. The program scorer predicts present performance; a continuation-value model predicts what additional search can achieve. Keep those targets distinct. A complete-program proposal with one measured reward can be treated as a contextual bandit; edits with history, remaining budget and future consequences define a sequential decision problem. Use the simpler formulation until the logs and experiments establish value in the sequential one.

The eventual feedback loop therefore has two independently tested improvements: search must produce useful supervision beyond the raw policy, and training must turn that supervision into better future search. An archive-only improvement can satisfy the first without the second. Expert Iteration is the clearest organizing principle for these checks. [R04]

#### 7.2.3 Search improvement and policy learning are different objects

The immediate Expert Iteration loop should freeze one actor checkpoint, search policy and training-role task roster; run exact evaluations and GP continuations; materialize eligible supervision; train through the existing native authority; and compare the child with the frozen parent and strongest simple control on independent families at equal deployment cost. Use the current fresh-sampling and consumption paths to prove actual uptake. A changed checkpoint digest alone is insufficient: decay can change parameters that received no useful supervised signal.

For a genuine MCTS implementation, the search can provide an improved action distribution at a state. With legal action set A(s), counts N(s,a), positive temperature τ and at least one visit, the conventional count target is:

~~~text
π_search(a|s) = N(s,a)^(1/τ) / Σ[b in A(s)] N(s,b)^(1/τ)
L_search = -Σ[a in A(s)] π_search(a|s) log p_θ(a|s)
~~~

This is a valid supervised target only for the search state and action support that produced those counts. If search uses a different policy-improvement operator, record that operator and its target rather than relabeling it as count distillation. Legal masks, temperature and grammar identity are part of the distribution.

Population GP does not automatically supply MCTS visit counts. Its useful targets are complete selected programs, measured parent-to-child edits, matched sibling preferences, and successful continuations. Complete-program teacher forcing is legitimate supervised learning. Advantage-weighted likelihood is a plausible next experiment [R10]. Neither is an on-policy PPO trajectory. With crossover, preserve both parents and the edit sites; crediting all downstream improvement to one neural seed is an approximation.

Compare beam/best-first exploration and independent GP restarts before adding tree infrastructure. MCTS earns its cost when partial states or edits share valuable continuations, not merely because AlphaZero used it. Exact transitions, legal-action factorization, transposition keys and batched evaluator work must remain auditable. Search-budget accounting includes surrogate calls, neural decoding, constant fitting and failed evaluations.

Gumbel planning addresses policy improvement under limited root-action visits and is a useful later comparison [R06]. Its theoretical conditions do not become a guarantee for noisy, shifting regression surrogates. MuZero's learned dynamics are lower priority because program transitions are already known [R05]; learn expensive evaluation and the value of extra computation first.

AlphaTensor and AlphaDev are closer “algorithm game” analogies because they construct executable algorithms in single-player settings [R07] [R08]. Their correctness targets are much more sharply verifiable than statistical generalization. JopeDime needs both executable correctness and independent predictive evaluation.

### 7.4 What neural GP research implies for the language and evolution

#### 7.4.1 The contribution must exceed neural generation-zero seeding

Deep Symbolic Regression uses risk-seeking policy gradients over expressions [R26]. NGGP directly studies neural population seeding [R23]. uDSR combines several symbolic and neural search ingredients [R24]. DGSR-MCTS combines dataset-conditioned neural proposals, search and learning from successful experience [R25]. NeSymReS and end-to-end symbolic transformers show the relevance of synthetic program pretraining and subsequent numerical refinement [R27] [R28].

The defensible advanced contribution is therefore **a transferable policy for discovering verified statistical learners, with measurable improvement across research waves and bounded scientific memory**. Demonstrate a better search decision under a fixed budget on a new task family. More generated syntax, a larger archive or a better fit on the same tables is insufficient.

Distinguish three expressivity levels in every claim: selecting/composing a predictor; discovering a parameterized expression with conventional fitting; and discovering the learning procedure itself. AutoML-Zero's setup/predict/learn representation illustrates the third level [R21]. Expanding JopeDime toward that level should retain bounded execution, train-only fitting, explicit state and separate prediction. This is a versioned extension to the existing language, not an immediate replacement of all supported IRs.

#### 7.4.2 Prior-art lessons for the evolutionary design

The concrete type/effect checks, variation operators, OOF semantics, resource charging, archive limits and macro admission are specified in section 6. Their research implications are testable: NGGP motivates a coupling-frequency ablation [R23]; epsilon-lexicase and MAP-Elites motivate specialist/diversity controls [R31] [R32]; DreamCoder motivates transfer-qualified abstractions [R22]. Equality saturation is relevant only where the executable numerical contract justifies a rewrite [R33]. None of those results establishes that simultaneously adding every mechanism improves this searcher. Stage them so a negative outcome has an interpretable cause.

### 7.5 Stage architecture, losses and optimizer changes

#### 7.5.1 First architecture: make ranking understand the program

Keep the accepted decoder and current mean-pool ranker as frozen controls. The first challenger should change only the critic's program representation: token and position information, typed argument roles and basic structure, using a small sequence or structural encoder. A two-layer critic is an initial experimental configuration, not a literature-established optimum. Compare a lightweight recurrent/sequence alternative and explicit structural features before assuming graph attention is necessary.

Include valid token-multiset collision fixtures with different semantics, and test disjoint program families. Reusing decoder states may save weights but can increase ranking latency or couple unrelated gradients; measure it as a separate variant. Version architecture and export identity, and establish native/Candle parity before using a changed model through product inference.

The current four reward heads are not automatically a calibrated uncertainty ensemble. Compare independently trained or bootstrapped models as a practical uncertainty control [R42], then measure calibration and acquisition regret on new families. Add failure probability and continuation-gain heads only after their labels exist. An execution failure, a scheduler cancellation and a completed poor predictor are different observations.

#### 7.5.2 Dataset encoders: compete against inexpensive information

EXP-018 makes a classical contextual surrogate a mandatory control. Retain dataset statistics and program features as a cheap, auditable starting point; test whether learned representations add useful interactions beyond these features. Compare existing context, train-only sketches plus MLP, Deep Sets, then Set Transformer if set interactions improve held-family search [R47] [R48]. A Perceiver bottleneck is a scaling option after input cost becomes measurable [R49].

For exchangeable rows, test row-permutation stability with randomness controlled. For columns, require consistent remapping of feature references rather than arbitrary invariance that loses feature identity. Grouped and temporal tasks need their dependency structure preserved. Imputation, normalization, target transforms, feature filtering and any target-supervised encoder must fit only their permitted training roles.

Separate two benchmark questions. **Search-controller surrogates** predict which program to evaluate. **User-task predictors** solve the regression problem directly. A strong surrogate does not imply a strong end predictor, and TabPFN does not automatically become the correct dataset encoder.

Include tuned tree ensembles, ridge/elastic baselines, a modest MLP/ResNet, FT-Transformer and TabM as relevant direct-prediction competitors. FT-Transformer and numerical-feature embedding research show why preprocessing and input representations deserve controlled attention [R51] [R52]; TabM strengthens the case for economical ensemble designs [R53]. TabPFN's 2025 Nature work includes regression on small tabular data [R50]. Pin the evaluated implementation and supported workload; do not extrapolate its paper's scope to every table or treat publication-era dimensions as permanent product limits. XGBoost remains a necessary established tree baseline [R54].

Evaluate the later TabPFN-2.5 release as a separate, pinned baseline [R67]. Its November 2025 report expands the stated supported scale to 50,000 rows and 2,000 features. These are that release's stated scope, not a guarantee of superiority or an instruction to reuse vendor win rates as JopeDime measurements. Record weights, software, preprocessing, inference configuration and resource budget for the version actually compared.

#### 7.5.3 Preserve the actual objective, then change one hypothesis

The native objective is already identity-bound:

~~~text
L_current = 1.00 L_sequence
          + 0.25 L_BradleyTerry
          + 0.10 L_listwise
          + 0.10 L_runtime
          + 0.05 L_contextfree_BradleyTerry
~~~

The runtime term is Huber on log1p seconds. Stability and loss-log-variance terms have zero coefficients; they are not evidence of learned stability or adaptive loss balancing. These are source facts from [training/objective.rs](https://github.com/neverhuman/jopedime/blob/5b8b8d56b4ff2458c97486c2ba6f1ebcd9a887bc/crates/jope-engine/src/training/objective.rs). Preserve this baseline while fixing representation.

Next compare sequence weighting, pairwise versus listwise supervision, and calibration separately. Ranking comparisons must share dataset, split, preprocessing, evaluator and comparable fidelity; runtime comparisons also require hardware context. Model uncertainty or explicitly tie differences too small to support a reliable ordering. Preserve every component of the objective vector so changed user preferences can be evaluated without inventing old measurements.

An advantage-weighted generation experiment can use nonnegative, capped weights derived within a matched context, normalized over eligible examples. Specify whether the target is a sampled whole program or a conditional edit; report effective sample size and whether a few champions dominate. Search-distribution distillation, selected-program imitation and on-policy reinforcement learning remain separate objective types with different admission conditions.

For runtime censoring, let T be latent completion time, c the stopping threshold, y=min(T,c), and δ indicate observed completion. Under a specified continuous runtime distribution and censoring independent of T conditional on recorded context, a proposed likelihood is:

~~~text
L_time = -δ log f_θ(y | context)
         -(1-δ) log S_θ(c | context)
~~~

Timeouts provide survival information, not an ordinary completed-time target [R41]. Performance-based pruning can be informative censoring; condition on stopping history or use a justified alternative. Worker loss may describe infrastructure reliability rather than algorithm runtime. Apply per-head eligibility masks; never create a low regression-quality label for an unmeasured program.

Learned task-loss weights [R43] do not infer the user's preferred accuracy/latency tradeoff. Likewise, a quantile head or feasibility classifier earns adoption through improved decisions and calibrated errors, not simply an extra decreasing training curve.

#### 7.5.4 Optimizers: explicit lineage before fashionable replacements

The current custom AdamW already has scalar and fused FP32 paths, fixed continuation parameters and bound state. Introduce a versioned optimizer recipe only when experimenting with schedules, clipping, parameter groups or precision. It must identify betas, epsilon, decay groups, schedule state, backend arithmetic and reset/continuation policy. A recipe change requires a weight warm start or verified migration; it is not exact continuation by assertion.

AdamW is the baseline [R55]. Test modest schedule and decay-group changes with architecture/data/objective fixed. The inspected baseline decays every parameter with a defined gradient, so excluding biases or normalization scales is a substantive change. No optimizer receives credit merely because checkpoint hashes move.

Lion, Shampoo, SAM and Muon are optional comparisons [R36] [R56] [R57] [R58]. Match total wall time and memory, including extra gradient passes or preconditioner work. Evidence from large language models does not establish Muon's superiority for a mixed decoder/MLP controller. Learned optimizers [R34] [R35] belong in a separate meta-training cost ledger and must transfer across horizons, model families and tasks. Keep controller optimization distinct from the inner solver used to fit constants or candidate-model parameters.

### 7.6 Eight falsifiable experiments

Every experiment must predeclare an effect size that matters, budget, family-level comparison unit, handling of failed/missing arms, uncertainty procedure and stop/adoption rule. Choose sample size from the observed paired-family variance and desired precision; an arbitrary fixed number of seeds is not a power argument. Repeated tuning uses development families. Reserve independent final evaluation for a limited, explicitly governed decision [R44] [R45] [R46].

#### E1. Does the existing native loop close causally?

**Hypothesis:** new measured training-role programs change consumed supervision and useful gradients, producing a verifiable child that can continue and undergo independent comparison. Exercise accepted60000→warm-start3000→continued6000→a successor through the new ancestry contract. Use existing approved training windows and miniature fixtures for CI. Record source closure, fresh-example consumption, active-gradient evidence and inference parity. A decay-only or zero-new-supervision control must be distinguishable. **Falsifier:** the loop runs but fresh labels do not affect supervised updates, the child cannot bind through the intended inference route, or continuation loses identity. This earns integration evidence before any claim of superior predictions.

#### E2. Does an order-aware critic improve acquisition?

**Hypothesis:** structure distinguishes materially different programs that the mean-pool representation aliases. Compare current critic, classical contextual surrogate, structural-feature MLP and one small order-aware encoder on identical candidate pools. Include exact token-multiset collisions and unseen structural/family partitions. Primary endpoint: measured top-B acquisition quality or saved exact evaluations at equal total cost. **Falsifier:** better ranker loss fails to improve acquisition, or inference overhead consumes the evaluation savings. Do not automatically replace the accepted decoder.

#### E3. When should neural proposals enter evolution?

**Hypothesis:** a particular coupling schedule improves final search quality per budget. Randomize generation-zero-only seeding, periodic injection, every-generation injection, learned mutation, and independent neural restarts against random GP. Hold initial proposal count, population size, evaluator and total compute constant where possible; report unavoidable budget differences explicitly. Include frozen-policy and shuffled-context controls. **Falsifier:** all neural schedules fail to beat the strongest simple control by the predeclared useful margin. This directly tests the NGGP caveat [R23] instead of mandating continuous injection.

#### E4. Does fresh feedback improve transferable search competence?

**Hypothesis:** feedback-selected training data improves future family-disjoint search beyond equal-compute passive retraining and a frozen policy. Compare repeated checkpoints with deployment budget fixed, shared allowable history, and stable baseline access. Separate a controlled common-data learning study from a full coupled search-and-learning study, whose later data necessarily diverge. Include strongest retrieval/classical selector, shuffled-feedback diagnostic, and cumulative meta-training cost. **Falsifier:** more archive winners or better shadow ranking occurs without prospective acquisition/search gain, or passive retraining matches the gain. This is the decisive flywheel experiment.

#### E5. Does learned budget allocation beat simple restarts?

**Hypothesis:** a continuation-gain predictor or operator bandit spends compute more productively than fixed scheduling. Randomize extra-budget assignments to obtain evaluation data that is not entirely selected by the predictor. Compare fixed restart GP, beam search, calibrated multi-fidelity allocation and then exact-state MCTS. Fully evaluate a random sample of low-fidelity rejects. **Falsifier:** false pruning, surrogate exploitation or search overhead eliminates the measured benefit. Report best-so-far curves and time-to-target rather than simulation counts alone [R38] [R39] [R40] [R41].

#### E6. Can the language discover transferable learners?

**Hypothesis:** a bounded extension with explicit fitted state or learning updates solves a controlled task family that the current expression/composition subset cannot solve comparably. Build diagnostic tasks with known required capabilities; include a conventional solver with those capabilities. Compare restricted and extended grammars at matched budgets, then execute the exported learned procedure on untouched task instances. **Falsifier:** apparent gain comes from target leakage, greater allowed fitting work, a hard-coded primitive that already solves the task, or failed export parity. This distinguishes learner invention from expression selection [R21].

#### E7. Do diversity and learned abstractions accelerate new discoveries?

**Hypothesis:** a compact behavioral archive and verified macros create useful stepping stones. Run staged ablations: tournament versus epsilon-lexicase; incumbent-only versus small MAP-Elites archive; frozen grammar versus macros mined exclusively from training families. Hold expanded-complexity and compute accounting equal. Measure novel eligible behavior, time-to-target and held-family quality. **Falsifier:** archive size or token compression improves while independently measured discovery does not, or gains disappear when macro cost is charged. Avoid changing all three mechanisms in the same unidentifiable comparison [R22] [R31] [R32] [R33].

#### E8. Can bounded replay preserve future learning?

**Hypothesis:** representative, family-aware replay with fresh examples and informative negatives retains adaptation and old-task competence better than champion-only or FIFO data at fixed bytes and training compute. Reuse current fresh/historical sampler semantics; compare uniform reservoir, current replay, top-score-only and proposed curation. Optional old-logit distillation is its own arm. Follow a chronological sequence with controlled distribution shifts; measure both new-family search gain and forgetting. **Falsifier:** compacted history preserves old summary scores but damages subsequent learning, coverage or rare-failure avoidance [R59] [R60] [R61] [R62].

The target demonstration is a chain of qualified checkpoints that needs less search compute, or finds better eligible programs under the same compute, on tasks outside the families that trained it. Some waves will be negative or inconclusive. Preserving those outcomes while retaining the strongest accepted policy is part of a credible research system; claiming universal monotonic improvement is not supported by the cited literature.

### 8.2 Identity, integrity and immutable publication

Define three separate identity types; never substitute one for another:

| Identity | Required fields | Purpose |
|---|---|---|
| `ContentId` | Domain/schema tag, SHA-256 of canonical identity bytes, logical byte length | Identifies the content or semantic object independently of physical relocation. |
| `PhysicalObjectId` | Store/account namespace, bucket, exact key, exact `VersionId` for versioned S3 | Identifies the physical bytes that can be verified, pinned, relocated or retired. Null/unknown versions are ineligible for version-level retirement. |
| `ObservedHead` | Key, response ETag, returned version when available, exact body, logical revision and unique commit ID | Concurrency observation for a conditional authority update; not a content digest. |

A manifest identity projection excludes its own ID, signatures, publication receipt and mutable rendering. It includes every field affecting execution, scientific meaning or dependency interpretation. Specify canonical serialization, finite numeric rules, ordered versus set-valued fields and domain-separated hashing. A compiler must not accidentally hash human comments or omit metric orientation. Immutable content references and physical locators are separate fields so packing preserves the logical identity.

AWS provides atomic single-key updates, not multi-key transactions [S1]. Conditional writes supply the concurrency primitive [S2]. ETags, application SHA-256 and S3 checksum algorithm/type have different meanings, especially for multipart bodies [S3]. Record them separately. When using versioning, a currently absent key is not proof the key never existed; a delete marker can change conditional creation behavior [S2] [S6].

Fix `crates/jope-models/src/publish.rs:46–67`: it currently accepts existing blobs on size and a create race on `Exists`. Verify existing bytes against the expected digest, as the learning Mirror already does at `mirror.rs:79–90`. Hash the actual submitted source bytes: the model publisher currently prehashes then rereads the file. Verify manifest closure before reporting publication success. Large objects may use bounded streaming verification; a remote verification cache is valid only for the same exact physical version and verification policy.

Required API behavior:

1. `put_verified_immutable(expected_content, source)` checks submitted content; creates conditionally; handles an existing object only after content verification; returns the physical identity and verification receipt.
2. `get_verified_version(physical_id, expected_content)` requires exact identity, bounds the body, verifies length and hash, and never silently reads latest.
3. `get_verified_range(pack_ref, chunk_ref)` verifies the exact pack version, compressed chunk and decoded entry. A range is not trusted merely because its parent key contains a hash.
4. `cas_authority(observed, proposed)` returns committed, conflict or unresolved. Lost responses are reconciled by reading the exact current authority; there is no unconditional overwrite fallback.

### 8.3 One compatible LearningSnapshot

First freeze and pin a `CandidateExecutionManifest` for a bounded candidate evaluation, with compatible completed model/export dependencies and a declared study/roster/seed/budget profile. It grants no research-parent or serving authority and does not contain a future assessment. Execute that manifest, then create an immutable `LearningPayloadManifest` containing the completed checkpoint, candidate input manifest and raw execution/evidence closure. A signed assessment references that payload; a compiled `ResearchCapsule` references the payload and assessment. Then create `LearningSnapshot`, which references those completed objects. This ordering avoids both execution-order and content-hash cycles: neither assessment nor capsule embeds the digest of a future snapshot containing itself. A separate publication receipt associates the snapshot with an authority revision.

For the initial operational integration profile, the assessment is explicitly `not_run` and the capsule is a minimal deterministic record of integration evidence. It may carry a separately authorized bounded research permission, but no scientific or serving claim. The full qualification profile requires completed assessment and complete raw closure. This declared optionality lets snapshot integration precede the prospective calculator and full capsule compiler without inventing a verdict.

`LearningSnapshot` binds:

- Model weights, architecture/configuration, tokenizer, GP grammar and numerical-semantics identities.
- Optimizer buffers, training step, scheduler, RNG states, precision settings and resumability verdict.
- Corpus manifest, exact replay input manifest, next admitted replay/support manifest, replay sampler and inclusion-policy versions.
- Teacher/checkpoint ancestry, critic version, learned library/version, candidate-support snapshot and admission rules.
- Evaluator image/build/protocol, role manifests, resource-accounting root, terminal census and qualification verdict.
- Compiled capsule, claim evidence root, rollback compatibility and declared restoration/reproducibility contracts.

Distinguish the data actually used to train the checkpoint from the data proposed for the next round. A next-round replay addition cannot retroactively become the checkpoint's training provenance. A new tokenizer or library may require an explicit compatibility adapter; matching tensor dimensions alone is insufficient.

`LearningAuthority` is one small mutable conditional head containing a monotonically increasing revision, unique commit ID, previous authority digest as provenance, research/serving/rollback snapshot roots, root registry, pin registry, retired-version set root and their generations. These referenced registries are immutable. The complete proposed head body is replaced by one CAS. Component aliases such as `latest-policy` are derived discovery views; they do not independently grant serving, training or GC authority.

Publication uploads verified dependencies, payload manifest, capsule and snapshot; checks compatibility, eligibility and full closure; then CAS-updates the authority against one observation. On conflict, reload the winner, recheck retired versions/pins/compatibility, and retry a new proposal or remain held. Reuse CLOVER's persistent HOLD for unresolved attempts (`clover/store.rs:134–251`). Existing per-run heads remain progress evidence. They enter the root registry through an adapter; they are not independent promotion or GC protection authorities.

Rollback publishes a new higher authority revision pointing to a verified retained snapshot. It does not decrement revisions, rewrite history or recover training authority from an unqualified checkpoint. Keep current and previous accepted serving snapshots hot by default; make the precise hot window and additional retained checkpoints explicit policy inputs.

### 8.8 Concurrent GC with an explicit linearization point

This design applies only to migrated namespaces whose authoritative roots and pins use `LearningAuthority`. #### 8.8.1 Reader and writer contract

A reader obtains a pin for an exact snapshot/dependency closure through an authority CAS before reading eligible old objects. Pins carry an ID, purpose, role, holder generation, expiry and protocol version. A renewal is another CAS-derived registry revision. Expired holders must stop before issuing further reads or publishing outputs; pause/resume rechecks the pin. The coordinator uses bounded clock uncertainty and a maximum expiry grace. If clocks or stop enforcement cannot be trusted, expiry alone cannot reclaim the closure.

An active legacy progress run registers a protected namespace and leases any shared inputs before work begins. Its changing per-run head remains evidence within that protected scope. Registering only a previously observed run head would miss later dependencies. New staging objects receive birth epoch/provenance and a minimum quarantine window. All publication and pin acquisition validate exact physical dependencies against the current retired-version set.

#### 8.8.2 Mark and prepare

Read one authority revision containing root, pin and retired-set generations. Mark the strong closure of research/serving/rollback roots, active pins, accepted libraries, declared proof/retraining commitments and protected classes. Discover candidates using a dated object/version census; Inventory is periodic reporting rather than a synchronization barrier [S8]. Unknown versions, unparsed references, unreadable evidence, incomplete listings, active namespace ownership or unresolved hold facts imply HOLD.

Create immutable `RetentionPlan/v2` with exact candidates, observed authority revision, source/target versions, policy, independent scan requirements and cost/restore bounds. An independent verifier recomputes marks and exact record reconciliation. Keep every object born after the cutoff protected. Compare current lifecycle/noncurrent expiration/hold configuration against pins; application reachability does not override a separately configured lifecycle deletion [S5] [S6] [S7] [S11].

#### 8.8.3 Pack, verify and commit logical retirement

Packing preserves originals initially. Reuse indexed zstd chunks and hashes; partition by role/access pattern/schema so train and sealed data do not acquire a shared access boundary. A relocation manifest maps original content and physical identity to an exact replacement pack version/chunk/offset/digest. Verify full source/replacement bytes and all logical records. Complete a cold restore when required by the selected class before accepting operational replacement.

Publish relocation and compatible revised roots first, retaining the original versions. Newly acquired pins resolve to replacements; existing pins continue protecting their original physical versions. An original becomes a retirement candidate only in a later mark epoch after its old pins and strong physical references have ended. Scientific byte-reproduction promises can accept a proven identical relocation; a promise explicitly requiring the original physical version cannot. This first implementation avoids combining the migration of a live reader's location and deletion into one opaque operation.

Commit logical retirement by a **single CAS of LearningAuthority** that installs both any required replacement roots and a monotonically extended retired-version set. The CAS must compare the exact authority used for marking, including pin/root generations. If a publisher or reader pin wins first, the GC CAS fails and its affected proof is recomputed. If retirement wins first, stale publisher/pin CAS attempts fail and retries reject those retired physical versions.

This is the concurrency guarantee. Checking roots and then separately deleting leaves a race in which a writer references an old immutable object after the check. Exact-version metadata stability does not close that race. The monotonic retirement set does: no future authority root or pin may resurrect a retired physical version. Logical content can be restored only into a new verified physical version, which is then pinned and published under a new revision.

#### 8.8.4 Physical retirement and recovery

After the defined quarantine/rollback interval and all proof requirements, a separately constrained executor may delete only exact physical versions in a committed retirement certificate. Its permission envelope names the bounded plan and operation set. It records each action as succeeded, failed or unresolved and reconciles unknown responses. A stale executor cannot damage a newly live root because its allowed old versions remain permanently retired. Restoring old content does not unretire those versions.

An unversioned delete in a versioned bucket generally creates a delete marker and does not reclaim old bytes [S6]. Do not substitute it for exact-version retirement. Object Lock/retention/legal holds remain independent constraints [S7]. Do not enable blanket immutable retention across all research caches by default. Multipart leftovers and lifecycle configurations require their own observed cleanup policy [S5] [S9] [S11].

Scope this executor only after the non-destructive proof, publication/pin protocol and restore drills qualify. If any actor can bypass the shared authority and establish a live reference to retired data, destructive rollout remains blocked for that namespace. Age-based grace cannot compensate for an unenforced reference protocol.

### 8.9 Cost and restore contracts

Expose logical versus physical/current/noncurrent bytes, object count, pending multipart bytes, pack overlap, PUT/GET/HEAD/LIST/retry counts, retrieval/egress/KMS charges where applicable, and oldest unverified restore promise. Report bytes actually reclaimed; temporary packing footprint includes both original bytes and new compressed packs until originals are retired. Use region/class/date-specific prices and minimum-duration assumptions [S10]. Small-object lifecycle behavior and archive overhead matter [S4] [S11].

Set separate budgets for active replay, hot rollback, essential proof, raw diagnostic payloads, local outbox and temporary compaction overlap. A budget breach pauses new optional production while preserving admitted completions. It does not delete an unknown-value artifact. Retention utility is measured as future learning/audit value relative to storage, retrieval and reconstruction cost, with hard proof obligations taking precedence.

A concrete **pilot policy**, to calibrate against deployment capacity before use, is:

| Class | Initial proposed policy | Retirement condition |
|---|---|---|
| Current/rollback serving | Current and two previous accepted snapshots hot; more if the rollout protocol requires them | Only after the rollback window and every other strong promise ends |
| Active replay | 32 GiB hot budget; bounded recent/history/negative/diversity/uniform sampling | Replacement replay passes a forgetting/transfer comparison; no active trainer lease |
| Local outbox | 2 GiB pending metadata/payload budget plus explicitly reserved admitted-completion capacity inside the hard cap; model staging has a separate quota | Verified remote segment, fsynced local checkpoint, historical dedup index and no last-copy obligation |
| Verbose routine telemetry | 14-day hot window, then lossless pack or eligible removal | Complete canonical census/card retained; no unique failure/reproduction evidence lost |
| Nonaccepted intermediate checkpoints | 90-day review window, with earlier/later windows explicitly costed | No current restart/retraining/proof promise; lineage certificates retain exact edge metadata |
| Pack size | Target 64–256 MiB by compatible role/access/schema; smaller final tail allowed | Full entry/version/hash and restore verification; packing alone does not authorize source deletion |
| Physical retirement grace | At least 14 days after logical retirement in the pilot | All old leases/graces ended and committed certificate independently verifies; grace never substitutes for authority fencing |

These numbers are proposed capacity/window settings, not statements of available disk, current bucket policy or guaranteed savings. Essential proof has an explicit budget forecast but cannot be evicted merely to satisfy a cap; pause optional work or revise a promise through its authorized policy process.

For the replay experiment, start with disjoint strata allocating approximately 35% of optional capacity to recent measured data, 25% to stratified historical data, 15% to hard/rare failures, 15% to diverse program/behavior lineages and 10% to a uniform background reservoir. Mandatory proof/recovery examples are accounted separately. Assign overlapping candidates to a deterministic stratum first. Compare this mixture with uniform, champion-only and fixed-history replay at equal bytes and optimizer updates. These quotas are an ablation recipe, not a universal best mixture. A byte-constrained weighted sampler must compute its actual inclusion probabilities; do not use `k/N` unless its design is truly uniform fixed-size sampling. Maintain separate replay-draw probabilities. Report forgetting, forward transfer, calibration and time/bytes saved before shrinking the retained predecessor.

Each retained snapshot declares recovery mode and target. Restart acceptance restores a checkpoint into a clean process, verifies tokenizer/grammar/corpus identity, resumes the next batch and checks the declared numerical tolerance. Serving rollback acceptance restores a retained bundle and reproduces its prediction contract. Claim-audit acceptance rebuilds the quantitative capsule from preserved sufficient evidence. Exact-retraining acceptance requires the entire declared training closure and is a stronger, separately costed promise. Define recovery-time objectives in deployment policy after measuring actual class/region paths; do not invent achieved timings.

## 9. Implementation architecture and delivery sequence

### One owner for each kind of truth

The architecture should remain mostly inside current crates. There is no new distributed platform or separate trainer in this plan. The proposed `jope-learning::selfplay` namespace owns wire contracts and adapters for evidence, snapshots and authority; the existing native loop remains the computation coordinator. It must not become a second search scheduler or numerical trainer.

| Responsibility | Authoritative current owner | Proposed boundary |
|---|---|---|
| Program semantics, exact representation, fit kernels, numerical faults, capabilities | `crates/feat-math` | No dependency on learning orchestration, cloud storage or UI |
| Search execution, common budgets, proposal/evaluation/variation interfaces and receipts | `crates/jope-pipeline` | Consume immutable profile and policy interfaces; no serving authority or corpus mutation |
| Product inference, grammar sampling, context production, accepted/challenger binding | `crates/jope-policy` | No native tch trainer linkage; validate exported contracts independently |
| Native training, actual optimizer, consumption, checkpointing and bounded research loop | `crates/jope-engine`, Cargo package **`jope-parallel`** | Preserve native coordinator, signed execution inputs and checkpoint authority |
| Evidence eligibility, corpus/replay views, research capsules, scientific calculation, S3 publication and authority | `crates/jope-learning` | Read trainer's published bytes through adapters; existing engine dependency remains test-only |
| Object transport, verified physical identities, credentials | `crates/jope-datasets` | Shared transport primitives; no scientific promotion decisions |
| Model bundle publishing and readback | `crates/jope-models` | Reuse shared immutable verification; no size-only shortcuts |
| Claim/revocation semantics | `crates/jope-records` | Continue importing the existing verifier rather than duplicating it |
| Campaign/UI orchestration | Existing campaign and CLI modules | Present decisions and submit bounded requests; numerical/scientific rules live below UI |

Current `jope-learning` depends on `jope-pipeline`, `jope-datasets` and `jope-records`; its `jope-parallel` dependency is test-only. Respect that dependency direction. If a pure wire contract truly needs common sharing, first place it in an existing suitable lower-level crate or use separately validated schema fixtures. Create a tiny new contract crate only after demonstrating that this avoids a real cycle; do not introduce one for every noun in the specification. [C32]

Use the new `jope.canonical-json/v1` contract for envelope payloads. Encode valid UTF-8 without a BOM, no insignificant whitespace, duplicate-key refusal and object keys sorted lexicographically by Unicode scalar sequence. Preserve array order. Do not normalize Unicode: reject invalid UTF-8/unpaired surrogates, and preserve distinct valid strings. Escape quote and backslash with their two-character escapes; encode all U+0000–U+001F controls as lowercase six-character `\u00xx`; emit other Unicode directly, and do not escape `/`. Booleans/null use lowercase JSON literals. Integer-valued fields use minimal decimal spelling, range −(2^53−1) through +(2^53−1), without negative zero; larger identities and 64-bit RNG seeds use schema-defined fixed-width lowercase hex strings. New identity readers refuse bytes that differ from their parse-and-canonicalize result. Historical formats keep their existing rules.

Compute new IDs as `SHA256(schema_utf8 || 0x00 || u64_be(payload_byte_length) || canonical_payload_bytes)`. Schema IDs contain no NUL; the length prefix removes ambiguity. Every execution/science/dependency field belongs in the declared identity projection; no implicit omission of unknown fields is allowed. The record's own ID and signature envelope are outside that payload. The graph's constants use exact `f32_bits`/`f64_bits` strings, preserving signed zero and subnormals. Shared native/inference/storage fixtures define the same bytes; independent serializers must pass those fixtures before exchanging identity-bearing objects.

For measured numeric fields, store finite values through a declared exact numeric encoding or preserve the exact canonical serialized representation with `float_roundtrip`; the schema must choose one, not accept several encodings as the same ID. **For new cross-language identity-bearing metrics this specification chooses tagged IEEE-754 bit strings plus a human numeric display field excluded from identity.** Missing values are null plus an explicit reason, never NaN masquerading as null. Historical formats retain their byte rules and receive bridge records. Publish conformance vectors for nested objects, reordered keys, ordered arrays, Unicode, signed zero, subnormal values, non-finite refusal and hash-envelope exclusion.

Avoid execution, assessment or capsule cycles: completed checkpoint → pinned candidate execution manifest → raw evaluation closure → payload manifest → signed assessment → capsule → snapshot → external authority publication receipt. The input manifest grants only its bounded evaluation capability. The payload does not contain its later assessment; the assessment does not reference the future snapshot that will embed it. Summary prose can be regenerated without changing measurements; a changed scientific interpretation gets a new interpretation record linked to the same evidence.

### First structural-critic implementation profile

To make the architecture experiment executable, start with the following **development challenger profile**, chosen for testability rather than asserted optimality:

| Component | Proposed initial configuration |
|---|---|
| Task input | Current verified 2,048-value native context; linear projection to 128 and layer normalization |
| Program input | Current native token IDs and EOS, explicit length mask, token embeddings width 128; reserved/non-generatable IDs retain their manifest status |
| Structural input | Position embedding through length 128; bounded argument-role/depth features derived from verified parse; no silent overlength truncation |
| Program encoder | Two bidirectional attention blocks, four heads, width 128, FFN 512; compare one cheaper sequence/structural-feature alternative |
| Fusion | Program summary plus projected task vector and elementwise interaction, followed by a small MLP |
| Outputs at first | One measured-quality/ranking head and one completed-runtime head with exact label masks; no fake stability/uncertainty claims |
| Parameter/latency budget | Target at most two million added parameters; actual count and tensor manifest generated from implementation; inference included in search cost |
| Controls | Existing mean-pool critic, frozen classical contextual surrogate, structural-feature MLP; actor weights frozen for initial acquisition test |
| Later uncertainty | Independently initialized or bootstrapped ensemble, only after single-model benefit; calibrated per family/fidelity/hardware |

An external critic artifact can be attached to `LearningSnapshot` while the accepted actor remains frozen. It receives its own architecture, training-intent, export and qualification identity. This is critic-guided search progress; it is not evidence that the actor's generation policy learned. Joint actor/critic training is a later explicit model migration. If graph programs exceed the existing sequence ABI, use a separately versioned graph encoder; do not force them into 128 tokens by truncation.

The first optimizer ablation should hold model/data/objective fixed and compare the existing recipe with a proposed AdamW recipe using explicit no-decay groups, global gradient clipping, 5% linear warmup and cosine decay over a **predeclared number of optimizer updates**. Development choices such as learning rates `{3e-5, 1e-4}` and global clip `{0.5, 1.0}` are a small bounded sweep, not production defaults. Record minimum LR and time at that floor. The chosen schedule is frozen before qualification. Warm starts reset incompatible moments; a schedule change must not be called exact resume.

For the allocator example, the precise EXP3-style experimental update is `w_a <- w_a × exp(eta × g / (M × p_a))`, with all other weights unchanged, bounded gain `g` in [0,1], positive exploration, and log-domain normalization. The metric/version defines gain scaling and actual cost. This makes an initial implementation unambiguous while keeping it separate from a future contextual continuation model. [R70]

Advanced language/search PRs are not prerequisites of PR07.

### Critical path and work allocation

The minimum integration path is `01 → {02,03,04} → 05 → 06 → 07`. The first **scientific** result also requires 08 and 11, plus a frozen roster and actual measured run. The first promising structural-critic experiment is 12→13 after that harness. Capsule compilation and outbox/custody work can proceed independently after their contracts are stable. Final physical GC is deliberately downstream of proof and migration; its delay does not block learning experiments or read-only storage savings estimates.

Keep parallel work in at most three implementation lanes initially: learning/lineage, evaluation/search, and storage/evidence. Use a separate reviewer for source/contract closure. One writer owns each checkout, and shared contract changes land before dependent implementation changes. PRs listed together are not permission for uncontrolled parallel edits to the same module. The existing repository review/merge rules remain in effect. [C01]

Planning ranges, not delivery promises: 6–10 engineer-weeks for the reliable minimum loop, evidence/cost harness and first prospective readiness; another 6–10 for structural ranking, selected search integration and bounded memory; 6–12 for robust custody/retention rollout with live integration; graph/learner invention is a later research program whose duration depends on measured results. With three engineers, calendar duration depends strongly on shared-module review, hardware access and qualification data. Avoid presenting all 32 PRs as a single fixed-date commitment.

A budget illustration makes the first study reviewable: 30 independent families × one task/context × three search seeds × three arms × 900 CPU core-seconds per episode = **67.5 CPU core-hours**, before training, encoding/GPU work, judge execution, storage and retries. Three independently trained lineages triple that search component to 202.5 core-hours. These are arithmetic examples, not estimates of this repository's actual throughput or an authorization to run them. Choose `b_0` from a development-calibrated baseline-completion bound; a task failing to produce its valid baseline by that boundary follows the prespecified incomplete/failed-unit policy, not a fabricated incumbent.

### CI and meaningful acceptance

Keep fast semantic/contract tests separate from asset/hardware/cloud qualifications. Source tests are not evidence that the live environment passed, and an excluded family is not equivalent to success. Extend existing aggregate reporting with required capability gates and a reason for every skip/exclusion. Current exact-commit CPU diagnostics are useful but insufficient for all new claims. [C31]

Examples of intended commands **after the corresponding tests exist**, using actual Cargo package names:

~~~bash
cargo test -p feat-math --locked
cargo test -p jope-learning --locked
cargo test -p jope-policy --features testing --locked
cargo test -p jope-parallel --locked
cargo test -p jope-parallel --features neural --locked
~~~

The `testing` policy feature belongs only in tests. Production builds must not enable it. The neural command requires the repository's supported LibTorch/hardware environment; the audit did not run it. Use targeted existing feature-qualified suites for each PR rather than rerunning every expensive campaign for a documentation or pure serialization change. A new numerical backend needs its own reference comparison and supported-hardware receipt; default CPU tests do not grant that capability. [C32]

|---|---|---|
| G0 identity | Canonical schemas, exact historical identities, no self-hash cycle, strict readers | Exchange/version new records |
| G1 execution | Admitted program has safe fit/predict path, correct scope, resource receipts and parity where required | Use measured outcome for its declared role |
| G2 evidence | All planned attempts reconciled; exact request/protocol/role/physical closure | Admit eligible per-head targets and compile a non-qualifying capsule |
| G3 learning | Actual supervised contribution, committed native update, honest lineage and next behavior change | Claim operational closed learning loop |

| G8 deployable learner invention | New fitting-procedure class, safety/parity, external task transfer and meaningful baseline gain | Claim algorithm invention at the demonstrated expressivity level |

Do not require strictly positive realized gain in every wave: noisy learning can regress, fail or plateau. Require non-regressing accepted serving behavior within a declared safety tolerance, honest inconclusive outcomes, and a cumulative claim whose evidence accounts for dependence and selection. A rejected child can still contribute valid training failures or scientific knowledge through the appropriate role.

### A demonstration that shows the right result

The product demonstration should begin with a named regression task and a visible budget. Show the current profile and policy snapshot, a few representative proposed kernels with source labels, exact measured quality/cost, and the train-selected incumbent over time. Let the viewer inspect the final program and emitted prediction contract. The UI should read the same immutable receipts used by the judge rather than recompute its own winners.

For a multi-wave demonstration, display three separate trends: archive best-so-far under its training role; frozen evaluation performance of parent/child policies on independent tasks; and marginal gain from fresh feedback compared with the no-fresh control. Show negative or inconclusive rounds explicitly. A source-linked capsule should explain the hypothesis, actual denominator, cost, effect interval, decision and next experiment in a short readable view.

A prerecorded deterministic fixture can prove the interface. A live authorized run can prove the system executes. A qualified controlled result can prove the specific scientific improvement. Keep those states explicit. The current CLOVER initialized 128×2 seed fixture is useful for the first of these, not evidence that the accepted model already learned through the loop. [C12] [C30]

Use the existing TUI/CLI rather than a new dashboard framework. Proposed subcommands can be added under current binaries for `round plan`, `round verify`, `snapshot inspect`, `capsule show`, `replay explain`, `retention plan`, and later bounded `retention apply`. These names are proposed; the specification does not claim those commands currently exist. Implementation details such as ETags need not appear in the normal demonstration, but an audit view must expose exact versions and receipt identities.

### Additional frontier comparisons

FunSearch and AlphaEvolve illustrate another route: learned code proposals combined with execution/evolutionary evaluation. They motivate optional external proposer controls and verifier discipline. They do not require replacing the requested neural-to-GP approach with an LLM agent that writes arbitrary code. If evaluated, keep the same task role, support allowance, verifier, execution isolation and total compute boundary; include model-call cost and any hidden evaluator assistance. Claim algorithm novelty only after comparing semantics and prior algorithms, not from unique source text. [R68] [R69]

A useful long-horizon target is **budget-conditioned compiler and learner co-design**: search a model/feature/fit recipe, then select a semantically qualified implementation suited to hardware and prediction constraints. Keep statistical-program identity separate from execution optimization identity. An accelerated backend that preserves predictions should benefit every eligible baseline; otherwise apparent learned improvement may simply be a compiler improvement. Exact mathematical algorithm-discovery examples such as AlphaTensor are instructive, but regression outcomes are statistical and do not provide the same proof of optimality or mathematical correctness. [R07]

## 10. Risks, unresolved deployment facts, and stop rules

The following need evidence during implementation; none prevents producing this specification. They are concrete prerequisites at their relevant rollout stage, not reasons to ask for a general permission now.

| Uncertainty or risk | Why it matters | Resolution / stop rule |
|---|---|---|
| Current production/experiment consumers differ | A source-capable feature can remain unwired or unqualified | Generate a consumer/profile inventory and require an actual receipt per claimed route |
| Accepted corpus/checkpoint live availability | Static source and CI cannot prove assets can restore | Bounded clean-host restore using exact retained manifests before operational continuation |
| Independent-family roster size and rights | Determines scientific scope, contamination and power | Adopt a versioned roster and variance-based plan; report exploratory results if insufficient |
| Hardware numerical drift | Identical seeds do not imply cross-hardware bitwise replay | Publish supported numerical profiles and backend-specific parity; no universal determinism claim |
| Critic extrapolation and search exploitation | Search optimizes model errors as well as real performance | Exact measurements, random audit floor, calibration, unsupported-action tracking and conservative fallback |
| Larger language reduces search coverage | Expressivity can outgrow evaluator budget and model support | Admit one capability at a time; held-family gain and coverage before wider rollout |
| Fresh data mostly duplicates champions | A changing corpus hash can conceal little information gain | Track novel logical outcomes, supervised contributions, structural/behavioral diversity and no-fresh controls |
| Replay deletion causes forgetting | Low present score can hide future stepping-stone value | Stratified/uniform floor, rare boundary retention and fixed-byte forgetting experiments |
| S3 lifecycle or legacy clients bypass authority | Application GC proof no longer protects active data | Namespace HOLD until all actors and lifecycle policies satisfy the pin/retirement contract |
| Long-lived credential expiry | Static resolved credentials can interrupt a sustained wave | Expiration-aware refresh and bounded retry/capacity handling with redacted receipts |
| Scientific memory leaks judge information | Short summaries can contaminate future training as much as raw scores | Role propagation through every derivative, pre-retrieval filtering and exposure ledger |
| Overengineering hides the first result | New planners/IRs/trainers can delay evidence indefinitely | Keep PR07 before optional search/language work; stop features that lose to simpler controls |

Kill or narrow any advanced component after two adequately powered, prespecified development comparisons fail to show the useful effect for its cost and complexity. Revisit only when new evidence identifies a specific changed condition. Do not keep adding objectives to explain a failure of the current objective, or preserve an expensive architecture merely because it is more sophisticated.

The acceptance target is a system that can demonstrate: **which new measurements changed which learning state; what those changes improved on independent tasks; what they cost; which conclusions remain uncertain; and which historical bytes can safely be removed while preserving the promises that still matter.**
