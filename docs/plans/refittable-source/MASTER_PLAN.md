# Refittable Rust source

## First delivery

Add the opt-in local `jopedime model export --format rust-refittable` profile for verified numeric regression math-pipeline objects with `prediction_version: 2`. The emitted Rust program fits a fixed GP recipe on an explicit FIT CSV, saves a standard model object, and predicts from a compatible saved object. A fresh FIT can change the object and predictions while the source and compiled executable stay reusable.

The initial recipe slice covers Ridge and `histgbm`/`gbm`, with zero or more non-appending `standardize` and `robust_scale` stages. Target transforms are outside the slice. Check the fitted stage and head kinds against the parsed recipe before export or prediction.

The first profile uses a pinned local `jope-runtime` build closure. Its recipe contains the admitted DSL operations and parameters under trusted local use. `GenomeIr::canonical` can round small numeric parameters, so this profile serializes its narrow admitted parameter set at round-trip precision. `jope-runtime` is unpublished. Prove the build with the supported local closure before describing the profile as usable, and record the commit, toolchain, lockfile and ABI identity.

Keep the legacy source profiles, service and SDK APIs, archive readers, release defaults, and historical receipts intact. GP search, ranker selection, fit math, evaluator identity, data splits, the histogram split bug, and the Blender deliverables have separate owners. The first PR covers this Rust profile only. Public profiles, other languages, standalone dependency-free trainers, bundle migration and a refreshed film require separate qualification.

## Implementation order

1. **Define the profile and pin the runtime.** Project the parsed recipe from a verified v2 pipeline through `MathPipeline::export_refittable_rust`. Admit only the supported stage, head and parameter slice and require matching fitted kinds. `jope-refittable-rust/v1` emits a compile-time check for `math_pipeline::refittable::ABI_VERSION` and invokes the existing fitting implementation through the pinned runtime. Verify the generated program builds in that locked closure.
2. **Emit reusable source.** The renderer receives the admitted recipe text from the typed projection. Source identity is the exact emitted bytes for that recipe text, profile and ABI. Quote the recipe as a Rust string literal. Exclude the template's feature and target schema, fitted state, input ranges, row values, fixture values, model IDs, file paths, clocks and fit receipts. The explicit FIT invocation supplies the schema for each saved object. Keep the source hash and runtime build identity in export evidence. Unsupported formats or incompatible contracts fail before the output is published.
3. **Fit with explicit inputs.** Expose `fit <train.csv> <target> <store> <feature>...` through `refittable::fit_csv`. Match CSV headers by name and validate complete, finite numeric cells, distinct names and target separation. Feed features in the exact caller-supplied order and record that order in the new input contract. Derive fresh ranges and target scale from the supplied FIT rows. Use existing v2 arithmetic, `feat_math::fit`, and the runtime's input and object limits. The caller designates the FIT file. The command performs no discovery, split inference, holdout reads, champion publication or session update.
4. **Save and predict.** Construct `jope.model-object/v1` with decoder `org.jopedime/math-pipeline/v1` and exactly `pipeline.json` and `input.json`. Reuse `ModelObject::save` for manifest-last content-addressed publication. Save validates executability before publication and returns the digest-named path. `predict <model-dir> <input.csv>` calls `refittable::predict_csv`. Open the exact named object, verify the admitted recipe projection and prediction version, and use its saved input contract in `MathPipeline::predict_table`. Keep the object hash bound to the exact manifest bytes and payload digests. Record provenance outside the object so a retry with identical fitted bytes preserves identity.
5. **Wire only the local opt-in.** Route `jopedime model export --model <object> --format rust-refittable --output <source>` through the new projection and renderer. Preserve existing CLI formats and the central legacy `ModelObject::export_source` dispatch. Existing service `ExportRequest.refit` selects an already published FIT or FIT+HOLDOUT role. New-data fitting is the generated program's explicit command. Correct the workflow docs and record qualified coverage in the existing matrix.

Model state owns data-derived statistics, coefficients, trees, learned ordering, and any retained support rows. The source profile owns recipe and runtime ABI. Each saved object binds its fitted state and declared input schema. A trained model's shareability requires its own review because separating the source leaves the fitted state's data retention intact.
