## Measured kernel improvement

A standalone `rustc --edition 2021 -O` comparison compiles the old and new
`ksmooth` implementations with the same `std_fit` source. Data: deterministic
LCG seed 42, 20,000 training rows, eight features, 254 query rows, k=32, gamma=1.
Five repetitions alternate execution order. All predictions match by `to_bits`.

| Repetition | Full sort (s) | Partial selection (s) | Ratio |
| --- | ---: | ---: | ---: |
| 0 | 0.326094 | 0.052351 | 6.229× |
| 1 | 0.329105 | 0.046918 | 7.015× |
| 2 | 0.339568 | 0.057427 | 5.913× |
| 3 | 0.333113 | 0.050794 | 6.558× |
| 4 | 0.395194 | 0.066903 | 5.907× |

Median paired ratio: **6.229×**. These are local microbenchmark results on a
contended host, not end-to-end search or fleet throughput. The in-tree ignored
`ksmooth_prediction_benchmark` provides a repeatable workload and compares against
the preserved full-sort reference without asserting a timing threshold.

Selection work changes from O(n log n) to O(n + k log k) per query; distance work
remains O(n p). Scratch remains O(n + p), but its three buffers are reused across
the prediction batch. No approximate neighbors, distance reordering, parallel
reduction, unsafe code or global scratch is introduced.

## Memory and threading boundaries

The stage-cache cap still measures f64 row payload plus serialized fitted bytes.
It is **not an RSS bound**: row/vector/hash-table overhead, fitted heap capacity,
temporary fit workspaces, and caller-held values outlive or sit outside that
charge. Streaming removes the extra JSON allocation; it does not qualify a
process memory ceiling. `jope-pipeline/src/execution.rs` owns per-fit cgroup
allocation, and `jope-pipeline/src/parallel.rs` owns admitted worker counts and
the fixed 32 MiB evaluation stacks. Keep those boundaries when tuning concurrency.

There is no new Rayon pool or nested parallelism in this change. Cache admission
remains atomic across shards; the tests exercise concurrent hits, replacements
and sweeps and check exact final accounting. Generation changes retain their
existing boundary-before-evaluations contract.

## Layout, design and follow-up work

1. **Separate navigation before changing evidence paths.** At the reviewed base,
   Git tracks 5,003 paths: 2,063 under `crates/`, 1,858 under `deploy/`, and 649
   under `docs/`. The approximately 5 MiB dated analytics HTML files and Parquet
   shards under `deploy/dl-flywheel/pipelines/rlfw/analytics/` are candidates for
   external archival. First inventory references, verify custody restoration,
   then replace only movable captures with manifests in a dedicated PR. The
   existing layout guard explicitly protects several qualification logs.
2. **Split large authored modules along tested boundaries.** `evolve.rs` has
   7,861 lines and `jope-pipeline/src/execution.rs` has 3,933 at the base. Extract
   scheduling, selection, publication and execution-policy units separately,
   preserving visibility, fixture identities and receiving-path tests. A bulk
   rename would create a large scientific-identity change with little benefit.
3. **Make CPU ownership consistent.** Review `jope-engine/src/gp.rs`'s
   `tchless_threads`: it defaults to four global Rayon workers and discards
   `build_global` errors. Prefer an explicitly admitted, named local pool at
   command boundaries after auditing all nested callers. Prove cpuset/cgroup
   limits and one-worker versus multi-worker decisions with identical seeds.
4. **Measure the actual bottleneck.** Record wall time, CPU time, peak RSS,
   admitted workers, bytes read/written, stage-cache hit/miss/accounted bytes,
   queue wait, fit count, and failed fits under one source/data/evaluator identity.
   Compare equal evaluation and compute budgets. Do not infer learning lift from
   faster proposals or a kernel microbenchmark.
5. **Keep dashboard state and views separable.** The React dashboard has a
   1,264-line `App.tsx` and 902-line stylesheet at the base. Extract overview,
   training, fleet, storage and program-library views with shared evidence-state
   components. Preserve unknown/stale/error distinctions. Source inspection also
   found spread-based chart extrema and a shallow snapshot validator: qualify
   nested observation shapes and long histories before increasing response caps.
   No rendered UI redesign is claimed by this PR.
