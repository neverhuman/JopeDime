\section{EurekaZero: Learning Taste}\label{sec:method}

The reference procedure uses verified search to train a program writer
and a separate problem--program map that ranks scored programs.
Deployment permits one draw from the writer, with the map absent.
We describe this historical reference first, then the later
adapter-ranking record in \cref{sec:method-status}. Ranking a pool and
proposing a new program are different tasks. The writer's first-proposal
behavior requires the matched comparison in \cref{sub:results-learning}.

\subsection{The player in one picture}\label{sub:method-picture}

\Cref{fig:network} separates the roles: a frozen encoder reads the board and
the program writer $\writer$ writes one complete program, as AlphaGo's policy
network proposed a move \citep{silver2016mastering}. The problem--program map
$\mapv$ supplies a separate ranking score. In this reference checkpoint it
neither conditions nor screens the writer. It is absent from deployment,
where \searchone{} permits only the writer's single draw.

\subsection{Reading the board}\label{sub:method-board}

The reference checkpoint uses a frozen encoder to turn the board of
\cref{sec:game} into 2,048 numbers, $z_p=\encP(p)$, in three blocks.
The first summarizes a pretrained row encoder's embeddings across rows,
independent of row order (512 values). The second projects the hidden
state of a pretrained third-party tabular regressor that reads the training
rows and labels (1,024; Foundation, version \texttt{foundation\_enc.v1.tabpfn}; license: proprietary, available on request; redistribution prohibited). The third passes the
scaled targets through two frozen windows (512).

The reference encoder stays fixed during writer training and is pinned by
hash. Encoding is bounded at
30 seconds per problem. A context with any non-finite value is refused
rather than imputed (\cref{app:training}). The input contract permits
training-side task evidence only; final held-out labels and their derived
statistics must stay outside the input closure. A context's recorded
declaration that no final target was used is part of the audit trail,
not a substitute for checking that closure.

Whether problems with similar best programs sit together requires a
separate representation study; \cref{sub:results-ablation} reserves that test.

\subsection{Describing the move}\label{sub:method-move}

A move is one program in the typed language of \cref{sec:game}, with a
401-token vocabulary. Up to six transforms from a set of 31 feed one of
22 prediction heads. The native decoder masks forbidden tokens at each
step, as in grammar-constrained generators
\citep{kusner2017grammar,dai2018sdvae}. A finished draft enters the pool
only after it decodes and parses. These grammar checks do not establish
that the writer avoids programs that parse but crash or lose. A program's
identity is the SHA-256 hash of its canonical form. A separate hash of
predictions on fixed training probes flags matching observed outputs.
Those matches do not establish equivalence on other inputs. Without probe
evidence, this behavior check reports novelty as unknown. The reference
procedure calls for readable Python and Rust recipe exports that fit on
the task's training rows. Reported winners also require the native--emitted
parity check in \cref{sub:method-referee}.

\subsection{One map for problems and programs}\label{sub:method-map}

The map reads a program as $z_w=\encS(w)$, the mean of learned token
embeddings. Pooling discards token order, limiting the map's ability to
distinguish compositions built from the same tokens. It combines $z_w$
with $z_p$ three ways (as is, gated by the problem, and as a distance from a projection of it) and
averages four heads into a score $\mapv(z_p,z_w)$ with parameters $\psi$. It learns from lists: for each problem $p$ with
at least eight scored programs, $G_p$ holds them and $\rho_w\in[0,1]$ is a program's percentile, 1
for the best. The map's softmax over the list is trained toward a target concentrated on the best
\citep{cao2007listnet}:
\begin{equation}
  \mathcal{L}_{\text{map}}(p)=-\sum_{w\in G_p}
  \frac{e^{\rho_w/\tau}}{\sum_{u\in G_p}e^{\rho_u/\tau}}\,
  \log\frac{e^{\mapv(z_p,z_w)}}{\sum_{u\in G_p}e^{\mapv(z_p,z_u)}},
  \label{eq:mapLoss}
\end{equation}
with $\tau=0.25$. With a unique best program, the low-temperature limit
concentrates the target on that program. This is a listwise ranking
objective over programs scored on the same problem; the analogy to
contrastive learning \citep{oord2018cpc,radford2021clip} does not establish
CLIP-style alignment across problems and programs.
A Bradley--Terry term on the same lists sharpens the top \citep{bradley1952rank}. Stillborn moves
have no score, so this ranking objective covers only programs that run. A program-only head
trained beside it tests whether the map reads the problem at all (\cref{sec:results}).

\begin{keyidea}
The reference game-day protocol omits the ranking map. Its single proposal
tests what the writer has learned.
\end{keyidea}

In this checkpoint the writer and map use separate context networks and
token embeddings. The map ranks the draft pool for comparison with the
referee; it drops no draft and does not condition, screen or steer the
writer. The writer learns directly from referee scores. Ranking agreement,
including comparison with the program-only control, can therefore assess
the map. Attributing better proposals to it would require an implemented
influence path and a matched ablation (\cref{sub:results-ablation}).

\subsection{The self-play loop}\label{sub:method-selfplay}

The historical reference uses expert iteration \citep{anthony2017expert}:
the writer learns from verified search (\cref{alg:selfplay}). Programs
sampled from the scored lists $G_p$ are weighted by their referee rank in
the combined objective (\cref{app:training}):
\begin{align}
  \mathcal{L}_{\text{writer}}(p) &= -\sum_{w\in G_p}\bigl(0.05+\rho_w^{4}\bigr)\log\writer(w\mid z_p),
  \label{eq:writerLoss}\\
  \mathcal{L} &= \mathcal{L}_{\text{writer}} + 0.1\,\mathcal{L}_{\text{map}}
  + 0.25\,\mathcal{L}_{\text{BT}} \nonumber\\
  &\quad + 0.1\,\mathcal{L}_{\text{runtime}} + 0.05\,\mathcal{L}_{\text{prog}}.
  \label{eq:totalLoss}
\end{align}
The writer loss in \cref{eq:writerLoss} is schematic: it displays the rank
weights. The native implementation also smooths grammar-legal targets,
averages token losses within each program, and normalizes by the sum of
program weights (\cref{app:training}).

Here $\mathcal{L}_{\text{BT}}$ is a Bradley--Terry loss on the same lists,
$\mathcal{L}_{\text{runtime}}$ a Huber loss for a head that estimates runtime cost, and
$\mathcal{L}_{\text{prog}}$ the Bradley--Terry loss of the program-only control head.
Losing moves still teach: a median-ranked program carries about a tenth of the top-ranked
program's weight in the writer loss. Its referee score also contributes
to the map's ranking targets.

\begin{algorithm*}[t]
\caption{The reference self-play loop (training).}\label{alg:selfplay}
\begin{algorithmic}[1]
\Require training problems; serving writer $\writer$ and map $\mapv$; incumbents $\inc{p}$
\For{each round}
  \For{each sampled training problem $p$}
    \State $z_p \gets \encP(p)$; keep the first 64 distinct valid draws from $\writer(\cdot\mid z_p)$ \Comment{$T=1$; grammar-uniform fill if short}
    \State verified search, seeded with the drafts and 16 random exploration programs, proposes more programs \Comment{the teacher}
    \State $\referee$ fits and scores each distinct program on 5 inner folds \Comment{stillborn: no score}
    \State \textbf{if} a program strictly beats $\inc{p}$ \textbf{then} it becomes $\inc{p}$ \Comment{board ratchet}
    \State add every scored program to the list $G_p$ \Comment{winners and also-rans}
  \EndFor
  \State train a challenger $(\theta',\psi')$ on the lists
  \State \textbf{if} it beats $\writer$ on held-out cuts \textbf{then} $(\theta,\psi)\gets(\theta',\psi')$ \Comment{player ratchet}
\EndFor
\end{algorithmic}
\end{algorithm*}

Two ratchets make this self-play rather than imitation of a fixed archive (\cref{sec:game}). A
program displaces a board's incumbent only by strictly beating it. A retrained writer takes the held-out
admission test: 16 cuts with three seeds each. It replaces the serving writer
only if its mean log error ratio favors it. It must also win at least as
many cuts as it loses and fail no more often.
%
Here a cut is a held-out evaluation case fixed before the admission test.
For each cut, the rule takes the natural log of paired best-error ratios
(challenger divided by serving) and averages over matched seeds; it then
averages across cuts. Negative values favor the challenger. This admission
comparison is separate from the single-program comparison in
\cref{sub:results-learning}.

\paragraph{The historical reference.} The writer is a decoder-only transformer (six blocks, width 512)
that reads the context as a prefix token and writes at most 128 tokens; with the map, the network
has 27.8 million parameters. The supplied source notes describe training on eight A100 GPUs in
September 2026, with a corpus of about 10.2 million scored programs from
80 training datasets. This paper does not document the evidence on which
the checkpoint was accepted; that record and a pinned runtime are required
inputs to the evaluation contract (\cref{sub:results-protocol}). These specifications
identify the historical reference; they do not describe the later adapter
snapshot or establish its deployment performance. Details belong in
\cref{app:training}.

\subsection{Keeping the referee honest}\label{sub:method-referee}

A learner rewarded by a referee can exploit its flaws. In February 2025 Sakana AI walked back
claims after its AI CUDA Engineer exploited the evaluation code \citep{sakana2025walkback}. In June
2025 METR reported frontier models patching their scorers \citep{metr2025rewardhacking}, and 16\% of
1,968 agent-benchmark tasks can be passed without being solved \citep{zhong2026hackerfixer}. We
require the evaluation protocol to withstand such attacks. Selection,
promotion and final scoring must use separate data (inner folds, held-out
cuts, a final fold scored once), with sealed meta-test families outside the
learner's inputs. The proposed comparisons require sandboxed execution
using seccomp and Landlock, with memory, swap and time limits. A
planted label leak and a sealed canary must both be caught, and every reported winner must be re-run
from its emitted code, with native and emitted predictions agreeing within
$10^{-9}\max(1,|\hat y|)$. One earlier leaderboard entry for our search selected each dataset's best
test-scored outcome from a ledger of 63,108 evaluations; we exclude it as test selection (\cref{app:incidents}).

\subsection{Game day: \texorpdfstring{\searchone}{search = 1}}\label{sub:method-gameday}

\begin{algorithm}[tb]
\caption{Proposed game-day protocol (\searchone).}\label{alg:gameday}
\begin{algorithmic}[1]
\Require new problem $p$ with training rows and metric; frozen $\encP$ and $\writer$
\State $z_p \gets \encP(p)$ \Comment{read the board}
\State $w \sim \writer(\cdot \mid z_p)$, one draw at $T=1$ \Comment{one move; no retry}
\State $f \gets \textsc{Fit}(w,\ \text{training rows})$ \Comment{as any algorithm is fit}
\State $\hat{y} \gets f(\text{new rows})$ \Comment{a stillborn $w$ scores as a loss}
\State \Return $w,\ \hat{y}$
\end{algorithmic}
\end{algorithm}

The proposed protocol in \cref{alg:gameday} permits one encoder pass and one
draw of at most 128 tokens at temperature 1 from a recorded seed. The
program is lowered to code and fitted. The map stays absent, and no
training exploration program is added. A draft that does not finish,
crashes or times out is stillborn and scores as a loss; it is not replaced.
Costs must include the encoder, writer and fit. Report later search
separately, as \citet{silver2017mastering} reported
AlphaGo Zero's raw network apart from its search (\cref{sec:results}).

The deployment budget is a protocol constraint. Whether training improves
the quality of that single proposal is a separate empirical question for
the matched comparison in \cref{sub:results-learning}.
