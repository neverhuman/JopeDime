What does the retained training record establish? These CSVs describe a
later adapter-training snapshot, separate from the historical reference
checkpoint above. Here an adapter is the trainable adjustment evaluated by
the admission loop; the utilities alone do not identify its relationship to
the historical writer and map. Utility denotes the logged scalar score,
with larger values treated as better in the admission record.
The admission CSV records each round, its candidate and best validation utilities,
an acceptance flag and a timestamp. Neither CSV records the adapter's
architecture, score normalization or evaluation population, so we do not
compare this snapshot with other models. The loop description that follows
comes from source inspection; it is not yet bound to the run that produced
these logs.

In the inspected loop implementation, heuristic program edits, retrieval
and grammar sampling supply candidate programs. A trainable adapter ranks
proposals by a predicted evaluation score; this loop does not optimize a
neural program writer. Its pool-utility calculation uses the recorded
scores and gate outcomes of
the first four candidates as revealed history, then selects the candidate
with the lowest predicted score from the pool, including those entries.
This is a conditional ranking task, separate from a single new program drawn by the
historical writer.

The inspected caller supplies modality tokens and a mask while zeroing
separate context and prior inputs. Its objective combines scalar
evaluation-score regression and listwise matching, with a fixed target for
failed gates. The reporting code averages the negative selected scores,
assigning a fixed penalty to failed gates.

Candidate programs are evaluated on two training-side folds; the historical
reference procedure specifies five. Evaluations are logged separately from
training-pool admission: ordinary admission retains only programs that pass
the gates and strictly improve the incumbent for their training context.
Historical programs have a separate admission path.

The admission log contains
695 consecutive rounds. Four rows are marked accepted, but only two strictly
increase the recorded best validation utility within this window. Its final
recorded best-validation value is 1.1378, with no later increase in the
retained interval (\cref{fig:fw-validation}). Acceptance flags and
improvements in this value are therefore distinct counts. Comparing these
utilities across harnesses requires matched data, normalization and scoring
protocols.

The more detailed summaries cover only 25 of those rounds. In that subset,
training utility exceeds validation utility by 0.282--0.290
(\cref{fig:fw-trainval}). This is a difference between reported aggregates
on separate training and validation contexts; it does not isolate a cause
or establish behavior in the missing summaries. The late validation plateau
is evidence to explain, rather than proof of useful transfer. Encoder
integrity and parameter updates require their own receipts; the plotted
utility tables do not establish either.
\Cref{fig:fw-telemetry} shows the loop's operating measurements from the same
snapshot.

Historical GP target scores provide a separate view in
\cref{fig:fw-target-progress}. The 159 repeated dataset/cut/arm groups cover
55 distinct dataset/cut pairs; the 64 groups with lower final scores cover
23 pairs. Shared incumbent and teacher seeds make the arms dependent.
These retained development outcomes do not establish that learning improved
the proposal policy.
