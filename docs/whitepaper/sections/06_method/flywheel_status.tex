\subsection{A separate adapter admission record}\label{sec:method-status}

The inspected operating loop ranks rule-based GP proposals with a cost-ranking adapter on a frozen, separately loaded candidate-scoring network. Its updates train neither the reference program writer nor the ranking map (\cref{sub:method-selfplay}). An admission gate retains or rejects each adapter update.
Validation-pool utility averages the negated recorded score of each context's adapter-selected candidate over fixed validation contexts; failed candidate gates count $-2.0$, and larger is better.

\input{sections/adapter_update_scope}

\paragraph{Two admission decisions.}
Programs and adapter updates pass separate admission rules. Program candidates use two training-side folds; the historical reference
uses five. Evaluation logging does not imply pool admission: failed candidate gates
and non-improving candidates are dropped (not kept as negatives), and
a candidate's logged utility (larger is better) must exceed its context incumbent's by more than $10^{-6}$
(\cref{fig:program-promotion-margins}). Programs imported from earlier training-side searches retain
their separate historical-admission path.

For adapter updates, inspected code accepts scored ties by default; a best-round identity
can change without raising utility. Optional strict admission requires
utility above the retained best plus an explicit nonnegative margin.
Program search continues after a rejection.
Refusals remain unscored; completed-round clocks include rejected work.

\paragraph{Scope of the telemetry.}
All records here and in \cref{app:flywheel-telemetry} are adaptive
training-side observations. Completed-round clocks include all work and
qualification waits; clock sums omit gaps between rounds. Program-incumbent
events and adapter admissions
have different denominators; neither establishes independent first-proposal
improvement or deployment throughput. The aggregate records do not yet bind
an exact loop source, adapter, evaluation population or normalization, so
cross-model comparisons and transfer remain unqualified. Retained windows
are separate; unobserved gaps are not filled or joined into a learning curve.

\paragraph{Adapter utility and admission.}
\Cref{tab:admission-ledger} fixes the chronology and counts.
\Cref{fig:fw-latest-admissions,fig:fw-admission-margins} show retained
validation-pool utility and pre-decision margins: eight updates are

\Cref{fig:adapter-admission-rates} resolves rounds 775--4529 into local
windows, using every recorded decision, including rejections, in each
denominator and separating ties from strict gains. Grey candidates and
the post-decision retained-best trace show different quantities; margins
use the retained best before each decision. The rolling margin view starts
only when its 50-round window is complete, and the later no-admission
trace retains all 200 decisions.

\paragraph{Program-journal activity.}
Programs pass a separate admission rule. \Cref{fig:program-journal-rates}
counts ordinary promotions and historical admissions against the captured
journal clock; \cref{fig:program-round-counts} resolves recent activity by
round, retaining observed zero counts and marking a missing decision.
\Cref{fig:recent-program-margins} gives each recorded promotion's
incumbent-utility difference. The 20-round window in
\cref{fig:fw-promotions-per-hour} records continuing program promotions
while retained adapter utility holds flat. Hourly counts resolve a captured
day (\cref{fig:program-24h}); fixed calendar bins extend the view from
round 775 onward (\cref{fig:full-cohort-program-rates}). The recent
round view includes 118 observed zero-count rounds. The program record at
round 4331 remains plotted, although its adapter decision is missing.
The gain distribution conditions on promotion; it supplies no
proposal-attempt denominator.

\paragraph{Operating clocks.}
Recorded time includes work and waits. \Cref{fig:fw-round-throughput}
divides distinct training contexts by whole-round time. The inclusive
ledger in \cref{fig:adapter-outcome-clock} groups recorded round hours by
adapter outcome, retaining rejected work. Gaps between program-pool
insertions include intervening work (\cref{fig:pool-insertion-cadence}).
\Cref{fig:round-phase-budget} separates measured phases from the remaining
recorded wall time in a later timing-only snapshot. The 20-round
throughput window and later phase-clock window are separate captures.
In the phase view, the remainder is wall time minus the logged phases;
no task is assigned to it. Inclusive outcome sums retain one unscored
round, whereas inter-round gaps remain outside the summed clocks.
