\section{EurekaZero: Learning Taste}\label{sec:method}

How does a model learn taste, the judgment that raises the win probability $q$ of
\cref{eq:taste} before a move is tried? \EZ{} learns it as AlphaGo learned Go: a program writer proposes moves, a problem--program
map judges them, and verified search during training teaches both. On game day the writer plays
alone, once.

\subsection{The player in one picture}\label{sub:method-picture}

In \cref{fig:network} a frozen encoder reads the board and the program writer $\writer$ writes one
complete program, as AlphaGo's policy network proposed a move \citep{silver2016mastering}. The
problem--program map $\mapv$ scores programs, as AlphaGo's value network judged positions, but only
in training. A network that ranks a search's output is a value network guiding search;
\searchone{} rests on the writer's single draw.

\subsection{Reading the board}\label{sub:method-board}

A frozen encoder turns the board of \cref{sec:game} into 2,048 numbers, $z_p=\encP(p)$, in three
blocks. The first summarizes a pretrained row encoder's embeddings across rows, independent of row
order (512 values). The second projects the hidden state of a pretrained third-party tabular
regressor that reads the training rows and labels (1,024; \TBD{name, version, licence}). The third
passes the scaled targets through two frozen windows (512). The encoder is
leak-free: it never receives held-out rows, held-out labels or test outcomes, and each context
records that no final test target was used. It is fixed, pinned by hash and never trained with the
writer, so the player cannot reshape the board to suit its moves. It is bounded at 30 seconds per
problem, and a context with any non-finite value is refused rather than imputed
(\cref{app:training}). Whether problems with alike best programs sit together is measured in
\cref{sec:results}, not assumed.

\subsection{Describing the move}\label{sub:method-move}

A move is one program in the typed language of \cref{sec:game}, spelled with a vocabulary of 401
tokens: up to six transforms from a set of 31, feeding one of 22 prediction heads. A grammar automaton masks every
forbidden token at each step, the valid-only decoding of grammar-constrained generators
\citep{kusner2017grammar,dai2018sdvae}, so every finished program is grammatical. We credit that to
the grammar, not to taste; taste must remove the moves that parse and then crash or lose. A program's
identity is the SHA-256 hash of its canonical form, so two spellings count once, and a hash of its
predictions on fixed training probes flags different programs that compute the same function. Every
move lowers to readable Python and Rust.

\subsection{One map for problems and programs}\label{sub:method-map}

The map reads a program as $z_w=\encS(w)$, the mean of learned token embeddings. It combines $z_w$
with $z_p$ three ways (as is, gated by the problem, and as a distance from a projection of it) and
averages four heads into a score $\mapv(z_p,z_w)$. It learns from lists: for each problem $p$ with
at least eight scored programs, $G_p$ holds them and $\rho_w\in[0,1]$ is a program's percentile, 1
for the best. The map's softmax over the list is trained toward a target concentrated on the best
\citep{cao2007listnet}:
\begin{equation}
  \mathcal{L}_{\text{map}}(p)=-\sum_{w\in G_p}
  \frac{e^{\rho_w/\tau}}{\sum_{u\in G_p}e^{\rho_u/\tau}}\,
  \log\frac{e^{\mapv(z_p,z_w)}}{\sum_{u\in G_p}e^{\mapv(z_p,z_u)}},
  \label{eq:mapLoss}
\end{equation}
with $\tau=0.25$. As $\tau\to0$ the target falls on the winner $w^+$, and \cref{eq:mapLoss} becomes
the InfoNCE loss \citep{oord2018cpc} that CLIP used to put images and text in one space
\citep{radford2021clip}, here problems and programs, with a problem's also-rans as hard negatives.
A Bradley--Terry term on the same lists sharpens the top \citep{bradley1952rank}. Stillborn moves
have no score, so the map learns where not to go only among programs that run. A program-only head
trained beside it tests whether the map reads the problem at all (\cref{sec:results}).

\begin{keyidea}
At \searchone{} there is nothing left for a value network to judge. Taste has to live in the
writer.
\end{keyidea}

In this checkpoint the map never touches the writer's draw. It ranks the writer's drafts, a
ranking we score against the referee, but drops none, and it does not condition, screen or steer
the writer. The writer learns its taste from the verdicts directly.

\subsection{The self-play loop}\label{sub:method-selfplay}

Training is expert iteration \citep{anthony2017expert}: verified search is the teacher and the
writer is the student (\cref{alg:selfplay}). The writer imitates every scored program in proportion
to the referee's verdict,
$\mathcal{L}_{\text{writer}}(p)=-\sum_{w\in G_p}(0.05+\rho_w^{4})\log\writer(w\mid z_p)$, inside
$\mathcal{L}_{\text{writer}}+0.1\,\mathcal{L}_{\text{map}}+0.25\,\mathcal{L}_{\text{BT}}
+0.1\,\mathcal{L}_{\text{runtime}}+0.05\,\mathcal{L}_{\text{prog}}$ (\cref{app:training}). Losing
moves still teach: a median also-ran carries about a tenth of a winner's weight and is a negative for the
map.

\begin{algorithm}[tb]
\caption{The self-play loop (training).}\label{alg:selfplay}
\begin{algorithmic}[1]
\Require training problems; serving writer $\writer$ and map $\mapv$; incumbents $\inc{p}$
\For{each round}
  \For{each sampled training problem $p$}
    \State $z_p \gets \encP(p)$; draw 64 distinct legal programs from $\writer(\cdot\mid z_p)$ \Comment{$T=1$}
    \State verified search, seeded with the drafts, proposes more programs \Comment{the teacher}
    \State $\referee$ fits and scores each distinct program on 5 inner folds \Comment{stillborn: no score}
    \State \textbf{if} a program strictly beats $\inc{p}$ \textbf{then} it becomes $\inc{p}$ \Comment{board ratchet}
    \State add every scored program to the list $G_p$ \Comment{winners and also-rans}
  \EndFor
  \State train a challenger $(\theta',\psi')$ on the lists
  \State \textbf{if} it beats $\writer$ on held-out cuts \textbf{then} $(\theta,\psi)\gets(\theta',\psi')$ \Comment{player ratchet}
\EndFor
\end{algorithmic}
\end{algorithm}

Two ratchets make this self-play rather than imitation of a fixed archive (\cref{sec:game}). A
program displaces a board's incumbent only by strictly beating it. A retrained writer is tested on 16
held-out cuts with three seeds each. It replaces the serving writer only if its mean log error ratio
favors it, it wins at least as many cuts as it loses, and it fails no more often.

\paragraph{The reported run.} The writer is a decoder-only transformer (six blocks, width 512)
that reads the context as a prefix token and writes at most 128 tokens; with the map, the network
has 27.8 million parameters. It trained on eight A100 GPUs in September 2026, on successive
corpora; the corpus behind the reported checkpoint, step 60,000, holds about 10.2 million scored
programs from 80 training datasets \TBD{acceptance record}. Details are in \cref{app:training}.

\subsection{Keeping the referee honest}\label{sub:method-referee}

A learner paid by a referee will learn the referee's flaws. In February 2025 Sakana AI walked back
claims after its AI CUDA Engineer exploited the evaluation code \citep{sakana2025walkback}. In June
2025 METR reported frontier models patching their scorers \citep{metr2025rewardhacking}, and 16\% of
1,968 agent-benchmark tasks can be passed without being solved \citep{zhong2026hackerfixer}. We
build the referee to be attacked. Selection, promotion and final scores use separate data (inner
folds, held-out cuts, a held fold scored once), and sealed meta-test families never reach the
learner. Programs run in a seccomp and Landlock sandbox with memory, swap and time limits. A
planted label leak and a sealed canary must both be caught, and every reported winner is re-run
from its emitted code, with native and emitted predictions agreeing within
$10^{-9}\max(1,|\hat y|)$. One earlier leaderboard entry for our search took, per dataset, the best
of 63,108 test-scored evaluations; we exclude it as test selection (\cref{app:incidents}).

\subsection{Game day: \texorpdfstring{\searchone}{search = 1}}\label{sub:method-gameday}

\begin{algorithm}[tb]
\caption{Game day in five lines (\searchone).}\label{alg:gameday}
\begin{algorithmic}[1]
\Require new problem $p$ with training rows and metric; frozen $\encP$ and $\writer$
\State $z_p \gets \encP(p)$ \Comment{read the board}
\State $w \sim \writer(\cdot \mid z_p)$, one draw at $T=1$ \Comment{one move; no retry}
\State $f \gets \textsc{Fit}(w,\ \text{training rows})$ \Comment{as any algorithm is fit}
\State $\hat{y} \gets f(\text{new rows})$ \Comment{a stillborn $w$ scores as a loss}
\State \Return $w,\ \hat{y}$
\end{algorithmic}
\end{algorithm}

\Cref{alg:gameday} is the whole of game day: one encoder pass, one draw of at most 128 tokens at
temperature 1 from a recorded seed, lowering to code, and the fit. The map is never run, and none of
training's exploration programs is added. A draft that does not finish, crashes or times out is
stillborn and scores as a loss; it is not replaced. Reported costs count the encoder and writer
with the fit, and any later search is reported apart, as \citet{silver2017mastering} reported
AlphaGo Zero's raw network apart from its search (\cref{sec:results}).

The method makes two testable promises: it learns, and it needs one try. \Cref{sec:results} checks
both.
