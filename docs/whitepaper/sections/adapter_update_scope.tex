Typed program edits, cross-family retrieval and grammar synthesis supply
candidates in the inspected implementation. The inspected loop freezes every
network parameter, then enables updates only for non-anchor cost-adapter
parameters (its parent-delta head receives no loss gradient). This loop
has no neural program writer. Its pool-utility calculation uses the
recorded scores and gate outcomes of the first four candidates as revealed
history, then selects the lowest predicted cost from the pool, including
those entries. Training puts the lowest recorded scores first in its
slates; utility evaluation uses stored pool order, so the calls can reveal
different examples. For new proposals, the caller reveals the first four
stored pool entries and pairs low-cost picks with
random exploration draws.

At the adapter interface, the caller supplies modality tokens and their
mask. It separately zeros the 584-entry context-feature slot and both
prior inputs, and supplies a fixed scale constant of \num{0.4208}; zero context
features do not mean absent modality tokens. Its objective combines regression to recorded costs and listwise
matching; failed gates receive target cost $+2.0$. Reporting averages
negative selected scores rather than cost predictions, with utility $-2.0$
for failed gates. The full-cohort
route disables development-anchor margin projection; smaller-cohort runs can
enable it. These two operating routes require separate verification receipts.

These selection records alone establish no gain from optimizer
updates or the separate reference map. The limits of component
diagnostics are covered in \cref{sub:results-diagnostics}.
Testing learning requires matched trained and untrained controls with
the same pool and revealed history, reporting invalid selections separately
from valid-program quality (\cref{sub:results-ablation}).
