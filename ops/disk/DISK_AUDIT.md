## Root-cause findings

1. `remote_tests/target` is a shared Cargo build cache and is the dominant *measured* contributor on xbabe3 (32.76 GB out of 34.59 GB in `~/remote_tests`). `~/bin/remote_test.sh` currently sets every Linux remote Cargo test's `CARGO_TARGET_DIR` to this path. Its guard clears the whole target when it exceeds 60 GB or free space is below 150 GB, but only when it sees no `remote_tests/src.<PID>` process. On xbabe3 at the second sample free disk was about 36 GB and `src.625552` existed, so the guard would defer. This launcher is host-local/outside this PR's Owns paths; DISK-01 reports the shared target only and does not race or override that guard.
2. xbabe1's selected `uv` cache is about 27.34 GiB. It is a rebuildable package cache, but the initial per-file dry run included cache markers and cached Git internals; UV therefore remains report-only until a safe, fully audited prune strategy is validated. `pip` caches were small (xbabe1 ~248 MiB); Docker roots measured 64–71 MiB where present.
3. `/tmp` totals are about 15 GiB on xbabe1 and 19.5 GiB on xbabe3; sampled top entries include dataset/GPU-named caches, Claude state, and agent PID directories. Ownership, freshness, and open handles are unresolved, so the daemon keeps `/tmp` report-only.
4. xbabe2's data volume is 87–88% at the measured times, below the daemon's soft threshold on the second sample; its APFS system root's 4% reading is misleading for capacity planning.
5. The highest overall disk consumers and the full flywheel/H-wave/fused output growth remain unmeasured. These paths include active/protected work and need an owner-bound inventory; they are excluded from automatic action.

## Daemon policy and evidence boundaries

`tools/ops/jope_diskd.py` defaults to dry-run. Its cache deletion allowlist is only the exact owned pip cache (`~/.cache/pip`) past TTL; UV remains report-only. It can also remove abandoned direct `remote_tests/src.<PID>` source scratch beyond 24 hours when PID and recursive open-handle checks prove inactivity; that path must be exactly `~/remote_tests` and is considered only above the 60 GiB aggregate cap. All deletions receive flushed before/after JSONL audit entries. At 85% it uses 30-day cache TTL; at 90% it uses 72 hours; at 95% it emits a daily alert. The daemon uses an apply-run lock and fails closed on symlinks, ownership changes, hardlinks, special files, incomplete scans, and unknown policy IDs.

Worktree targets, the shared `remote_tests/target`, Docker data, arbitrary `/tmp`, research/flywheel outputs, checkpoints, datasets, receipts, custody and protected families are report-only or hard denied. This follows `deploy/maintenance/README.md`, which warns that Cargo `target/` can hold evidence at any depth and rejects automatic deletion. Flywheel log rotation/artifact reduction is proposed for a later approved restart only.

No service is enabled from this feature branch. Three-host dry runs were repeated against the final review policy at 03:05–03:07Z and planned zero deletion. Linux would use a ten-minute systemd user timer; macOS would use an idempotent ten-minute user cron entry. The installer requires existing Linux linger and never changes host account settings; deployment remains a post-merge step.
