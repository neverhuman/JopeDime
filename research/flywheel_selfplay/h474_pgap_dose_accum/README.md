# H474: gap-weighted BT pairs, dose (gap²) and stacked with gradient accumulation, on the gated pairnf step (offline, adapter-only)

**Status: `RUNNING` (pre-registration record).** This README records the design, code hash and launch plan before any CV result exists. The probe, smoke, verdict, metrics and red-team will be added at closeout, once all 3 seeds write `summary.json`.

## Hypothesis
H473 (#2404 prereg, #2409 closeout) was `NO_LIFT`, but gap-weighted Bradley-Terry pairs (`pgap_z40`) were the first arm on this instrument to be positive against the `pairnf_z40` control on **all 3 seeds**: +0.0035 / +0.0013 / +0.0044, every CI spanning 0, cross-seed +0.0031 [−0.0012, +0.0095], Elo vs control +2.4 [−0.2, +4.9]. Its pooled Elo CI vs the incumbent cleared 0 on every seed. The edge is −2.0 floor recoveries (7 / 6 / 9 of 38 vs the control's 3 / 5 / 4, the same extra contexts on every seed, 0 new gate failures). On non-floor contexts its extra kept changes win 67/38 (64%, vs the control's ~57%), but it also drops net-positive control changes (30/25), so its non-floor gain equals the control's (+0.0001 [−0.0019, +0.0016]). The only optimizer lever with a seed-level paired CI > 0 on this instrument is gradient accumulation (H467 acc2 seed 1 +0.0025 [+0.0002, +0.0070]; H468 acc4 seed 1 +0.0025 [+0.0001, +0.0069], no dose-response over acc2). acc2 also keeps the control's ~58% non-floor win rate with a few more kept changes.

H474 asks two pre-registered questions on the control's random streams and the same 16-step, lr 3e-4, slate 192, keep 48, z ≥ 0.40 configuration:
1. **Dose.** Does the pgap signal grow when the pair weight is sharpened from gap¹ to gap² (`pgap2_z40`, still renormalized to mean 1 per context)? A monotone control < pgap < pgap2 in floor recoveries *and* non-floor gain is dose evidence. Flat or reversed means gap¹ already captures it.
2. **Stacking.** Do pgap and accumulation add (`pgapa2_z40` = pgap gap¹ + 2 × 1,024-context gradient accumulation on the H467 acc2 keyed streams)? Both are small, seed-inconsistent effects in roughly the same direction. If they are independent, the stack should clear the paired CI on more seeds than either alone.

Arms:
- `pairnf_z40`: the control. Its 30 CV cells are **copied** from H473 `results/fold_sig` (= H472 / H471 cells; sha256 list `control_fold_sig_from_h473.sha256` has the same hashes as H473's).
- `pgap_z40`: the H473 arm, kept as a **reference** (30 CV cells copied from H473, sha256 list `pgap_fold_sig_from_h473.sha256`). Selection still considers it, so if it is selected its val91 build is re-trained fresh (deterministic, so it should reproduce the H473 seed 2 / 3 full-train shas `e6e980fd…` / `845ac12f…`).
- `pgap2_z40`: pair weight gap², renormalized to mean 1 over the context's active pairs.
- `pgapa2_z40`: pgap gap¹ + accum 2. It does 2× the per-step compute, which is not compute-matched by design, since the question is stacking.

Not repeated (already falsified on this instrument): Polyak/EMA tail and ASAM (H457), 32-step dose and family-balanced sampling (H461), recalibrated gate and 32-step cosine (H463), ctxnorm, tail clip and pair weight 2 (H466), acc2, Lookahead and BT label smoothing (H467), acc4 and displacement-matched Lookahead (H468), trim10/trim25/Cauchy robust per-context losses (H469), gradient noise (H470), one-cycle/SGDR schedules (H471), slate coverage/head focus (H472), the strict-improvement dead zone pm25 (H473), hard-negative top-16 slate and z-margin pair focus (H454), ensembles/soups/agreement gates (H453), regret curricula (H446–H450).

## Pre-registered rules (unchanged from H452–H473)
- **Primary metric:** median across 3 seeds of the pooled OOF Elo vs the incumbent, with 95% family-bootstrap CIs (families resampled with all their rows in both partition copies). **Non-floor Elo** is co-primary and drives selection. Elo only, no AUC.
- **Selection:** per seed, the max mean non-floor OOF Elo over the two partitions (ties broken by pooled gain).
- **Strict:** pooled OOF gain > 0.002 and gain CI low > 0; pooled Elo > 0 and Elo CI low > 0; non-floor Elo CI low > 0; Elo > 0 on each partition. Ties never win, and a tie with the control is not accepted.
- An arm counts only if it also beats the control in the paired family bootstrap (arm − control CI low > 0).
- **LIFT** requires a non-control arm that passes strict and beats the control on every seed, val91 not_worse on every seed, a clean red-team **and** a median val91 gain beyond its cross-seed family-bootstrap CI (CI low > 0). Otherwise the verdict is `NO_LIFT`. val91 has 0 incumbent gate failures, so a floor-only edge cannot reach LIFT.
- **Secondary (new):** the aggregator is re-run with `CTRL=pgap_z40`. A new arm that beats the control but not pgap is reported as pgap-equivalent, not as a new lever.

## Pre-registered red-team checks
- **Floor-recovery confound:** report gain with and without −2.0 floor recoveries (`h473_nonfloor.py`, copied), non-floor gain/Elo, `recovered_gatefails` and `new_gatefails` per arm and seed. A paired non-floor gain CI > 0 vs the control is the mechanism test.
- **Dose / stacking:** report pgap2 vs pgap vs control (floor recoveries, non-floor gain, kept counts), and pgapa2 vs pgap and vs the H467 acc2 control-relative effect.
- **Mechanism (win rate):** the non-floor W/L of each arm's extra kept changes and of the control changes it drops.
- **Displacement / z-inflation:** kept counts, the median |z| of changed picks vs the control and the kept-set overlap. An arm that keeps < 0.5× the control's changes is flagged gate-starved, and > 2× z-inflated. gap² concentrates weight on a few pairs per context, so check this first for pgap2.
- **Control / reference reuse:** the copied control and pgap cells are re-checked against their sha256 lists after the run. The smoke re-trains h452a fold 0 seed 1 fresh for every arm (control must equal `8d5ac793…`, pgap `1afa7d46…`, same OOF vectors). The probe's full-train shas must equal H473's (control `5f3acc50…`, pgap `4c2e17f9…`).
- **Tie acceptance:** ties never win. Report W/T/L everywhere, and treat a val91 gain ≈ 0 with ≥ 85/91 ties as not evidence. Report single-context val91 drivers (H472/H473: idx 41).
- **Equal-Elo coincidences:** equal pooled Elos with equal W − L are reported as arithmetic coincidences after checking that the adapters and decisions differ.
- **No label leakage:** pair weights use training-fold fitness only (spread_c is the training context's own passing-fitness std). Held-out folds are scored by the label-free z-gate, and val91 is read once per seed for the selected arm only.

Expected cost per seed ≈ 10 pgap2 folds × ~14 min + 10 pgapa2 folds × ~28 min + setup and the full-train build ≈ 7.5 h. Seed 3 waits for a free slot, so expect a close about 16 h after launch.
