# H278 frozen-export shadow handoff

`h278_shadow.py` consumes the separately published H278 three-seed native text
models. It never imports H278 fitting code or invokes a fit/optimizer. This is a
separate handoff: the original H273 observer and its runtime files stay untouched
and retain their original bounds. The live writer remains a read-only input.

Before loading, download each object at its exact S3 VersionId and verify SHA256
against the published export manifest. The manifest itself must match the
publisher's VersionId/SHA receipt. Validate the DL-Train-only fit-lock, all205
TRAIN families disjoint from the91 Dev contexts'19 families, source/code hashes,
568 features, eight slots, seeds278101..278103, tau0.10 and locked margins/tree
counts. The preparation receipt is an input to the loader; it hashes every file
again. No model text or large feature packet belongs in Git.

Use the H278 exported Dev feature packets unmodified. Candidate/order columns
must match the local candidate/pick/utility binding bit-for-bit; the final context
norm alone may differ by one float32 ULP in the local reference calculation. This
exception changes no exported feature bytes or model inputs. Regression reproduces
all546 H278 frozen slot picks (3seeds ×2panels ×91contexts) exactly. The veto masks
all nonbaseline slots with p_invalid>=0.10 before strict margin selection.

Each completed live round reports every seed's frozen pick against the actual
incumbent pick, family-median and family-mean delta, family-equal two-contender MM
Elo and95% family-bootstrap intervals, invalid picks from actual gates, harmed
families and fam-769243ee. Metrics use H278's family-mean utility comparisons,
tie1e-4, prior.01,400MM iterations; bootstrap10,000draws,seed278150. Predictions are
frozen before live-round outcomes enter the comparison; no winning-seed selection.

Primary shadow candidate pool is r882's frozen top8. The CPU-reproducible r3175
candidate pool is also reported **EXPLORATORY**: its stored native reference
matches90/91 contexts, so H278's declared P2 verdict is **P2_BLOCKED**. Comparisons
use the actual live incumbent's91 picks/utilities, never that approximate CPU
reference. This does not reopen or relabel the H278 scientific gate.

The advisory gate requires H278 P2 ADOPT_SHADOW_PASS plus at least3 consecutive
completed rounds with strict positive family-median gain for all3 fixed seeds and
no excess invalid picks. Ties fail. The gate can only report prerequisites:
`adoption_authorized` and `promotion_wiring` are always false; the watcher decides.
No serving, checkpoint, pool, promotion, DOPE or trainable-parameter writes exist.

Run CPU nice10, OMP_NUM_THREADS=1, OPENBLAS_NUM_THREADS=1,MKL_NUM_THREADS=1,
PYTHONDONTWRITEBYTECODE=1,CUDA_VISIBLE_DEVICES=''. Output is separate from writer
run/custody. The handoff has an absolute deadline,40-round bound,2GiB RSS and4-thread
ceiling, and90MB output ceiling with no deletion. Combined shadow storage must
stay below100MB. Writer exit or identity change ends observation.
