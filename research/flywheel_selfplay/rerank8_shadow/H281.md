# H281 GPU-exact P2 and unique-pool gate

`h281_shadow.py` retains the frozen H278 models and their P1 and CPU exploratory
panels, and adds `P2_GPU_EXACT_R3175_TOP8`. H281's exact-VersionId/SHA S3 manifest
binds GPU costs, 91/91 native-baseline replay, P2 picks and utility/invalid panels.
This lane rebuilds the GPU-cost feature packet on CPU with only the verified H278
inference functions. It uses no GPU, qualification lock, fitting or writer change.
The regression must reproduce all273 P2 picks and both full arrays bit-for-bit.

Current `H278_P2_verdict=ADOPT_SHADOW_PASS` means the H278 P2 rule is qualified by
**H281**. `historical_H278_CPU_P2_verdict=P2_BLOCKED` remains explicit, and the CPU
panel stays EXPLORATORY. This does not rewrite the H278 study's historical verdict.

`pool_evidence.py` fingerprints the scored GPU candidate membership, frozen pool
anchor parameter identity, actual live incumbent parameter identity, DOPE and
evaluator identity. Contexts and program memberships are canonicalized. Round
numbers, timestamps, file paths, checkpoint serialization, candidate order and
reranker changes are not novelty inputs. The accepted incumbent's actual parameter
SHA is read from its retained scientific round receipt; metadata-only checkpoint
changes cannot manufacture fresh evidence. H282's new anchor/pool identities can
be handled as new data when qualified and supplied later; no pools are fabricated.

Every round has `pool_sha256` and `counts_toward_gate`. Only the first eligible
**live** completed round for a previously uncounted hash counts. Repeats are
`REPEAT_NO_NEW_EVIDENCE` and never add credit. Distinct-pool counted rounds form the
filtered evidence stream: a fresh nonpositive/invalid-worse pool resets its positive
streak; repeats are ignored. Unknown round gaps reset the streak. All previously
counted hashes, including negative pools, are remembered across restarts by replaying
committed round records, so a state-write interruption cannot count a repeat again.

Legacy records are preserved byte-for-byte in `legacy-v1/` before the owning proof
lane publishes versioned H281 contract revisions. Those revisions add the GPU panel
and fields but are marked RETROSPECTIVE and receive **no live gate credit**. The
old repeated-round counter is invalidated. Original source records remain linked
by SHA. New live GPU-qualified evidence starts with one unique pool, never with
the old repeated-round count.

The gate still only reports numerical prerequisites (three consecutive strictly
positive counted pools, all3 fixed seeds, no excess invalid picks). H280/H282 and
the watcher's decision remain explicit. `adoption_authorized`, promotion and serving
wiring remain false regardless of the counter.

The owning shadow observer may be handed off after a complete-record boundary;
writer PID1402163, its output/custody, model and promotion state stay untouched.
Run CPU nice10, OMP/OPENBLAS/MKL1, <=2 actual threads, <=2GiB RSS. The original
absolute deadline is retained. At most180 retained round records and a combined
98MB guard keep all shadow outputs below100MB without deleting evidence. Repeats
